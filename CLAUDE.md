# silly-kicks

Maintained fork of socceraction — SPADL event conversion + VAEP action valuation for soccer analytics.

## Architecture

- **Hexagonal**: All core functions are pure (pandas in, pandas out). Zero I/O, zero global state mutation.
- **Converters** (`spadl/`): Each provider (StatsBomb, Opta, Wyscout, Sportec, Metrica, Gradient Sports, SkillCorner, plus the Kloppy gateway) has its own module. All return `tuple[pd.DataFrame, ConversionReport]` with guaranteed columns/dtypes via `_finalize_output()`. Live per-provider contracts:
  - **Gradient Sports goal capture (ADR-018).** Own goals = `RE`+`shotOutcomeType=="G"` -> `bad_touch`+`owngoal` (conceding team/rebounder kept; a post-LTR own-half geometry tripwire warns+reverts a mis-located one). Cross-goals = `CR`+`G` -> keep the cross + synthesize a `shot`/`shot_freekick`+`success` by the crosser; synthesized rows carry `is_synthetic=True` (they share the parent's `original_event_id`). Voided `possessionEvents.nonEvent==True` events are excluded (optional column -- absent is an observable no-op warn, tallied in `excluded_counts`). `"O"` shot-outcome is off-target -> `fail`, NOT own-goal.
  - **GS null-actor rows carry NaN, never a sentinel `0` (ADR-027).** The null-actor duel/foul events (`OTB`+`CH`, `FOUL`+`FO`) have both `gameEvents.teamId` AND `playerId` NULL; GS schema ids are nullable `Int64`, not the `SPADL_COLUMNS` `int64`. A non-NaN sentinel bypasses `pd.isna` routing and crashes downstream opponent guards. ADR-001 forbids back-filling from duel/foul qualifiers; `_resolve_team_ids` fills team ONLY from a real same-match `player_id` (ambiguity raises). `convert_to_atomic` preserves source id dtype.
  - **GS dribble ends are derived GS-locally (ADR-018 amendment).** GS initializes `end=start` for every event and never runs `_add_dribbles`, so every `OTB`+`BC` shipped a placeholder. `_derive_end_coordinates` takes keyword-only `extra_type_ids` and ONLY gradientsports passes `{dribble}` -- the shared `_DERIVE_END_TYPE_IDS` stays untouched, because its `placeholder_end` guard cannot distinguish statsbomb's genuine stationary carries from placeholders. Period-last carries honestly keep the placeholder.
  - **GS ball-carry results come from the native `ballCarryOutcome`**: `R` (retained) -> success, `L` (lost) -> fail, unknown/absent -> fail. Without it every GS dribble fell to `fail`.
  - **SkillCorner `time_seconds` is period-relative** -- `_to_period_relative` subtracts the period-start offsets `{1:0, 2:2700, 3:5400, 4:6300, 5:7200}` (ADR-017).
  - **SkillCorner `result_id` routes through the native outcome** -- `pass_outcome` -> `received==True` (success-only) -> residual `same_team_next` -- and emits a dedicated `result_source` column (`native`/`inferred`/`stopgap`) in `SKILLCORNER_SPADL_COLUMNS`. `received==False` is NOT a fail (it can be completion to a non-targeted teammate).
  - **SkillCorner `_transform_coords` scales THEN clamps -- never call it on tracking (ADR-038).** The clamp is safe for events (on-pitch by construction) and destructive for tracking: a ball 9 m behind the goal snaps onto the goal line, erasing goal-vs-save. Tracking calls `_scale_to_spadl` (affine only) and nothing else. Pitch dims come from the events converter's own affine transform; missing dims RAISE, and `assume_standard_pitch=True` is the explicit opt-in.
  - **sportec pass/set-piece results use a kloppy-aligned success-ALLOWLIST** on the native DFL `play_evaluation` (`_extract_play_eval`/`_play_evaluation_is_fail`/`_warn_unexpected_play_eval`, single-sourced across the main and synth sites): `fail` iff the Evaluation is non-empty AND not in `{successfullyCompleted, successful}`, so unseen reason-coded failures fail by construction; empty/absent/NULL -> success (no mass-fail on a missing column); unexpected tokens warn. The punt-synth goalkick inherits its parent Play's eval.
  - **metrica is deliberately unchanged** -- measured-correct (PASS = completed pass; a loss is a separate `BALL LOST` event).
  - **Restart-coordinate enrichment is additive (ADR-025).** `spadl.add_restart_coordinates(actions, *, frames=None, links=None)` imputes NaN restart coords for the Law-fixed-spot types as NEW provenance-tagged columns (`enriched_start_x/_y`, `enriched_end_x/_y`, `start_coord_source`/`end_coord_source`, `*_coord_confidence`) and NEVER mutates canonical `start_x`/`end_x`. Single engine `tracking.resolve_restart_geometry`; `tracking.resolve_gk_geometry` is a byte-identical shim over it.
- **Tracking** (`tracking/`): Per-frame namespace parallel to `spadl/`. 20-column long-form schema (`TRACKING_FRAMES_COLUMNS`); native Sportec + Gradient Sports adapters; native SkillCorner + Metrica bronze->frame builders (ADR-034); kloppy gateway. The linkage primitive (`link_actions_to_frames` + `slice_around_event`) joins SPADL actions to frames -- pointer-DataFrame return plus a `LinkReport` audit (ADR-004). Tracking-aware features compose into VAEP via `compute_features(*, frames=None)` and the `_frame_aware` xfn marker (ADR-005); every family has an `atomic.tracking.features` mirror.
  - **`time_seconds` is period-relative** (it resets each period -- NOT an absolute match clock). ADR-017 enforces it with a per-period `min_link_rate`/`on_low_coverage` guard plus `LinkReport.per_period_link_rate`, and public `validate_time_base`/`TimeBaseDiagnosis` as the pre-link guard for time-filtering consumers (the linker cannot see pre-filtered-out actions).
  - **GK identity:** `is_goalkeeper_source` is `native` or `derived`; `_gk_identification.derive_goalkeepers` is the B+ filtered algorithm with agreement-based source resolution. SkillCorner **trusts its authoritative roster** (`native`, derivation skipped; derive only for a `(game, team)` with no native GK) -- positional derivation is unstable over the short windows a batched builder sees. Metrica has no roster and stays Tier-2 (ADR-007); it seeds NONE, because `gk_jersey_numbers` is a flat team-agnostic list and `derive_goalkeepers` ORs-never-clears.
  - **Metrica input CONTRACT:** bronze `y` must be SPADL bottom-to-top. Kloppy's metrica NATIVE coordinate system is top-to-bottom, so a `TrackingDataset` consumer MUST flip `1-y`.
  - `tracking.preprocess` ships Savitzky-Golay / EMA `smooth_frames`, linear `interpolate_frames`, SG-derivative `derive_velocities`, and the shared `PreprocessConfig` (flag-based `is_default()`, per-provider defaults auto-promoted via `for_provider`).
  - Feature families -- purity, liveness, NaN-safety, dtype and orientation rules for every `add_*` are in **Key conventions**:

- **VAEP** (`vaep/`): Feature engineering + gradient boosting binary classifiers. `HybridVAEP` removes result leakage from a0 features. xG-targeted labels available via `xg_column` parameter. PR-S32 ships TF-29 design-space variants: `window` parameter on `scores()`/`concedes()` (`"action"` / `"possession"` / `"time"`); `xfns_default_no_goalscore` / `hybrid_xfns_default_no_goalscore` goalscore-bias-control lists. **4.13.0 (ADR-018): own goals are counted by RESULT (`result_id==owngoal`), not via a `type_name` shot-gate** — single-source `_is_goal`/`_is_owngoal` helpers in `vaep/labels.py` (all sites route through them; a guard test forbids the old shot-gated owngoal predicate). Fixes a codebase-wide undercount (every converter emits own goals as `bad_touch`, which the old `str.contains("shot")` gate zeroed out); the atomic label path already counted them. Hyrum: shifts scores/concedes/xG label distributions for all providers (VAEP-model retrain trigger).
- **xT** (`xthreat/`): Expected Threat. SK-xT-1 (4.17.0, ADR-021) refactored the `xthreat.py` module into a package with a house-style **pluggable transition family** (string-dispatch + frozen-dataclass params, NOT ABCs): `ExpectedThreat(method="singh_counts"|"kde_smoothed", params=, l=, w=)`. The `singh_counts` default is **byte-identical** to the classic socceraction grid (frozen-oracle parity gate at `tests/xthreat_legacy_reference.py`); `singh_transition_matrix` is vectorized (`np.add.at`, byte-identical). KDE-smoothed transition (`kde_smoothed_transition_matrix`, Silverman-1986 bandwidth, adaptive per-source-zone); `KDEParams.bandwidth=1.0` (pure Silverman) is a conservative default — the held-out-NLL optimum is **corpus-size-dependent** (~1 on a 64-match sample, ≥4 on an 8.9M-action mart), tune via the evaluator. `GridSpec` first-class variable resolution (pitch dims stay in `spadlconfig`). Standalone `value_iteration` (raw-diff convergence — monotone-from-below, do NOT "fix" to abs; optional `max_iter`). Held-out **transition-model** NLL evaluator (`holdout_split` `game_id`-keyed, `compute_holdout_nll` pure, `compute_holdout_nll_per_group`) — NOT an xT-quality metric. KNN/conditional deferred (pre-publication); lakehouse `XTGrid` declined (keep raw `.xT`). Additive — no Singh-path change, no retrain trigger (TF-24 calibration `FrozenXt` untouched). Lakehouse-proposed; attribution Singh 2018 / Silverman 1986 / Salimi 2026 (pre-pub). Decision: ADR-021. **SK-xT-2 (4.19.0, ADR-022)** wires xT into VAEP as an opt-in, frame-free feature: `vaep.features.xt_xfns(*, model)` + atomic mirror `atomic.vaep.features.xt_xfns` emit `xt__<model.method>` per gamestate slot (ADR-005 §8 naming), caller-supplies-the-fitted-model (fail-closed; `str`/`None`/unfitted raise; `ExpectedThreat` imported `TYPE_CHECKING`-only — duck-typed at runtime, **no new runtime edge**). In **no** default xfn list (additive — opting it in is a self-triggered VAEP retrain; guard test enforces absence). Atomic reuses `model.rate()` **unchanged** (no `_rate_cells` extraction — SK-xT-1 parity gate untouched) via a synthesized standard-SPADL frame + **type-aware** `result_id` (dribble intrinsic since dribbles are never followed by `receival`; pass/cross success iff next atom is `receival`); maps slots by composite `(game_id, period_id, action_id)`; period-last pass/cross → NaN (inherent atomic edge). Cross-representation symmetry verified by a geometry-keyed oracle (NOT `action_id` — `convert_to_atomic` renumbers it) + a dribble keystone gate on the committed WC2018 fixture. Bundled-grid variant reserved via a typed `str` door (ADR-011). C4-free.

- **xT-GK v1** (`tracking/_xt_gk.py`, `_gk_geometry.py`, `_gk_completion.py`): FROZEN parametric GK-distribution value (ADR-024) -- `compute_xt_gk` / `add_xt_gk` / `xt_gk_xfns` plus `XtGkParams.for_philosophy`. Tracking-required; in no default xfn list. Live contracts:
  - Normative params (gamma/delta/phi/eta, `defensive_third_boundary`, `pressure_scale`, `convolution_sigma`) are **intent-set, NEVER calibrated**.
  - **Invariant: the phi surface enters value via PEV and DZV ONLY** -- `base = -xT*(z)` and RAV stay on raw `xT*`, so the destination is never revalued twice. Behaviourally guarded.
  - `resolve_gk_geometry` derives a missing goal-kick origin/destination WITHOUT mutating shared `actions`, emitting per-row `xt_gk_origin_source`/`xt_gk_dest_source`/`xt_gk_origin_confidence` plus an aggregate `XtGkReport`. The `x <= 16.5` goal-area clamp is an **action-LTR own-half predicate, so it must run AFTER the ADR-028 reflection**, never before -- applied to a raw away-team frame x it rejects a correctly-placed keeper and silently loses the tracking tier.
  - **Native-origin trust is a FAIL-SAFE provider allowlist** (`native_origin_is_trusted`; unknown/None/future -> distrust). Distrust scope is **goal-kicks ONLY**: SkillCorner records a goal-kick origin as the broadcast ball detection ~14-20 m downfield, but its open-play GK-pass origin IS the keeper (measured 0.4 m).
  - `GkCompletionModel` (logistic, pure-numpy `sigmoid(Xb)` serve, pickle-free JSON + SHA256) backs RAV and the public `compute_gk_completion` / `add_gk_completion`. **Provider-keyed variants** via `variant_key_for_provider` (`skillcorner` -> its own weights, else `gs`); one call = one match (`_resolve_single_provider`). **Training is `result_source=="native"`-ONLY** -- `inferred` is positive-only and would bias a multiplicatively-consumed calibration -- and defaults to FULL-match frames, because a small `--tracking-limit` starves derived-GK detection and inflates the domain. A capped run is dev-smoke only, never used to bundle.
  - **Per-type serve gate:** any completion sub-domain whose held-out AUC lower confidence bound is <= 0.5 (or degenerate, or `n < 50`) serves the calibrated per-type base rate, tagged `xt_gk_completion_source="base_rate"` (`serve_mode_from_lcb`). Data-driven per variant, not a blanket goal-kick rule.
  - **Do not pool `xt_gk` across completion variants without running the comparability gate** (`scripts/_xtgk_comparability.py`).
  - The resolved-coordinate audit columns (`xt_gk_origin_x/_y`, `xt_gk_dest_x/_y`) are provenance and deliberately NOT in `_OUTPUT_COLS`, so `xt_gk_xfns` never surfaces them as VAEP features.

- **xT-GK v2 possession value** (`xtgk/`): the honest value surface `V(z,p)` behind the v2 metric `rho*[V(s') - V(s)] - (1-rho)*[V(s) + kappa*V_opp]` (ADR-036). Hexagonal -- a `PossessionValue` Protocol plus adapters; `compute_xt_gk_v2` depends only on its three ports and emits the coherent additive decomposition `xt_gk_v2_position` / `_pev` / `_retention_loss` / `_dzv` / `xt_gk_v2`. In no default xfn list.
  - `MarkovPossessionValue` (production) = pressure-stratified value iteration reusing `xthreat.value_iteration` verbatim, with an xG-calibrated first-shot reward, a goal-kick-inclusive move-set (`_moves.MOVE_TYPE_IDS` = pass, dribble, cross, goalkick, throw_in) and pressure terciles. `V(z,p) = E[xG of the possession's FIRST shot | ball at z under pressure p]`. The xtgk-local builders reuse `xthreat`'s low-level seams and modify NO `xthreat` source -- classic xT stays byte-identical, parity-gated.
  - **silly-kicks ships NO xG model.** `V` is fittable only where a calibrated per-shot xG exists; the column is injected (`xg_column`).
  - **rho** = `GkRetentionModel` (logistic, pure-numpy serve, JSON + SHA256, provider variants); labels come from `retains(actions, *, window_seconds=10.0)`, where a truncated window is NaN -- excluded, never falsely-retained. Features are marts-native (gold `fct_action_values` + `fct_action_context`), NOT tracking frames, and pressure is pinned to `pressure_on_actor__bekkers_pi`. Every bundled variant must clear `ece <= 0.10 AND |reliability_slope - 1| <= 0.25`, CI-certified against its recorded `metrics.json`.
  - **`V_opp`** = `EmpiricalTurnoverValue`: possession-bound by default, with support-gated hierarchical bin-widening (native cell -> coarse block -> global-per-pressure, `min_support=30`) so a one-turnover deep cell is not a noise estimate.
  - **Consumer contract: call `apply_resolved_gk_geometry` BEFORE `compute_xt_gk_v2`, and keep `is_gk_distribution` (or the `gk_geometry_source` stamp) on the frame.** Resolved keeper origins live in `fct_action_context.xt_gk_origin_x/_y`, not raw `bronze.spadl_actions`, and the rule is **OVERRIDE, not coalesce** -- SkillCorner's native goal-kick origin is present-and-wrong (the broadcast ball), so a `fillna` would fix GS and silently miss SkillCorner. The warn-once attestation needs a domain column, so a pre-filtered slice with the flag dropped scores raw origins silently.
  - **`flat_zones` maps a NaN coord to zone `(0,0)` -- a FIT-PATH-only contract.** Every fit seam `dropna`s first; use `finite_coord_mask` at any scoring seam. `compute_xt_gk_v2` NaN-guards non-finite rows across all five outputs (never a fabricated zone) and raises on coordinate incoherence between `actions` and the rho features.
  - **Status: NOT construct-validated.** Out-of-sample on real gold, v2 loses to `raw_completion` on outcome-AUC (GS -0.147, SC -0.027); the deep-zone pressure gate is GO-leaning (a real, decreasing, monotone gradient on both cohorts) but WC2022's absolute effect sits under the pre-registered floor. Reports in `docs/research/xtgk_v2_construct_validity/`.
  - v1 is **FROZEN** and coexists until the lakehouse migrates its `xt_gk*` columns; there are no v2<->v1 imports.
- **GKDV — GK Deterrent Value** (`gkdv/`): PR-3 of the TF-19 cycle (ADR-043; spec `docs/superpowers/specs/2026-07-12-tf19-gkdv-regate-and-v1-design.md`). Counterfactual valuation of keeper POSITIONING: how much does the actual keeper's position change the attacking team's space and threat versus a league-average "ghost" keeper in the same frame state? **Depends on `silly_kicks.tracking` PUBLIC seams ONLY, never the reverse** — `tracking/` must never import `gkdv/` (pinned by `tests/gkdv/test_import_allowlist.py`; the same rule ADR-037 set for `tracking/_model_eval.py`). **Engine** (`_engine.py`): `build_ghost_frames(frames, *, home_team_id, model=, carrier=, params=)` → `(counterfactual_frames, provenance, report)`, PURE (never mutates `frames`); domain = alive ball ∧ in-possession team attacking ∧ ball within `domain_ball_to_goal_m` of the attacked goal ∧ defending-GK row present; the ball carrier is pinned ONCE and shared by the domain filter and the serving seam. **A NaN/missing ghost is dropped-and-COUNTED, never scored as Δ=0** — a zero delta from a missing keeper reads as "no deterrence" and biases keeper aggregates toward the null (`GkdvReport` conserves exactly: `n_frames_scored + Σ drop_reasons == n_frames_in`); a non-finite served ghost RAISES rather than making the keeper vanish. `counterfactual_frames` is the FULL input with only the defending keeper substituted, so consumers MUST restrict to the scored set via `provenance_to_targets` / `provenance["drop_reason"].isna()` before differencing. **Arms** (`_arms.py`), both in ATTACKER-VALUE units as `actual − ghost` so **negative = deterrent** uniformly: `delta_das` (accessible space; direction is pinned ONCE on the FACTUAL frames and the SAME pinned column feeds BOTH legs — accessible-space otherwise infers direction per period from a team-x mean the ghost displacement perturbs, so the two legs could infer OPPOSITE directions and the difference would not be a counterfactual at all; routed through `get_individual_das` summed per team via the narrow `_das_port.py`, since `get_das` hardcodes `infer_attacking_direction=True`) and `delta_threat_suppression` (`compute_threat_pc(actual) − compute_threat_pc(ghost)`). **Asymmetric keeper modelling, by construction:** the threat arm carries `lambda_gk` (a keeper GAIN applied after the influence field, so keeper position enters via TTI) while ΔDAS is **keeper-BLIND** (accessible-space's column map has no `is_goalkeeper`), i.e. ΔDAS measures relocating a GENERIC player. **`method="spearman"` is a HARD API constraint** enforced in `GkdvParams.__post_init__` — a GK-blind pitch-control configuration is *unrepresentable*, not merely discouraged, and the check lives in ONE place (the arms deliberately do not re-check). **Neither arm accepts a `pitch_control_cache`, and that is CORRECTNESS not performance:** `PitchControlCache` keys on frame IDENTITY (`game_id, period_id, frame_id, team, method, params, ball_position, decompose`) and excludes player positions, so a ghost frame — which carries its twin's identity — would be served the factual leg's surface and every delta would collapse to exactly zero with no warning. Ships **no `add_*` aggregator** (C4 action-coupled count unchanged) and is in **no** default xfn list. §6.4 Layers 0–3 and the xS-arm probe (PR-3b) are NOT in this PR. Attribution: Le et al. 2017 (ghosting); DEFCON-GNN arXiv:2512.10355 (comparator only, not implemented).

## Key conventions

- No pandera — schemas are plain Python dicts (`SPADL_COLUMNS`, `ATOMIC_SPADL_COLUMNS`).
- Config DataFrames (`actiontypes_df()`, etc.) are cached with `@functools.cache`.
- Vectorized dispatch: converters use `np.select` over pre-flattened columns, not `apply(axis=1)`.
- All `warnings.warn()` calls include `stacklevel=2`.
- ML naming conventions (uppercase `X`, `Y`, `Pscores`) are allowed in `vaep/` and `xthreat/*.py` per ruff per-file-ignores.
- **Converter identifier conventions are sacred.** SPADL DataFrame converters never override the caller's `team_id` / `player_id` columns from provider-specific qualifiers. Qualifier-derived facts surface as dedicated output columns (see `tackle_winner_*` / `tackle_loser_*` on sportec). Decision: ADR-001.
- **Block-detection columns are cross-provider + nullable (ADR-046, 4.56.0).** Every converter emits `shot_blocked` + `cross_blocked` (in `SPADL_COLUMNS`, pandas `"boolean"`) via the shared `spadl/utils._blocked_flag` helper with 3-valued semantics: `True`/`False` on shot/cross rows the provider encodes a block, `pd.NA` on non-shot/non-cross rows AND on providers that cannot encode it (Opta unverified; SkillCorner absent — real-data verified both tiers; StatsBomb `cross_blocked` deferred at n=1; Sportec/Metrica/kloppy `cross_blocked` infeasible). `cross_blocked` = open-play `cross` only (set-piece crosses `pd.NA` in v1). Additive → **no retrain**; declared `"invariant"` in the ADR-045 reflection registry; atomic-SPADL unaffected (projects to `ATOMIC_SPADL_COLUMNS`). TF-51 prerequisite. GS `crossOutcomeType=="B"` pining-probed on real WC2022.
- **Public enrichment helpers (post-conversion `add_*` family) tolerate NaN in caller-supplied identifier columns.** NaN identifiers route to the documented per-row default (typically NaN-output / False / 0); helpers never crash on NaN input. Decoration with `@nan_safe_enrichment` from `silly_kicks._nan_safety` is the formal opt-in; the CI gate at `tests/test_enrichment_nan_safety.py` auto-discovers decorated helpers. Decision: ADR-003.
- **Public `add_*` enrichers are PURE — input-mutation is CI-gated (ADR-033, 4.32.0).** Every registered `add_*` (the full public surface across `spadl`/`atomic.spadl`/`tracking`/`atomic.tracking` — `__all__` UNION `.features.__all__`, since the 15 `atomic.tracking.features` mirrors export via the submodule, not the package) must NOT mutate any caller-supplied DataFrame/Series/ndarray and MUST return a NEW object. Gate: `tests/test_add_star_purity.py` — one canonical `PURITY_ENTRIES` registry (key `"<package>:<add_name>"`), build-fresh-owned-inputs-once + snapshot-every-array-arg + value-equality + `out is not input`; two meta-assertions pin the surface to the public export (a new `add_*` must register or CI fails). A best-effort AST heuristic NUDGES toward per-branch coverage. **Contributor contract:** any `add_*` that *conditionally* adds columns (a present/absent branch) MUST register ≥2 purity variants (both branches) — the heuristic is a nudge for the one known shape, NOT a guarantee, so the contract is the real backstop. Born from the `add_gk_distribution_metrics` gk_role-present in-place-mutation defect (the gk_role-absent path always copied, so the old column-list guard never caught it). Same PR renamed `pitch_control_at_action`→`pitch_control_at_target` (function aligns with its emitted `pitch_control_at_target__<method>` column base, unchanged since 4.31.0) — note the lakehouse keeps its own DEFCON `pitch_control_at_action` mart column (different semantics; not silly-kicks').
- **GK-domain keeper identity: use the RESOLVED `player_key`, never raw `player_id` (4.45.0/PR-S112).** SPADL `player_id` is **null for goal-kicks by design** (the taker isn't in the raw event — the reason `acting_gk_from_frames`/the lakehouse goal-kick-taker override exist), and it was 100% null across the whole GK-distribution domain in the gold marts. The resolved Kimball surrogate `fct_action_context.player_key` (99.9% populated on `is_gk_distribution` rows) is the keeper identity. Analysis loaders source resolved fields from GOLD marts, NOT raw `bronze.spadl_actions`. CI guards: `tests/xtgk/test_player_key_contract.py` (pure SQL-source guard + an `@e2e` `player_key ≥99%` data-contract that catches both a wrong-column read and a resolver regression).
- **Every band needs a test from BOTH sides, and every counterfactual needs a non-vacuity assertion that it actually moved something.** A gate that only asserts "value is inside the band" passes identically when the value is inside the band *and* when the computation silently produced nothing; a counterfactual test that only asserts `delta == expected` passes when both legs are secretly the same object. Assert the failing side too (a mutation that SHOULD move the number out of the band), and assert the counterfactual measurably differs from its factual twin. **Four silent-null defects in this codebase share exactly one shape** — the kloppy tracking y-inversion (ADR-031), the fabricated `flat_zones` grid origin (ADR-036/PR-S113), the identity-keyed `PitchControlCache` served to a moved-GK counterfactual (ADR-043), and a mirrored external-provider event frame — each produced a plausible number from a computation that had not happened. None was caught by a one-sided assertion; each was caught by a test that checked the other side. Precedents: `test_deep_zone_gate_nan_invariance.py`'s non-vacuity meta-assertion (its first draft compared an all-zero surface to an all-zero surface), the `test_ghost_gk_mirror_invariant` off-centre probe (ADR-040 strengthened it because the central probe moved ~0.1 m and was vacuous), and `tests/gkdv/test_arms.py::test_unpinned_implementation_would_measurably_differ`.
- **Private modules can have downstream consumers.** Before renaming, splitting or relocating any `silly_kicks/**/_*.py`, check `docs/PRIVATE_CONSUMERS.md`. Path pins fail **silently** — a renamed module degrades a consumer's guard with no `ImportError`.
- **Artifact-writing drivers REFUSE a dirty tree (4.63.0, `scripts/_provenance.py`).** Any `scripts/` driver that writes a registered artifact calls `require_clean_tree(git_provenance(), allow_dirty=...)` FIRST — before paying for any corpus work — and stamps `run_commit` + `run_tree_dirty` into its output. The reason is measured, not hypothetical: `git rev-parse HEAD` returns the same SHA whether or not the tree is modified, so a driver stamping the bare SHA records a commit that does **not** describe the code that ran. A corpus pass was launched exactly that way (HEAD clean, three drivers modified); the resulting numbers would have carried a verifiable-looking false provenance, which is strictly worse than none. Absent git counts as dirty, never clean. `--allow-dirty` permits a dev run but the artifact still records `dirty: true` — the escape hatch must never launder the fact. **Enforcement belongs in `main()`, not in the work function** (a `run()` that refuses to execute on a dirty checkout cannot be tested without mocking git; the CLI refuses, `run()` records the truth). **CI-gated as of 4.65.0** (`tests/scripts/test_provenance_wiring.py`): the rule was enforced by memory and memory had already failed twice — `validate_xshot_causal.py` wrote the §3.3 entanglement artifact with no provenance at all, and `validate_xs_probe.py` stamped a bare `git rev-parse HEAD` into the cited 4.60.0 result. The gate requires every artifact driver to import the helper, offer `--allow-dirty`, never shell out to `rev-parse` (AST-matched on CALLS, so prose describing the defect is not mistaken for committing it), and call `require_clean_tree` from `main()`. An artifact whose inputs came from another driver (e.g. the arm-values table feeding the §6.1 ICC number) needs provenance on BOTH, or the clean SHA on the downstream metrics launders the dirty upstream input.
- **Every corpus driver adopts the shared seam `scripts/_driver.py` -- CI-gated, not prose (ADR-052, 4.72.0).** This rule was prose for two releases and prose was not enough: of 21 in-population drivers, **three** survived a crash and **fourteen** held every result in memory and wrote once at the end. `for_each(items, key=, work=, shard_root=, token_inputs=)` owns the loop -- it STREAMS its corpus (never `list()`s it: `load_matches` parses a full tracking frame per match inside the generator), writes one shard per item into a generation DIRECTORY named by a `ruthless.fingerprint` digest of the DECLARED inputs, skips an item whose shard exists, prints a FLUSHED `[i/n]` line, records failures rather than losing the pass, and asserts conservation over its OWN keys. **An empty result still writes a shard** (absent = "not yet run", present-and-empty = "ran, produced nothing"; conflating them recomputes every barren item forever). The primitives are the escape hatch and a driver on that path must call `assert_conservation` **AND** `_require_injective` -- conservation alone is SATISFIABLE BY A LOSSY RUN, because a colliding key makes two items share one shard and `present` counts it once per duplicate key (measured: 2 items -> 1 processed -> conservation returns `(2,2)` and PASSES). **`reconcile` requires a partition surface**; selectors are deliberately outside `token_inputs` so narrowing reuses shards, which makes the generation a SUPERSET of any one run, so every other adopter combines from `res.keys`. Corpus-scoped counters survive resume via a `<key>.counters.json` sidecar (pass-scoped `n_attempted` deliberately does NOT -- a resumed pass must be able to declare it built nothing); use `CorpusPassResult.manifest()`, since a hand-written `manifest_fields(...)` silently took the old `counters_unrecorded=0` default and reported a complete corpus of nothing. **What it does NOT prove:** token completeness (a wrong declaration digests stably), and a SECOND uncounted loop -- that writes no shards and lists no keys, so nothing sees it; a fan-in check is the recorded follow-up. Two rules the migrations produced: `for_each` resumes WORK, never the PRODUCTION of its items, so invert onto an id list only where `work` is unambiguously trivial next to the load; and the `work -> tidy frame` contract carries no per-item METADATA (use the documented `counters(item, frame)` closure) and no non-tabular side state at all.
- **An expensive corpus pass is its OWN shardable driver, and an inestimable replicate is COUNTED (4.65.0, `scripts/build_layer2_spells.py` + `causal/power.py`).** **MECHANISM SUPERSEDED by ADR-052 (4.72.0) — the POLICY below still holds in full (per-match shards on completion, `--match-ids-json` partitionability, atomic writes, counted degenerate replicates), but shard writing and combination now live behind `scripts/_driver.py`: `build_layer2_spells` no longer calls `write_table_atomically` at all (measured: zero references), it calls `for_each` + `reconcile`, and `_partition.py` is retained for MANIFEST aggregation and partitioning. Read this bullet for the WHY, the seam bullet above for the HOW.** Any `scripts/` pass whose per-match work costs minutes writes **per-match shards on completion** (an existing shard is skipped, so a crash resumes) and accepts `--match-ids-json`/`--list-matches` so N processes share one `--out`. Measured: the power driver built its spells INLINE, spent **8.7h** walking 64 matches, then raised in the cheap analysis step that followed and lost every one of them — while the arm-values pass, which had shards, survived its own 64-match run twice. The consumer takes the persisted table (`--spells`, mirroring `--arm-values`), so a crash downstream costs seconds. Reconciliation lives in the shared `scripts/_partition.py` because it has already been wrong once (N workers writing one manifest let the last writer win, so a 64-match artifact reported one partition's `n_matches: 8`) and must not be fixable in one producer while live in the other; it also checks **commit consistency** across workers, since nothing stops one being launched from a different checkout. **A partition that names NO ids for a provider must DROP it** (`providers_for_slice`): the shared loader reads `(match_ids.get(p) if match_ids else None) or list(manifest_ids)`, so an empty list (falsy) and an absent key (None) BOTH expand to the entire manifest — correct for an unpartitioned caller, exactly inverted for a worker, and measured to make every worker of a multi-provider driver load the unsliced providers in full. Two corollaries of running N writers against one output dir: tables are written via `write_table_atomically` (private temp + `os.replace`), per-match shards included because N workers rebuilding it from the shared shard dir means N concurrent writers on one path, and the CONSUMER (`run_signoff_power.py --spells/--arm-values`) reads each input's sibling manifest and REFUSES a dirty upstream, a **missing** manifest (unprovenanced == dirty), or one whose workers ran at different commits — extending the ADR-037 rule above from "this run's tree" to "every artifact this number derives from". Statistically: `att_power_curve` scores a single-treatment-class resample as a **non-detection** and reports it in `n_degenerate_by_size` — never a crash (it used to raise out of sklearn) and never a silent skip. Counting is load-bearing in the same way conservation is: a size whose degenerate count approaches `n_replicates` reports an **inestimable design at that n**, which is not a weak effect, and excluding those replicates from the DENOMINATOR would condition on estimability and inflate the curve exactly where the design is weakest.
- **Academic attribution discipline.** Every new feature implementing a published methodology gets an entry in the `NOTICE` file's "Mathematical / Methodological References" section. Cross-link from per-feature docstrings via `See NOTICE for full bibliographic citations.` Mirrors the lakehouse pattern. Decision: ADR-005.
- **Aggregator column liveness is CI-gated (non-NaN AND non-constant).** Every registered `tracking` `add_*` (the full `__all__` surface, jersey helper included) must produce non-null values for every column it ADDS, and every float METRIC column with ≥2 observed values must carry >1 distinct value, on the multi-domain fixture in `tests/tracking/test_aggregator_column_liveness.py` (5 action windows: pass / shot / GK goalkick / attacking-third / wide-area; actor carries the ball through a final-step kick; per-window velocity/layout/GK/kick variation; event clocks jittered off the frame grid). A meta-assertion pins the gate surface to `tracking.__all__`, so a NEW `add_*` must wire a liveness entry or CI fails. Constants BY DESIGN go in the `STRUCTURAL_CONSTANTS` registry with a justification + dedicated invariant test — never silent exclusions. The registry is currently EMPTY: the space-creation structural zeros were RETIRED from the contract (4.24.0), and the dead `pitch_control_at_ball__spearman` near-ball-PPCF degeneracy was RETIRED + replaced by the LIVE `pitch_control_at_target__spearman` (sampled at the action destination + ADR-028-reprojected; 4.31.0, ADR-032). Born from the TF-41 hard-coded-NaN `_opponent` defect (ADR-026; non-constant added 4.24.0 after `space_destroyed_m2 ≡ 0` showed non-NaN alone is insufficient).
- **Linkage-provenance columns are idempotent.** All tracking `add_*` aggregators that merge provenance columns (`frame_id`, `time_offset_seconds`, `link_quality_score`, `n_candidate_frames`) must skip the merge when those columns already exist on the input DataFrame. This allows callers to chain multiple `add_*` calls without producing `_x`/`_y` suffixed duplicates. Pattern: `if not any(c in out.columns for c in provenance_cols):`. CI gate: `tests/tracking/test_provenance_skip_guard.py`.
- **Pre-linking optimization via `links` kwarg.** All tracking `add_*` aggregators accept an optional `links: pd.DataFrame | None = None` kwarg. When provided, the function skips its internal `link_actions_to_frames` call and uses the caller-supplied pointers. Pipeline callers (e.g. lakehouse) pre-link once and pass `links` to all enrichment steps, reducing N × 2-5s to 1 × 2-5s per match. The `links` DataFrame must be the pointers output of `link_actions_to_frames` (columns: `action_id`, `frame_id`, `time_offset_seconds`, `n_candidate_frames`, `link_quality_score`). Internal helpers (`_resolve_action_frame_context`, kernel functions) also accept `links` for full thread-through. `infer_ball_carrier` additionally accepts `pre` (a precomputed `_pre_index_frames(frames)`) and `ball_carrier_at_action` accepts both `pre` and `links`; the pre-index dominates carrier cost (~99%) yet is param-invariant, so the TF-24 Stage-1 calibration objective caches `pre`+`links` per match (invariant-prepare) and re-runs only the carrier kernel per Optuna trial (~100× faster sweep; bit-identical).
- **Shared pitch-control surface via `pitch_control_cache` kwarg.** All pitch-control-consuming aggregators (`add_obso`, `add_cover_shadows`, `add_gk_influence`, `add_player_influence`, `add_space_creation`, `add_pitch_control`) accept an optional `pitch_control_cache: PitchControlCache | None = None` kwarg (mirrors `links`). `PitchControlCache` (in `tracking/pitch_control/`) memoizes **canonical** per-frame surfaces keyed on `(game_id, period_id, frame_id, team, method, params, ball_position, decompose)`, so families that need pitch control on overlapping frames compute each surface once instead of once per family. Only canonical-frame surfaces are cached — **counterfactual** (player-removed) surfaces in `cover_shadows`/`space_creation` are never routed through the cache. Zero global state. - **Dtype-safe id comparisons are a REPO-WIDE contract (ADR-019, 4.15.0; scope widened 4.53.0/ADR-043).** No consumer anywhere in the package compares ids (action↔frame, action↔action, or against a scalar `home_team_id`/`player_id`) with raw `==`/`!=`, and none merges on id keys without alignment — those silently mis-resolve across dtypes (`Int64(366) == "366"` → False) or raise on a mixed merge key. Originally written as a *tracking-feature-seam* rule; it never was one, and 4.53.0 stopped pretending — the seam is the **public `silly_kicks.id_compat`**, imported by **39 modules across 6 packages** (`spadl/`, `vaep/`, `atomic/`, `causal/`, `gkdv/`, `tracking/`; measured by AST over `silly_kicks/`, excluding the module itself). ADR-043 promoted it out of `tracking/_id_compat.py`: five packages were reaching into a private *tracking* submodule, two via function-local imports in `spadl/utils.py` written to dodge a circular import, and a seam ADR-019 makes MANDATORY is public API by definition. **Breaking import-path change, no shim** — the pin fails loud at import, and a shim would have made the promotion cosmetic. Surface: `ids_equal`/`ids_differ` (column-vs-column, NA-safe both-present), `ids_match` (Series/array vs scalar), `same_id` (scalar↔scalar groupby loops), `align_join_keys` (pre-merge, numeric-vs-object only), `restore_id_dtype` (put a kernel-built id column back on its SOURCE dtype where that dtype can represent the result — numpy ints can't hold NA, so a result with unmatched rows stays float). One `_canonical` truth (integral-float collapse; genuine strings pass through). **The both-object fast path is CONTENT-probed, not free** (`_raw_comparable`): an object column of boxed floats raw-compares False against the same id as a string, so dtype alone cannot license a raw `==`. Probe cost ≈15% of the comparison per side, ≈30% for the guard. Opt-in loud guard: public `validate_id_dtypes` + `IdDtypeDiagnosis` (mirrors ADR-017's `validate_time_base`). CI gates: red-first **asymmetric** dtype-invariance gate over every registered `add_*` (`tests/tracking/test_id_dtype_invariance.py`; numeric actions × string frames + reverse, `home_team_id` independent axis) + meta-assertion (gate surface == registered surface) + the **`PUBLIC_ID_SCALAR_ENTRIES` registry** (`tests/invariants/conftest_id_scalar.py`, exercised by `tests/invariants/test_public_id_scalar_registry.py`) + structural de-dup perf guard. **The AST lint is DELETED as of 4.53.0/ADR-043 — deleted, NOT widened, and do not reinstate it.** Widening was rejected on principle, not cost: it was a NAME heuristic (it missed ADR-027's `t != action_team`, and `_ghost_gk`'s `str(t) == home_team_id_norm` because the scalar was renamed), but the unfixable part is that **a safe same-source compare and an unsafe cross-source one are the IDENTICAL AST** — only the scalar's *provenance* separates them, and no syntactic rule sees provenance, so any widening either flags correct code (breeding the exemptions that grew `ALLOW_MODULES` in the first place) or keeps missing real defects. **Complete by ENUMERATION where the lint was incomplete by HEURISTIC** (same idiom as ADR-003's NaN-safety registry and ADR-033's `PURITY_ENTRIES`): the registry derives its surface from `inspect.signature` over the `__all__` exports of `spadl`/`atomic`/`vaep`/`causal`/`tracking`, keyed by defining qualname — **102 functions: 77 exercised directly, 22 delegated** to the `add_*` gate (machine-checked against that gate's registered surface, not asserted in prose), **3 justified non-invariant** — each invoked on a matched scalar, a mismatched-but-value-equal one (`5` vs `"5"`), and a **float** one (`5.0`; not redundant — a naive `str(x)==str(s)` renders identically for ints, so only the float axis exposes it). Two meta-assertions pin it to the public surface in BOTH directions, so a newly-exported id-scalar function fails CI until registered, delegated or justified — the anti-rot property the lint's glob lacked. It caught two live `str()`-comparison defects on its first run that the lint structurally could not have seen. Fixed three latent bugs (object-`is_ball` `~`-no-op ball-as-opponent; `str(5.0)` iterrows-upcast player-influence/cover-shadow mislabel; object-path opponent join-miss) → **VAEP retrain trigger**. ADR-001 preserved (fix lives at consumer seams, not converters). **4.25.0 (ADR-027), retained as the historical case that killed the lint:** it missed a raw `t != action_team` in `_line_breaking.py` ward (a NaN-team crash + an Int64-vs-string silent opponent miscompute on GS) because the operands are not named `*_id`; the behavioral NaN-safety gate (`tests/test_enrichment_nan_safety.py`, NaN-team fixture) caught it. Fixed via `same_id` + a `pd.isna` NaN-route. **Behavioral gates, never a lint, are the backstop** — ADR-043 acted on exactly this by replacing the lint with the enumeration registry above. One site ships DELIBERATELY ungated (the velocity-state defending split, ADR-043 decision 6): its `gk_team` scalar comes from the same frame it is compared against, so no input can distinguish `ids_match` from `==` and no lint could flag it without flagging safe code — recorded so a future reader meets the reasoning instead of "fixing" an untested line.
- **Per-action geometry is emitted in the SPADL action-LTR frame (ADR-028, 4.26.0).** Actions are per-acting-team LTR (acting team attacks x=105); `convert_to_frames` is home-attacks-right (home attacks x=105 every period). They are a 180° point reflection apart for **away-team actions**, and the geometry layer historically sampled frame positions WITHOUT re-projecting → ~50% of tracking action rows wrong: visibly-bimodal absolute positions (`pre_shot_gk_x`, `defensive_line_x`, `team_shape_centroid_*`) AND silently-wrong mixed-frame scalars (`nearest_defender_distance`, `receiver_zone_density`, `defenders_in_triangle_to_goal`, all `pressure_on_actor__*`, `pre_shot_gk_distance_to_shot`/`_angle_*` — action anchor combined with frame positions). - **Trained artifacts are parameters-only, pickle-free, and fail-closed on load (ADR-011, ADR-016, ADR-040, ADR-044, ADR-050).** Every bundled model (`GhostGkModel`, `XShotOccurrenceModel`, `XCrossAttemptModel`, `GkCompletionModel`, `GkRetentionModel`) serializes as npz or booster-JSON plus JSON metadata plus `SHA256SUMS` -- never pickle -- and inference never imports sklearn. Distributed ghost artifacts carry **no training data** (`stores_training_data:false`), so `predict_density` and `ghost_gk_density_spread` exist only on a locally `fit()` model. `load()` enforces two independent guards. **Chirality** (`_chirality.verify_chirality`) re-runs the model's own outputs on `canonical_probe_frame` and raises both on a MISMATCH and on a MISSING fingerprint -- every pre-enforcement artifact is the mis-served class -- with `legacy_override=True` as a warning escape hatch. The **feature contract** (`_feature_contract`) records the feature vector an extractor produces on a fixed probe plus the geometry constants it consumes: a missing contract WARNS (pre-contract artifacts are undeclared, not known-bad), a probe change warns and skips only the fingerprint comparison, and a fingerprint or declared-constant mismatch RAISES with that model's own `IntegrityError`. **Declared constants compare FIRST and ALWAYS**, including when the probe changed, because a sub-probe-resolution change moves no feature and only the declared constant catches it. Tolerance is chosen, not inherited (`atol=1e-6`, `rtol=0`); `equal_nan=True` is load-bearing, since `np.allclose(v, v)` is False for any NaN-bearing vector; and a declared constant MUST be load-bearing on the probe, or the guard fires when nothing changed and `legacy_override` becomes reflex. `load_xgb_booster_base_score_safe` strips the bracketed `"[X]"` `base_score` that xgboost 3.x writes and 2.x silently drops to the `0.5` default.
- **Geometry constants are canonical and CI-enumerated (ADR-050).** Use `spadlconfig.penalty_area_half_width` / `penalty_area_depth` and the two frame-explicit predicates `_geometry.in_penalty_area_absolute(x, y, *, attacked_goal_x)` / `in_penalty_area_goal_relative(gr_x, y)` -- two entry points because the call sites differ on FRAME, not just strictness, and `goal_x` already means the *defended* goal in `_geometry` (same name, two readings, an 88.5 m error). The goal-relative form takes no goal argument so the ambiguity cannot re-enter. `_ghost_gk` deliberately keeps its own 40.3 (its weights were fit on it), pinned by a raise rather than a comment a contributor can delete. Rule: **a module-level constant exists iff something in that module reads it** -- aliases would satisfy the enumerator vacuously. `tests/tracking/test_geometry_constant_enumeration.py` AST-walks the extractor modules and requires every geometry constant either declared in a model's contract or `_EXEMPT` with a reason.
- **A feature that reads its own action's `result_id`, or any post-contact outcome, ships with NO `*_xfns` factory -- or stays out of every default xfn list.** Enforced by an auto-discovering absence guard anchored on the transformer NAME, so renaming a factory cannot silently disarm it. TF-48 shot goalmouth (ADR-030) and TF-51 defensive credit (ADR-047, ADR-049) ship no factory at all; `packing_xfns` (ADR-039) and `off_ball_run_value_xfns` (ADR-042) exist but are in no default list. Opting a leaky factory into a default list is a HybridVAEP-class correctness break, not a tuning choice.
- **`DasUnscoreableError` is the ONLY degradable DAS exception (ADR-043).** Everything else PROPAGATES. The former broad `except (ValueError, RuntimeError, ImportError, IndexError, TypeError)` swallowed silly-kicks' own bugs, and an all-NaN column is indistinguishable downstream from legitimately-absent DAS. `add_das` emits a `das_source` column over the closed `DAS_SOURCE_VALUES` vocabulary (each token also exported as a `DAS_SOURCE_*` constant so consumer enums pin to the library's set); `das_at_action` returns a bare Series and carries no provenance; `das_xfns` deliberately does not emit the string column, because VAEP matrices stay numeric.
- **`speed_source` has three tokens, not two.** `TRACKING_CATEGORICAL_DOMAINS["speed_source"]` is `{native, derived, unavailable}`. `"unavailable"` is a frame builder DECLARING that its source has no per-player temporal history, so `speed`/`vx`/`vy` can never exist -- deliberately distinct from a NULL `speed_source` ("not derived YET"), because the two demand opposite responses. Third-party builders may set it; it is a public contract, not a snapshot backdoor. An UNMARKED or PARTIALLY-marked frame set missing `vx`/`vy` still RAISES: fail-loud wins on a mixed frame set.
- **Public warning categories are deliberately separate, never one umbrella.** `SyntheticEPVWarning`, `IgnoredSurfaceInputsWarning`, `RunValueCoverageWarning`, `MissingFeatureContractWarning`, `UnverifiableFeatureContractWarning`, `OrientationUnresolvedWarning`, `GhostClampWarning`, `UndeclaredGeometricColumnWarning`. None subclasses another (test-enforced): silencing a routine notice must never silence genuine misuse, and escalating the missing-contract case must never turn every benign probe extension into a hard failure. CI escalates `SyntheticEPVWarning`, `IgnoredSurfaceInputsWarning` and `MissingFeatureContractWarning` only -- `OrientationUnresolvedWarning` is NOT escalated, and escalating it remains an open decision rather than a guarantee to rely on.
- **Reflection goes through the one public seam `silly_kicks/reflection.py` (ADR-045).** A 180-degree point reflection point-reflects POINTS, **negates VECTORS** (`vx`/`vy`/`dx`/`dy`), leaves MAGNITUDES (`speed`) alone and swaps DIRECTION LABELS. Every column declares a `ReflectionKind` in `TRACKING` / `SPADL` / `ATOMIC_SPADL_REFLECTION_KINDS`; `reflect()` serves schema-bearing tables and `reflect_columns()` derived or pre-canonical frames. The historical defect class is columns that an explicit per-site list simply omitted -- `vx`/`vy`/`x_smoothed`/`y_smoothed` are not in `TRACKING_FRAMES_COLUMNS` (preprocess adds them), so they rode through untransformed. `on_unknown` defaults to `"warn"`, NOT `"raise"`: `to_spadl_ltr` runs inside nine converters on frames carrying the caller's unbounded `preserve_native` columns, so a raise has no reachable remedy; fail-closed lives in the CI registry-completeness meta-assertion instead. - **`ExpectedThreat.xT` stores rows y-INVERTED; `rate()` compensates and `interpolator()` does NOT (ADR-041).** `xthreat/_physical.py` is the ONE place that inversion is neutralized: `physical_grid(model, grid_x, grid_y)` resamples onto a **consumer-supplied** grid in ascending-y physical orientation (pass the consumer's own grid; do not invent one), `values_at_points` gives exact NaN-tolerant `rate(use_interpolation=False)` semantics, and `require_fitted_xt` is the single fitted-model guard. Never multiply a raw `interpolator()` output into a physical surface. `compute_threat_pc` REFUSES an unfitted xT -- it used to return `0.0`, so any caller persisting a threat column persisted structural zeros that look like a measurement.
- **Policy lives at the edge, never in the shared engine.** The ghost pitch clamp sits at the serving seam, not in `predict_mean` (whose exact-boosted parity contract must stay clean); the restart geometry tripwire sits at the `add_restart_coordinates` edge, not in `resolve_restart_geometry`; the per-type base-rate switch sits in `compute_xt_gk`, not in `predict_proba`, which stays a pure scorer. A guard that changes numbers belongs where the decision is made.
- **The library ships RAW primitives; composites, archetypes and rankings stay consumer-side (ADR-009).** TF-45 emits `structural_lbs` / `structural_sgm` / `structural_sdi`; the TIV z-norm composite, the K-means archetypes and the delta-TIV/cumulative rankings are frozen-exogenous consumer concerns.
- **Corpus visibility is fail-closed (`scripts/_corpus.py`, ADR-038).** `is_public_row` treats unknown or missing visibility as restricted, `artifact_label` derives from the ship-mask composition, and `assert_public_corpus` subset-gates. There is deliberately no `_PUBLIC_PROVIDERS` provider allowlist -- it labelled a restricted-corpus run `"public"`, i.e. marked a non-redistributable model reproducible. A trainer with no taxonomy enforcement must be pointed at a public-only corpus by hand.
- **A validation harness must make the observed outcome UNREPRESENTABLE, not merely refused.** `causal.power.att_power_curve` accepts no outcome vector at all -- only an `InjectionSpec` recipe it draws from per replicate -- so machinery that could answer an open research question before the sign-off meant to authorise it structurally cannot. A call-count spy on `estimate_att` would be vacuous (the harness always calls it); the guard is provenance, and its non-vacuity is demonstrated by removing the guard and watching a fully duck-typed fake succeed silently. Relatedly, an inestimable replicate is COUNTED (`n_degenerate_by_size`), never crashed on and never silently skipped: excluding it from the denominator would condition on estimability and inflate the curve exactly where the design is weakest.
- **Feature columns are documented in `silly_kicks/feature_glossary.py`, and coverage is CI-gated (ADR-048).** Every derived column carries a `FeatureColumn(name, definition, unit, emitting_module, attribution, higher_is_better)` record; `emitting_module` is the metric's HOME compute module (`_packing`, `_obso`, ...), not the `features.py` monolith where the public producer happens to be defined. `describe_level(z, *, higher_is_better=True)` lives separately in `silly_kicks/reporting.py`, because direction is glossary metadata and the caller supplies it -- so a lower-is-better metric is never mislabelled. A new `add_*` or `*_xfns` must document its columns or the coverage gate fails; the load-bearing completeness dependency is the `add_*` / `*_xfns` NAME SHAPE.
- **The C4 model (`docs/c4/`) is pinned to the code.** Subpackages are derived from the package tree by a completeness gate -- nothing else pinned the diagram to the code, which is how a public subpackage went unmodelled for five releases. A new action-coupled `add_*` aggregator changes the documented count.
- **Frame-aware `*_xfns` must resolve frames POSITIONALLY, never by `action_id` lookup (ADR-020).** VAEP shifted gamestate slots repeat the boundary action, so `action_id` is NOT unique in an xfns matrix: `set_index("action_id").at[aid]` returns a Series and raises, and provenance merges fan out. `_kernels.resolve_frame_ids_by_position` is the single seam, byte-equivalent to the old `.at` on unique ids. A `.at` grep missed two of the eight defective families; the behavioral gate found all eight.
- **A coverage denominator must never masquerade as a tactical signal (ADR-042).** Mean disruptive run value divides by `n_valued_disruptive_runs`, NEVER `n_disruptive_runs`, or tracking coverage reads as tactics. A runner absent from the linked frame keeps `run_value` NaN and keeps its ROW (`RunValueCoverageWarning`) -- never a fabricated `0`. - **Detection lands BEFORE the fix, and every registry gate carries an anti-rot meta-assertion (ADR-051).** A gate written after its own repair arrives green and is never observed failing, so the mirror gates above were landed RED -- enumerating all 33 aggregators before a single fix existed. ## Testing

```bash
python -m pytest tests/ -m "not e2e" -v --tb=short
```

e2e tests require dataset fixtures not committed to the repo. Tests with
fixtures committed to the repo should not be marked e2e — they run in
the regular suite.

CI runs a bulk suite step serial (`--benchmark-skip`) on every matrix leg and a benchmark
*measurements* step single-threaded (`--benchmark-only`) on the primary leg only (see the
slow-test-gating note below for the per-leg split). There are no wall-clock
`assert ms < budget` perf tests — performance regressions are guarded by
**deterministic structural guards** (call-count spies on each function's dominant
primitive; see `tests/_perf_structural.py` + the `*_perf_budget.py` files), which
never flake on shared runners. (An xdist parallelization was tried and reverted: it
regressed py3.12 on the 4-core/7GB CI runners — memory/JIT pressure.)

**Doctests: CI executes `--doctest-modules` on the PUBLIC surface only** (`pytest --doctest-modules
silly_kicks/ --ignore-glob="*/_[!_]*.py"`, every leg; PR-S124, wiring guarded by
`tests/test_ci_doctest_wired.py`). The glob skips single-underscore
private modules while KEEPING dunder `__init__.py`; private-module examples are kept CORRECT (the
whole-package sweep is clean) but are NOT executed in CI, to bound wall-clock — the initial
enforcement scope. Most public examples are the canonical indented RST **literal block** (the honest
form for anything needing a real match's `actions`/`frames`/`xt` — no docstring can conjure them);
`tests/test_public_api_examples.py::_has_real_example` accepts a ≥4-space-indented non-`>>>` line in
the Examples section as a REAL example, so converting a failing `>>> f(actions, ...)` doctest to a
literal block satisfies BOTH the doctest run (nothing to execute) and the Examples gate. Genuinely
self-contained examples stay executable `>>>` doctests. Do NOT reintroduce `>>> f(x)  # doctest: +SKIP`
filler — the gate's `_demonstrates_something` rejects it (the 4.53.0 tightening).

**`@pytest.mark.slow` = expensive AND platform/interpreter-INVARIANT** (does-it-run train-script
smokes, same-run internal-consistency/parity, calibration cache-equivalence). These run **once on the
CI primary leg (`ubuntu-3.12`, matrix `primary: true`)**; every other leg runs `-m "not e2e and not
slow"`. Do **NOT** mark version-sensitive tests `slow` (golden-hash / snapshot / absolute-numeric — e.g.
`test_golden_*`) — they must stay on all legs (OS + interpreter axes), as must cheap behavioral-contract
guards (dup-`action_id`, id-dtype-invariance, orientation/roster). The matrix partition is guarded by
`tests/test_ci_slow_gating_wired.py`. Decision: ADR-023.

**Claims about a gate's behaviour must quote the assertion body, not its registration.**
A gate's registry (`ENTRIES`, `PURITY_ENTRIES`, `AGGREGATORS`, `_PUBLIC_MODULE_FILES`,
`_EXHAUSTIVE_EMITTED`) tells you *whether* a helper is exercised — never *what is asserted
about it*. Two PR-S119 review errors came from this, one on each side: a reviewer read the
liveness gate's registration and concluded a partially-`pd.NA` column would fail, when
`tests/tracking/test_aggregator_column_liveness.py:416` asserts only
`not out[c].notna().any()` (100%-null), and `:448`'s non-constant check is
float-dtype-gated so non-numeric columns are exempt entirely; and a plan asserted the
synthetic reachability grid was exactly y-symmetric and that symmetrizing it would cost
"≤ 1 ulp", when neither had been run (measured: 4.44e-16 across 3752/6400 cells). Same
failure mode both times — adjacent evidence substituted for the executed thing. **Rule: any
claim that a test passes or fails, or that a numeric property holds, carries either the
quoted assertion body or a pasted measurement.** Registration proves coverage; only the
assertion proves behaviour. Corollary for tolerances: measure at the scale you assert at —
grid-level float noise does not transfer to a derived area (a 3.3e-16 relative grid
asymmetry is not a 1e-12 absolute bound on an m² quantity).
