# silly-kicks

Maintained fork of socceraction — SPADL event conversion + VAEP action valuation for soccer analytics.

## Architecture

- **Hexagonal**: All core functions are pure (pandas in, pandas out). Zero I/O, zero global state mutation.
- **Converters** (`spadl/`): Each provider (StatsBomb, Opta, Wyscout, Sportec, Metrica, Gradient Sports, SkillCorner, plus the Kloppy gateway) has its own module. All return `tuple[pd.DataFrame, ConversionReport]` with guaranteed columns/dtypes via `_finalize_output()`. Live per-provider contracts:
  - **Gradient Sports goal capture (ADR-018).** Own goals = `RE`+`shotOutcomeType=="G"` -> `bad_touch`+`owngoal` (conceding team/rebounder kept; a post-LTR own-half geometry tripwire warns+reverts a mis-located one). Cross-goals = `CR`+`G` -> keep the cross + synthesize a `shot`/`shot_freekick`+`success` by the crosser; synthesized rows carry `is_synthetic=True` (they share the parent's `original_event_id`). Voided `possessionEvents.nonEvent==True` events are excluded (optional column -- absent is an observable no-op warn, tallied in `excluded_counts`). `"O"` shot-outcome is off-target -> `fail`, NOT own-goal.
  - **GS null-actor rows carry NaN, never a sentinel `0` (ADR-027).** The null-actor duel/foul events (`OTB`+`CH`, `FOUL`+`FO`) have both `gameEvents.teamId` AND `playerId` NULL; GS schema ids are nullable `Int64`, not the `SPADL_COLUMNS` `int64`. A non-NaN sentinel bypasses `pd.isna` routing and crashes downstream opponent guards. ADR-001 forbids back-filling from duel/foul qualifiers; `_resolve_team_ids` fills team ONLY from a real same-match `player_id` (ambiguity raises). `convert_to_atomic` preserves source id dtype.
  - **GS dribble ends are derived GS-locally (ADR-018 amendment).** GS initializes `end=start` for every event and never runs `_add_dribbles`, so every `OTB`+`BC` shipped a placeholder. `_derive_end_coordinates` takes keyword-only `extra_type_ids` and ONLY gradientsports passes `{dribble}` -- the shared `_DERIVE_END_TYPE_IDS` stays untouched, because its `placeholder_end` guard cannot distinguish statsbomb's genuine stationary carries from placeholders. Period-last carries honestly keep the placeholder.
  - **GS ball-carry results come from the native `ballCarryOutcome`**: `R` (retained) -> success, `L` (lost) -> fail, unknown/absent -> fail. Without it every GS dribble fell to `fail`.
  - **SkillCorner `time_seconds` is period-relative** -- `_to_period_relative` subtracts the period-start offsets `{1:0, 2:2700, 3:5400, 4:6300, 5:7200}` (ADR-017).
  - **SkillCorner `result_id` routes through the native outcome** -- `pass_outcome` -> `received==True` (success-only) -> residual `same_team_next` -- and emits a dedicated `result_source` column (`native`/`inferred`/`stopgap`) in `SKILLCORNER_SPADL_COLUMNS`. `received==False` is NOT a fail (it can be completion to a non-targeted teammate).
  - **SkillCorner `_transform_coords` scales THEN clamps -- never call it on tracking (ADR-038).** The clamp is safe for events (on-pitch by construction) and destructive for tracking: a ball 9 m behind the goal snaps onto the goal line, erasing goal-vs-save. Tracking calls `_scale_to_spadl` (affine only) and nothing else. Pitch dims come from the events converter's own affine transform; missing dims RAISE, and `assume_standard_pitch=True` is the explicit opt-in.
  - **sportec pass/set-piece results use a kloppy-aligned success-ALLOWLIST** on the native DFL `play_evaluation` (`_extract_play_eval`/`_play_evaluation_is_fail`/`_warn_unexpected_play_eval`, single-sourced across the main and synth sites): `fail` iff the Evaluation is non-empty AND not in `{successfullyCompleted, successful}`, so unseen reason-coded failures fail by construction; empty/absent/NULL -> success (no mass-fail on a missing column); unexpected tokens warn. The punt-synth goalkick inherits its parent Play's eval.
  - **metrica is deliberately unchanged** -- measured-correct (PASS = completed pass; a loss is a separate `BALL LOST` event).
  - **Restart-coordinate enrichment is additive (ADR-025).** `spadl.add_restart_coordinates(actions, *, frames=None, links=None)` imputes NaN restart coords for the Law-fixed-spot types as NEW provenance-tagged columns (`enriched_start_x/_y`, `enriched_end_x/_y`, `start_coord_source`/`end_coord_source`, `*_coord_confidence`) and NEVER mutates canonical `start_x`/`end_x`. Single engine `tracking.resolve_restart_geometry`; `tracking.resolve_gk_geometry` is a byte-identical shim over it.
- **Tracking** (`tracking/`): Per-frame namespace parallel to `spadl/`. 20-column long-form schema (`TRACKING_FRAMES_COLUMNS`); native Sportec + Gradient Sports adapters; native SkillCorner + Metrica bronze->frame builders (ADR-034); kloppy gateway. The linkage primitive (`link_actions_to_frames` + `slice_around_event`) joins SPADL actions to frames -- pointer-DataFrame return plus a `LinkReport` audit (ADR-004). Tracking-aware features compose into VAEP via `compute_features(*, frames=None)` and the `_frame_aware` xfn marker (ADR-005); every family has an `atomic.tracking.features` mirror.
  - **`time_seconds` is period-relative** (it resets each period -- NOT an absolute match clock). ADR-017 enforces it with a per-period `min_link_rate`/`on_low_coverage` guard plus `LinkReport.per_period_link_rate`, and public `validate_time_base`/`TimeBaseDiagnosis` as the pre-link guard for time-filtering consumers (the linker cannot see pre-filtered-out actions).
  - **GK identity:** `is_goalkeeper_source` is `native` or `derived`; `_gk_identification.derive_goalkeepers` is the B+ filtered algorithm with agreement-based source resolution. SkillCorner **trusts its authoritative roster** (`native`, derivation skipped; derive only for a `(game, team)` with no native GK) -- positional derivation is unstable over the short windows a batched builder sees. Metrica has no roster and stays Tier-2 (ADR-007); it seeds NONE, because `gk_jersey_numbers` is a flat team-agnostic list and `derive_goalkeepers` ORs-never-clears.
  - **Metrica input CONTRACT:** bronze `y` must be SPADL bottom-to-top. Kloppy's metrica NATIVE coordinate system is top-to-bottom, so a `TrackingDataset` consumer MUST flip `1-y`.
  - `tracking.preprocess` ships Savitzky-Golay / EMA `smooth_frames`, linear `interpolate_frames`, SG-derivative `derive_velocities`, and the shared `PreprocessConfig` (flag-based `is_default()`, per-provider defaults auto-promoted via `for_provider`).
  - Feature families -- purity, liveness, NaN-safety, dtype and orientation rules for every `add_*` are in **Key conventions**:

- **VAEP** (`vaep/`): Feature engineering + gradient boosting binary classifiers. `HybridVAEP` removes result leakage from a0 features. xG-targeted labels available via `xg_column` parameter. PR-S32 ships TF-29 design-space variants: `window` parameter on `scores()`/`concedes()` (`"action"` / `"possession"` / `"time"`); `xfns_default_no_goalscore` / `hybrid_xfns_default_no_goalscore` goalscore-bias-control lists. **4.13.0 (ADR-018): own goals are counted by RESULT (`result_id==owngoal`), not via a `type_name` shot-gate** — single-source `_is_goal`/`_is_owngoal` helpers in `vaep/labels.py` (all sites route through them; a guard test forbids the old shot-gated owngoal predicate). Fixes a codebase-wide undercount (every converter emits own goals as `bad_touch`, which the old `str.contains("shot")` gate zeroed out); the atomic label path already counted them. Hyrum: shifts scores/concedes/xG label distributions for all providers (VAEP-model retrain trigger).
- **xT** (`xthreat/`): Expected Threat. SK-xT-1 (4.17.0, ADR-021) refactored the `xthreat.py` module into a package with a house-style **pluggable transition family** (string-dispatch + frozen-dataclass params, NOT ABCs): `ExpectedThreat(method="singh_counts"|"kde_smoothed", params=, l=, w=)`. The `singh_counts` default is **byte-identical** to the classic socceraction grid (frozen-oracle parity gate at `tests/xthreat_legacy_reference.py`); `singh_transition_matrix` is vectorized (`np.add.at`, byte-identical). KDE-smoothed transition (`kde_smoothed_transition_matrix`, Silverman-1986 bandwidth, adaptive per-source-zone); `KDEParams.bandwidth=1.0` (pure Silverman) is a conservative default — the held-out-NLL optimum is **corpus-size-dependent** (~1 on a 64-match sample, ≥4 on an 8.9M-action mart), tune via the evaluator. `GridSpec` first-class variable resolution (pitch dims stay in `spadlconfig`). Standalone `value_iteration` (raw-diff convergence — monotone-from-below, do NOT "fix" to abs; optional `max_iter`). Held-out **transition-model** NLL evaluator (`holdout_split` `game_id`-keyed, `compute_holdout_nll` pure, `compute_holdout_nll_per_group`) — NOT an xT-quality metric. KNN/conditional deferred (pre-publication); lakehouse `XTGrid` declined (keep raw `.xT`). Additive — no Singh-path change, no retrain trigger (TF-24 calibration `FrozenXt` untouched). Lakehouse-proposed; attribution Singh 2018 / Silverman 1986 / Salimi 2026 (pre-pub). Decision: ADR-021. **SK-xT-2 (4.19.0, ADR-022)** wires xT into VAEP as an opt-in, frame-free feature: `vaep.features.xt_xfns(*, model)` + atomic mirror `atomic.vaep.features.xt_xfns` emit `xt__<model.method>` per gamestate slot (ADR-005 §8 naming), caller-supplies-the-fitted-model (fail-closed; `str`/`None`/unfitted raise; `ExpectedThreat` imported `TYPE_CHECKING`-only — duck-typed at runtime, **no new runtime edge**). In **no** default xfn list (additive — opting it in is a self-triggered VAEP retrain; guard test enforces absence). Atomic reuses `model.rate()` **unchanged** (no `_rate_cells` extraction — SK-xT-1 parity gate untouched) via a synthesized standard-SPADL frame + **type-aware** `result_id` (dribble intrinsic since dribbles are never followed by `receival`; pass/cross success iff next atom is `receival`); maps slots by composite `(game_id, period_id, action_id)`; period-last pass/cross → NaN (inherent atomic edge). Cross-representation symmetry verified by a geometry-keyed oracle (NOT `action_id` — `convert_to_atomic` renumbers it) + a dribble keystone gate on the committed WC2018 fixture. Bundled-grid variant reserved via a typed `str` door (ADR-011). C4-free.

- **xT-GK v1** (`tracking/_xt_gk.py`, `_gk_geometry.py`, `_gk_completion.py`): FROZEN parametric GK-distribution value (ADR-024) -- `compute_xt_gk` / `add_xt_gk` / `xt_gk_xfns` plus `XtGkParams.for_philosophy`. Tracking-required; in no default xfn list. Live contracts:
  - Normative params (gamma/delta/phi/eta, `defensive_third_boundary`, `pressure_scale`, `convolution_sigma`) are **intent-set, NEVER calibrated**.
  - **Invariant: the phi surface enters value via PEV and DZV ONLY** -- `base = -xT*(z)` and RAV stay on raw `xT*`, so the destination is never revalued twice. Behaviourally guarded.
  - `resolve_gk_geometry` derives a missing goal-kick origin/destination WITHOUT mutating shared `actions`, emitting per-row `xt_gk_origin_source`/`xt_gk_dest_source`/`xt_gk_origin_confidence` plus an aggregate `XtGkReport`. The `x <= 16.5` goal-area clamp is an **action-LTR own-half predicate, so it must run AFTER the ADR-028 reflection**, never before -- applied to a raw away-team frame x it rejects a correctly-placed keeper and silently loses the tracking tier.
  - **Native-origin trust is a FAIL-SAFE provider allowlist** (`native_origin_is_trusted`; unknown/None/future -> distrust). Distrust scope is **goal-kicks ONLY**: SkillCorner records a goal-kick origin as the broadcast ball detection ~14-20 m downfield, but its open-play GK-pass origin IS the keeper (measured 0.4 m).
  - `GkCompletionModel` (logistic, pure-numpy `sigmoid(Xb)` serve, pickle-free JSON + SHA256) backs RAV and the public `compute_gk_completion` / `add_gk_completion`. **Provider-keyed variants** via `variant_key_for_provider` (`skillcorner` -> its own weights, else `gs`); one call = one match (`_resolve_single_provider`). **Training is `result_source=="native"`-ONLY** -- `inferred` is positive-only and would bias a multiplicatively-consumed calibration -- and defaults to FULL-match frames, because a small `--tracking-limit` starves derived-GK detection and inflates the domain. A capped run is dev-smoke only, never used to bundle.
  - **Per-type serve gate:** any completion sub-domain whose held-out AUC lower confidence bound is <= 0.5 (or degenerate, or `n < 50`) serves the calibrated per-type base rate, tagged `xt_gk_completion_source="base_rate"` (`serve_mode_from_lcb`). Data-driven per variant, not a blanket goal-kick rule.
  - **Do not pool `xt_gk` across completion variants without running the comparability gate** (`scripts/_xtgk_comparability.py`).
  - The resolved-coordinate audit columns (`xt_gk_origin_x/_y`, `xt_gk_dest_x/_y`) are provenance and deliberately NOT in `_OUTPUT_COLS`, so `xt_gk_xfns` never surfaces them as VAEP features.

- **xT-GK v2 possession value** (`xtgk/`): the honest value surface `V(z,p)` behind the v2 metric `rho*[V(s') - V(s)] - (1-rho)*[V(s) + kappa*V_opp]` (ADR-036). Hexagonal -- a `PossessionValue` Protocol plus adapters; `compute_xt_gk_v2` depends only on its three ports and emits the coherent additive decomposition `xt_gk_v2_position` / `_pev` / `_retention_loss` / `_dzv` / `xt_gk_v2`. In no default xfn list.
  - `MarkovPossessionValue` (production) = pressure-stratified value iteration reusing `xthreat.value_iteration` verbatim, with an xG-calibrated first-shot reward, a goal-kick-inclusive move-set (`_moves.MOVE_TYPE_IDS` = pass, dribble, cross, goalkick, throw_in) and pressure terciles. `V(z,p) = E[xG of the possession's FIRST shot | ball at z under pressure p]`. The xtgk-local builders reuse `xthreat`'s low-level seams and modify NO `xthreat` source -- classic xT stays byte-identical, parity-gated.
  - **silly-kicks ships NO xG model.** `V` is fittable only where a calibrated per-shot xG exists; the column is injected (`xg_column`).
  - **rho** = `GkRetentionModel` (logistic, pure-numpy serve, JSON + SHA256, provider variants); labels come from `retains(actions, *, window_seconds=10.0)`, where a truncated window is NaN -- excluded, never falsely-retained. Features are marts-native (gold `fct_action_values` + `fct_action_context`), NOT tracking frames, and pressure is pinned to `pressure_on_actor__bekkers_pi`. Every bundled variant must clear `ece <= 0.10 AND |reliability_slope - 1| <= 0.25`, CI-certified against its recorded `metrics.json`.
  - **`V_opp`** = `EmpiricalTurnoverValue`: possession-bound by default, with support-gated hierarchical bin-widening (native cell -> coarse block -> global-per-pressure, `min_support=30`) so a one-turnover deep cell is not a noise estimate.
  - **Consumer contract: call `apply_resolved_gk_geometry` BEFORE `compute_xt_gk_v2`, and keep `is_gk_distribution` (or the `gk_geometry_source` stamp) on the frame.** Resolved keeper origins live in `fct_action_context.xt_gk_origin_x/_y`, not raw `bronze.spadl_actions`, and the rule is **OVERRIDE, not coalesce** -- SkillCorner's native goal-kick origin is present-and-wrong (the broadcast ball), so a `fillna` would fix GS and silently miss SkillCorner. The warn-once attestation needs a domain column, so a pre-filtered slice with the flag dropped scores raw origins silently.
  - **`flat_zones` maps a NaN coord to zone `(0,0)` -- a FIT-PATH-only contract.** Every fit seam `dropna`s first; use `finite_coord_mask` at any scoring seam. `compute_xt_gk_v2` NaN-guards non-finite rows across all five outputs (never a fabricated zone) and raises on coordinate incoherence between `actions` and the rho features.
  - **Status: NOT construct-validated.** Out-of-sample on real gold, v2 loses to `raw_completion` on outcome-AUC (GS -0.147, SC -0.027); the deep-zone pressure gate is GO-leaning (a real, decreasing, monotone gradient on both cohorts) but WC2022's absolute effect sits under the pre-registered floor. Reports in `docs/research/xtgk_v2_construct_validity/`.
  - v1 is **FROZEN** and coexists until the lakehouse migrates its `xt_gk*` columns; there are no v2<->v1 imports.
- **GKDV — GK Deterrent Value** (`gkdv/`): PR-3 of the TF-19 cycle (ADR-043; spec `docs/superpowers/specs/2026-07-12-tf19-gkdv-regate-and-v1-design.md`). Counterfactual valuation of keeper POSITIONING: how much does the actual keeper's position change the attacking team's space and threat versus a league-average "ghost" keeper in the same frame state? **Depends on `silly_kicks.tracking` PUBLIC seams ONLY, never the reverse** — `tracking/` must never import `gkdv/` (pinned by `tests/gkdv/test_import_allowlist.py`; the same rule ADR-037 set for `tracking/_model_eval.py`). **Engine** (`_engine.py`): `build_ghost_frames(frames, *, home_team_id, model=, carrier=, params=)` → `(counterfactual_frames, provenance, report)`, PURE (never mutates `frames`); domain = alive ball ∧ in-possession team attacking ∧ ball within `domain_ball_to_goal_m` of the attacked goal ∧ defending-GK row present; the ball carrier is pinned ONCE and shared by the domain filter and the serving seam. **A NaN/missing ghost is dropped-and-COUNTED, never scored as Δ=0** — a zero delta from a missing keeper reads as "no deterrence" and biases keeper aggregates toward the null (`GkdvReport` conserves exactly: `n_frames_scored + Σ drop_reasons == n_frames_in`); a non-finite served ghost RAISES rather than making the keeper vanish. `counterfactual_frames` is the FULL input with only the defending keeper substituted, so consumers MUST restrict to the scored set via `provenance_to_targets` / `provenance["drop_reason"].isna()` before differencing. **Arms** (`_arms.py`), both in ATTACKER-VALUE units as `actual − ghost` so **negative = deterrent** uniformly: `delta_das` (accessible space; direction is pinned ONCE on the FACTUAL frames and the SAME pinned column feeds BOTH legs — accessible-space otherwise infers direction per period from a team-x mean the ghost displacement perturbs, so the two legs could infer OPPOSITE directions and the difference would not be a counterfactual at all; routed through `get_individual_das` summed per team via the narrow `_das_port.py`, since `get_das` hardcodes `infer_attacking_direction=True`) and `delta_threat_suppression` (`compute_threat_pc(actual) − compute_threat_pc(ghost)`). **Asymmetric keeper modelling, by construction:** the threat arm carries `lambda_gk` (a keeper GAIN applied after the influence field, so keeper position enters via TTI) while ΔDAS is **keeper-BLIND** (accessible-space's column map has no `is_goalkeeper`), i.e. ΔDAS measures relocating a GENERIC player. **`method="spearman"` is a HARD API constraint** enforced in `GkdvParams.__post_init__` — a GK-blind pitch-control configuration is *unrepresentable*, not merely discouraged, and the check lives in ONE place (the arms deliberately do not re-check). **Neither arm accepts a `pitch_control_cache`, and that is CORRECTNESS not performance:** `PitchControlCache` keys on frame IDENTITY (`game_id, period_id, frame_id, team, method, params, ball_position, decompose`) and excludes player positions, so a ghost frame — which carries its twin's identity — would be served the factual leg's surface and every delta would collapse to exactly zero with no warning. Ships **no `add_*` aggregator** (C4 action-coupled count unchanged) and is in **no** default xfn list. §6.4 Layers 0–3 and the xS-arm probe (PR-3b) are NOT in this PR. ## Key conventions

- **The package version is single-sourced in `silly_kicks/_version.py` (ADR-079).** `pyproject.toml` `[project]` is `dynamic = ["version"]` with `[tool.hatch.version] path = "silly_kicks/_version.py"`, and `silly_kicks/__init__.py` re-exports it — so the wheel/sdist metadata and the runtime `silly_kicks.__version__` derive from ONE literal and cannot drift. Bump that **one** file for a release; `uv.lock` follows from `uv lock` (never hand-edit it), and the metadata follows from hatchling. A typo in the `[tool.hatch.version] path` fails CI at `pip install -e`, so it can't lie dormant until release. Guarded by `tests/test_version_single_source.py` (catches *reintroduction* of a second source, which deletion alone cannot).
- No pandera — schemas are plain Python dicts (`SPADL_COLUMNS`, `ATOMIC_SPADL_COLUMNS`).
- Config DataFrames (`actiontypes_df()`, etc.) are cached with `@functools.cache`.
- Vectorized dispatch: converters use `np.select` over pre-flattened columns, not `apply(axis=1)`.
- **No rescan-in-loop; use `silly_kicks._frame_index.group_rows` (ADR-068).** A full-table filter inside a per-item loop (`df[df["frame_id"]==fid]`, `df[(df["a"]==x)&(df["b"]==y)]`, or a positional forward scan) is O(n·m) where O(n) is available — the class the 2026-08-24 audit found in 9 sites across `causal`/`tracking`/`spadl`/`scripts` (invisible at test scale, biting only at real-match 0.95–3.2 M rows). Build the grouping ONCE with `group_rows(df, by)` (dtype-safe `groupby().indices` lookup, empty-frame-on-miss, raises on ADR-019 canonicalisation collision) and `.get(key)` per item. The turnover scan (numba-@njit on equality-preserving int codes + pure-Python fallback) and the cover-shadow baseline (setup/core hoist) are the loop-shaped variants of the same fix. All output-preserving (parity test + structural call-count guard per site); **not** a retrain trigger.
- **Item/row-looping primitives carry a sub-quadratic-growth guard (ADR-073).** `call_counter` is scale-INVARIANT (a `calls==1` assertion passes whether the one call is internally O(n) or O(n²)) and benchmarks only MEASURE — so a single-call-internally-O(n²) (the 4.92.0 turnover bug) reaches a lakehouse report, not CI. `tests/_perf_structural.assert_subquadratic_growth(measure_work, *, sizes=(256,1024,4096), max_exponent=1.5)` asserts the empirical operation-count growth EXPONENT stays ≤ 1.5 (deterministic integer counts, small fixtures, every leg — never wall-clock; a quadratic-ish detector, sub-n^1.5 is out of scope). Each adopter supplies a SCOPED counter that isolates the super-linear-suspect op: `rows_scanned_counter` is the rescan proxy (boolean-mask `__getitem__` + `.groupby` + axis-0 `.take`, with a re-entrancy depth guard so `df[mask]`'s internal take is not double-counted); a compiled kernel counts its pure-Python fallback via a counting-array; a constant-work primitive (databricks IN-batch) uses an equality guard. A NEW `group_rows` caller MUST register a guard in `tests/_scale_guarded.SCALE_GUARDED` (meta-assertion enforces the superset of AST-derived callers + degenerate-companion). **A growth fixture MUST scale the GROUP (loop-iteration) dimension, not a within-group one** — a rescan is O(groups×table), so a constant loop count (single game / fixed team set) leaves the regressed rescan LINEAR and the guard passes on the bug (a guard that cannot guard; `assert_subquadratic_growth` passing is necessary, not sufficient — each adopter needs the regression-goes-quadratic proof). Known limit: a new rescan that neither routes through `group_rows` NOR rebuilds a `groupby` in-loop is not force-caught (no reliable AST signal); the AST rescan-lint was considered and DECLINED (ADR-019 lint lesson).
- All `warnings.warn()` calls include `stacklevel=2`.
- ML naming conventions (uppercase `X`, `Y`, `Pscores`) are allowed in `vaep/` and `xthreat/*.py` per ruff per-file-ignores.
- **`detect_input_convention` must require DISCRIMINATING evidence, and DEFER when it has none (ADR-059).** Rule 1 infers `POSSESSION_PERSPECTIVE` from *"every reliable (match, team, period) group attacks high-x"* — but `reliable` is filtered to `n >= min_shots_per_group_medium` (5), so when that filter removes the low-side groups an all-high survivor set is an **artifact of the filter, not a measurement**. Measured wrong on **2 of 36** real Gradient Sports matches, at `confidence="medium"`, against a converter that correctly declares `PER_PERIOD_ABSOLUTE`. Rule 1 now fires only on a configuration an absolute convention could not produce — **two distinct teams reliable in the SAME period**, or **one team reliable across TWO periods** — and otherwise returns `convention=None` with a diagnostic naming why. **Deferral is the safe direction and that asymmetry is the whole argument:** `validate_input_convention` reads `None` as "keep the caller's declared convention", so a false ambiguous leaves output correct and loses only a cross-check, while a false positive contradicts a correct declaration and **raises** under `on_mismatch="raise"`. The second clause **IS** the guard TF-22 added inline to the ABSOLUTE branch in 3.0.1 — both branches now call `_a_team_spans_periods`, ONE spelling; the first clause is deliberately NOT given to that branch, because separating `ABSOLUTE` from `PER_PERIOD` requires observing a team ACROSS periods and a single shared "is this discriminating?" helper would silently loosen TF-22. Rule 1 is what validates statsbomb + skillcorner, so the coverage risk is a SILENT downgrade to ambiguous: `test_statsbomb_raw_detected_as_possession_perspective` guards it on 3 real matches; SkillCorner is guarded by `test_skillcorner_raw_detected_as_possession_perspective` on real public match `1886347` (`PUBLIC_CORPUS` registers TEN redistributable SkillCorner matches — **visibility is keyed PER MATCH, never on the provider name**, which is the inference `scripts/_corpus.py` exists to prevent and which was made anyway while reading that very file). Its fixture deliberately retains a below-threshold group, so it exercises the sparse-drop shape that caused the misfire and still classifies. **The durable rule: "no counter-evidence" is not evidence — when a FILTER precedes a universal claim, ask what the filter removed.**
- **Converter identifier conventions are sacred.** SPADL DataFrame converters never override the caller's `team_id` / `player_id` columns from provider-specific qualifiers. Qualifier-derived facts surface as dedicated output columns (see `tackle_winner_*` / `tackle_loser_*` on sportec). Decision: ADR-001.
- **Converters are ORDER-INSENSITIVE; `action_id` is chronological (ADR-065).** A `convert_to_actions` is a pure function of its chronological event CONTENT — permuting the input row order yields identical output modulo the `action_id` renumber. Each converter sorts at the TOP of its frame via `spadl.base.sort_actions_chronologically(frame, *, by, tiebreak)` **before any positional/`.shift()` derivation** (`by` is parameterized because the sort runs on different frames/keys: SPADL `(game_id, period_id, time_seconds)` for top-of-pipeline sorters; raw keys like opta `(game_id, period_id, minute, second)` where `time_seconds` isn't built yet). - **Artifact-writing drivers REFUSE a dirty tree (4.63.0, `scripts/_provenance.py`).** Any `scripts/` driver that writes a registered artifact calls `require_clean_tree(git_provenance(), allow_dirty=...)` FIRST — before paying for any corpus work — and stamps `run_commit` + `run_tree_dirty` into its output. The reason is measured, not hypothetical: `git rev-parse HEAD` returns the same SHA whether or not the tree is modified, so a driver stamping the bare SHA records a commit that does **not** describe the code that ran. A corpus pass was launched exactly that way (HEAD clean, three drivers modified); the resulting numbers would have carried a verifiable-looking false provenance, which is strictly worse than none. Absent git counts as dirty, never clean. `--allow-dirty` permits a dev run but the artifact still records `dirty: true` — the escape hatch must never launder the fact. **Enforcement belongs in `main()`, not in the work function** (a `run()` that refuses to execute on a dirty checkout cannot be tested without mocking git; the CLI refuses, `run()` records the truth). **CI-gated as of 4.65.0** (`tests/scripts/test_provenance_wiring.py`): the rule was enforced by memory and memory had already failed twice — `validate_xshot_causal.py` wrote the §3.3 entanglement artifact with no provenance at all, and `validate_xs_probe.py` stamped a bare `git rev-parse HEAD` into the cited 4.60.0 result. - **Every corpus driver adopts the shared seam `scripts/_driver.py` -- CI-gated, not prose (ADR-052, 4.72.0).** This rule was prose for two releases and prose was not enough: of 21 in-population drivers, **three** survived a crash and **fourteen** held every result in memory and wrote once at the end. `for_each(items, key=, work=, shard_root=, token_inputs=)` owns the loop -- it STREAMS its corpus (never `list()`s it: `load_matches` parses a full tracking frame per match inside the generator), writes one shard per item into a generation DIRECTORY named by a `ruthless.fingerprint` digest of the DECLARED inputs, skips an item whose shard exists, prints a FLUSHED `[i/n]` line, records failures rather than losing the pass, and asserts conservation over its OWN keys. **An empty result still writes a shard** (absent = "not yet run", present-and-empty = "ran, produced nothing"; conflating them recomputes every barren item forever). The primitives are the escape hatch and a driver on that path must call `assert_conservation` **AND** `_require_injective` -- conservation alone is SATISFIABLE BY A LOSSY RUN, because a colliding key makes two items share one shard and `present` counts it once per duplicate key (measured: 2 items -> 1 processed -> conservation returns `(2,2)` and PASSES). **`reconcile` requires a partition surface**; selectors are deliberately outside `token_inputs` so narrowing reuses shards, which makes the generation a SUPERSET of any one run, so every other adopter combines from `res.keys`. Corpus-scoped counters survive resume via a `<key>.counters.json` sidecar (pass-scoped `n_attempted` deliberately does NOT -- a resumed pass must be able to declare it built nothing); use `CorpusPassResult.manifest()`, since a hand-written `manifest_fields(...)` silently took the old `counters_unrecorded=0` default and reported a complete corpus of nothing. **A driver that changes its SHARD SCHEMA must bump its schema token, and the two must be pinned TOGETHER (4.77.1).** This is the "token completeness" limit below, measured: 4.77.0 renamed a `measure_match` column and added another (the ADR-042 denominator) while leaving `token_inputs["schema"]` at `"sb360-coverage-2"`. The fingerprint digests `token_inputs` only, so the un-bumped token resolved to the SAME generation directory, where **22 stale shards** carrying the old column were waiting -- a re-run would have skipped all 22 as already-done, reported a clean CONSERVED pass, and combined the OLD schema, with the fix silently not taking effect. Nothing in the suite could see it: the driver's own assertion on the renamed column lived in an `e2e` test, which CI does not run, so CI was green on a broken driver. The pattern that fixes it is a declared `_EMITTED_SHARD_COLUMNS` + `_SHARD_SCHEMA_VERSION` pair, gated three ways -- the declaration matches the dict the work function ACTUALLY builds (AST, not a copy of it), `token_inputs["schema"]` references the constant rather than a literal, and the pair itself is pinned -- plus a run-time assertion that fails at the FIRST shard. **Never write `pd.DataFrame(rows, columns=DECLARED)` as the check:** it SELECTS to the declaration, so a dropped key vanishes and a missing one arrives as NaN, and the guard certifies both. Compare the keys the rows actually carry. **What it does NOT prove:** token completeness (a wrong declaration digests stably), and a SECOND uncounted loop -- that writes no shards and lists no keys, so nothing sees it; a fan-in check is the recorded follow-up. Two rules the migrations produced: `for_each` resumes WORK, never the PRODUCTION of its items, so invert onto an id list only where `work` is unambiguously trivial next to the load; and the `work -> tidy frame` contract carries no per-item METADATA (use the documented `counters(item, frame)` closure) and no non-tabular side state at all.

- **Frame-aware `*_xfns` must resolve frames POSITIONALLY, never by `action_id` lookup (ADR-020).** VAEP shifted gamestate slots repeat the boundary action, so `action_id` is NOT unique in an xfns matrix: `set_index("action_id").at[aid]` returns a Series and raises, and provenance merges fan out. `_kernels.resolve_frame_ids_by_position` is the single seam, byte-equivalent to the old `.at` on unique ids. The production `add_*` aggregator path has unique ids and is unaffected, which is precisely why this survived so long -- so the gate is behavioral and auto-enumerates every `*_xfns` (`tests/tracking/test_frame_aware_xfns_dup_action_id.py`). A `.at` grep missed two of the eight defective families; the behavioral gate found all eight.
- **A coverage denominator must never masquerade as a tactical signal (ADR-042).** Mean disruptive run value divides by `n_valued_disruptive_runs`, NEVER `n_disruptive_runs`, or tracking coverage reads as tactics. A runner absent from the linked frame keeps `run_value` NaN and keeps its ROW (`RunValueCoverageWarning`) -- never a fabricated `0`. Same reasoning behind emitting `peak_speed_source` as DATA: the all-NaN-speed fallback under-states peak speed, so sparse providers legitimately LOSE runs and the consumer has to be able to see that.
- **Detection lands BEFORE the fix, and every registry gate carries an anti-rot meta-assertion (ADR-051).** A gate written after its own repair arrives green and is never observed failing, so the mirror gates above were landed RED -- enumerating all 33 aggregators before a single fix existed. Both pin their registry to `tracking.__all__` in BOTH directions, so a new `add_*` must register or CI fails. Corollary to Gate A's blindness (see the ADR-028 bullet): a clean Gate A reading is NOT evidence about identity-keyed direction -- one such reading was withdrawn on exactly that ground.
- **A spec that changes a public seam enumerates every caller of every CHANGED FUNCTION and classifies each as affected or not WITH EVIDENCE ON BOTH SIDES -- and the sweep is the FLOOR, not the check.** Measured on the ADR-051 PR 5 cycle: the sweep took under a minute, returned five call sites, and resolved two questions in OPPOSITE directions (`causal/opportunities.py` affected because it builds causal covariates from the changed extractors; both frozen fixtures unaffected because they are built at `goal_x=0.0`, where the transform is the identity and every delta measured exactly zero). It also MISSED four things, which is why the rule names them. A symbol sweep cannot see (a) **a changed function nobody thought to grep** -- that PR changed FOUR and the sweep covered three, missing the `_dominant_region_area` grid re-anchor entirely, which moved a causal confounder at BOTH goal ends; (b) **wrapper callers** -- `derive_opengoal_range.py` imports `prepare_xshot_training_data`, which wraps the changed extractor, and is itself in `ARTIFACT_DRIVERS`; (c) **committed data artifacts**, which call nothing -- a frozen fixture went stale in `space_controlled` and no sweep could say so; (d) **numbers recorded in prose** rather than in a driver-produced file; (e) **the second hop** -- the sweep returns a module, never the research artifacts downstream of it. So ALSO enumerate: every function in the diff, every committed fixture derived from them, every research artifact downstream of a changed module, and every number recorded outside a driver artifact. Spec `2026-08-03-adr051-closeout-and-artifact-validity-design.md` §7.1.

## Testing

```bash
python -m pytest tests/ -m "not e2e" -v --tb=short
```

e2e tests require dataset fixtures not committed to the repo. Tests with
fixtures committed to the repo should not be marked e2e — they run in
the regular suite.

**Lint at the CI scope, never `.`** — `python -m ruff check silly_kicks/ tests/ scripts/` and
`python -m ruff format --check silly_kicks/ tests/ scripts/`, matching `ci.yml`. `ruff check .`
walks `.venv/` and `calibration_runs/` and reports ~234 vendored errors that are not the repo's,
which is enough noise to hide the real ones. `pyright` runs **bare** (config-driven include), and
neither tool is on PATH — use `python -m`.

CI **duration-shards** the bulk suite across parallel jobs via `pytest-split` (ADR-074)
(`--splits 3 --group ${{ matrix.shard }}`, matrix `os × python × shard[1..3]`), each shard on its
own runner (the `xdist -n auto` memory-kill on the 4-core/7GB runners is why intra-job parallelism
was reverted — sharding gives the parallelism without the shared-memory contention). The split is
balanced by the committed **`.test_durations`**; **without it pytest-split's count-mode split is
NON-DETERMINISTIC (measured: shard sizes drift run-to-run and can under-cover), so `.test_durations`
is committed.** The committed file is **CI-MEASURED** (a local `--store-durations` mis-balances — CI
is ~2× local and per-py-version relative timings differ; measured: a local-durations shard ran 11:26
vs 5:50 on CI, whereas the CI-measured file balances all three primary shards to ~7.3 min). **To
regenerate:** temporarily re-add a `durations-capture` job (full `pytest -m "not e2e"
--store-durations` under the warm numba cache, `include-hidden-files: true` on the upload since
`.test_durations` is a dotfile), download its `test-durations-ci` artifact, commit it, and remove the
job (a permanent ~20-min serial capture would become the wall-clock bottleneck). Regenerate when the
suite shifts materially or a shard drifts toward budget; balance is tuned for the ubuntu primary leg
(others may run hotter — acceptable, the runtime `shard-reconcile` job still proves completeness). `-p no:randomly` pins collection order (a shuffle plugin would break the partition;
`tests/test_ci_shard_wiring.py` bans it). Coverage is proved two ways: the static
`tests/test_ci_shard_wiring.py` (contiguous `1..N`, `--splits == N`, `-p no:randomly`, numba-cache
key covers all `@njit` files) and the runtime `shard-reconcile` job (node-ID `union == full ∧
pairwise-disjoint`, per leg). Benchmark *measurements* run single-threaded in a **standalone**
`benchmark` job (off the shard critical path). Windows is the binding leg (undivided ~1:49 install);
numba (`NUMBA_CACHE_DIR` + `actions/cache`) + pip caching are prioritized there. There are no
wall-clock `assert ms < budget` perf tests — performance regressions are guarded by **deterministic
structural guards** (call-count spies; `tests/_perf_structural.py` + the `*_perf_budget.py` files).

**CI's pandas-major span is DECLARED, not inherited (ADR-057).** The matrix is OS × Python with no
pandas axis, yet it spans both majors: `pyproject.toml` pins `pandas>=2.1.1,!=3.0.4` with **no upper
bound** and pandas 3 requires Python ≥3.11, so pip resolves the newest compatible pandas per
interpreter — measured, `ubuntu-3.10` → **2.3.3** and the other three legs → **3.0.5**. That coverage
was real but ACCIDENTAL, and could have vanished with no diff and no signal (this repo has one
measured instance of that class: DAS going silently all-NaN on pandas 3). It is now asserted by a
PAIR, because a test running in one leg cannot observe another: `tests/test_ci_pandas_span_wired.py`
pins that the **resolved leg set** still straddles the 3.11 boundary — parsing os × python-version
**minus `exclude` plus `include`**, never the axis, since `exclude` is the pruning mechanism already
in use and excluding a leg collapses the span while leaving its version in the axis — and a
`pandas-span` job (`needs: test`) asserts the union of each leg's recorded major covers both. Assert
the SPAN, never specific versions: pinning "3.10 → 2.3.3" fails on every routine bump and trains a
reader to edit the expectation without thinking. **A `.to_numpy()` result you intend to MUTATE needs
`copy=True`** — under pandas 3's copy-on-write it is a READ-ONLY view when no dtype conversion is
required, so `arr[mask] = x` raises `ValueError: assignment destination is read-only`; pandas 2
returned a writable array, which means a full local suite on the 3.10 leg passes and sees nothing
(measured: 48 failures on 3.11, 0 locally, 4.80.0). Sweep this by PREDICATE, not by patching the
line that failed — an AST search for "a `to_numpy()` result later subscript-assigned" finds every
site repo-wide, and there are four. **Never assert a dtype literal across pandas
majors** — assert the behaviour (that `id_compat` comparisons still match), which is what made the
two-cycle-old `snapshot_to_tracking_frames` question finally answerable.

**A TYPING input is pinned; a BEHAVIOURAL input is not (4.80.0).** The lint job exact-pins
`ruff`, `pyright`, `pandas-stubs` **and `numpy`** -- numpy ships inline types, so it decides what
pyright REPORTS exactly as pandas-stubs does, and leaving it floating made the gate's verdict a
function of resolution luck (measured: main resolved 2.5.2 then DOWNGRADED to 2.4.6, so a PR whose
diff could not reach the three offending files went red while main stayed green). **Pin it on the
LAST install that can move it** -- the tools line runs first, but `pip install -e ".[test]"`
re-resolves, so a pin above it is decorative. The TEST matrix stays UNPINNED on purpose: there,
floating numpy/pandas is ADR-057's span and is what catches real breakage. Both halves are pinned
by `tests/test_ci_lint_pins_wired.py`, including the asymmetry, so "tidying" the jobs into
consistency fails CI rather than silently deleting the coverage.

**The BUILD BACKEND is bounded and the PUBLISHER's validator is pinned — the pair, or neither works
(4.79.0).** Same shape as the span above, and it bit within hours of that ADR landing: every Action
in `.github/workflows/` is SHA-pinned while `[build-system] requires` was `["hatchling"]` with **no
upper bound**, so the artifact's `Metadata-Version` was a function of WALL-CLOCK TIME. hatchling
1.32.0 (2026-08-11 05:03Z) moved 2.4 → 2.5; `v4.78.0` built at 01:39Z and published, `v4.79.0` built
at 12:56Z and was REFUSED by the publisher's pinned `packaging==25.0`, whose valid set stops at 2.4
— **green build, green CI, failed upload, no diff between the two runs.** Fix BOTH sides and bump
FORWARD (`gh-action-pypi-publish` v1.14.2 = `packaging==26.2` + `twine==7.0.0`): metadata 2.5 is
legitimate, and pinning the backend below it only defers the failure. Bounded (`>=1.27,<2`), never
pinned — the point is that a backend release lands in a DIFF instead of in a failed publish.
`tests/test_ci_publish_guard_wired.py` rejects any unbounded `[build-system]` requirement; because a
bound-checker passes vacuously if its predicate says yes to everything, a companion test pins that
the predicate rejects the exact `"hatchling"` string that broke this release. **The durable rule: a
pinned consumer and a floating producer are one dependency, and pinning only the half you control is
not a pin.** Corollary for diagnosis: I first argued v1.14.2 wouldn't help because its RELEASE DATE
predates hatchling 1.32.0 — the wrong lens entirely; what decides it is the validator version the
action pins, which is readable in seconds from `requirements/runtime.txt` at that tag.

**Doctests: CI executes `--doctest-modules` on the PUBLIC surface only** (`pytest --doctest-modules
silly_kicks/ --ignore-glob="*/_[!_]*.py"`, every leg; PR-S124, wiring guarded by
`tests/test_ci_doctest_wired.py`). The glob skips single-underscore
private modules while KEEPING dunder `__init__.py`; private-module examples are kept CORRECT (the
whole-package sweep is clean) but are NOT executed in CI, to bound wall-clock — the initial
enforcement scope. Most public examples are the canonical indented RST **literal block** (the honest
form for anything needing a real match's `actions`/`frames`/`xt` — no docstring can conjure them);
`tests/test_public_api_examples.py::_has_real_example` accepts a ≥4-space-indented non-`>>>` line in
the Examples section as a REAL example, so converting a failing `>>> f(actions, ...)` doctest to a
literal block satisfies BOTH the doctest run (nothing to execute) and the Examples gate. Genuinely
self-contained examples stay executable `>>>` doctests. Do NOT reintroduce `>>> f(x)  # doctest: +SKIP`
filler — the gate's `_demonstrates_something` rejects it (the 4.53.0 tightening).

**`@pytest.mark.slow` = expensive AND platform/interpreter-INVARIANT** (does-it-run train-script
smokes, same-run internal-consistency/parity, calibration cache-equivalence). These run **once on the
CI primary leg (`ubuntu-3.12`, matrix `primary: true`)**; every other leg runs `-m "not e2e and not
slow"`. Do **NOT** mark version-sensitive tests `slow` (golden-hash / snapshot / absolute-numeric — e.g.
`test_golden_*`) — they must stay on all legs (OS + interpreter axes), as must cheap behavioral-contract
guards (dup-`action_id`, id-dtype-invariance, orientation/roster). The matrix partition is guarded by
`tests/test_ci_slow_gating_wired.py`. Decision: ADR-023.

**Claims about a gate's behaviour must quote the assertion body, not its registration.**
A gate's registry (`ENTRIES`, `PURITY_ENTRIES`, `AGGREGATORS`, `_PUBLIC_MODULE_FILES`,
`_EXHAUSTIVE_EMITTED`) tells you *whether* a helper is exercised — never *what is asserted
about it*. Two PR-S119 review errors came from this, one on each side: a reviewer read the
liveness gate's registration and concluded a partially-`pd.NA` column would fail, when
`tests/tracking/test_aggregator_column_liveness.py:416` asserts only
`not out[c].notna().any()` (100%-null), and `:448`'s non-constant check is
float-dtype-gated so non-numeric columns are exempt entirely; and a plan asserted the
synthetic reachability grid was exactly y-symmetric and that symmetrizing it would cost
"≤ 1 ulp", when neither had been run (measured: 4.44e-16 across 3752/6400 cells). Same
failure mode both times — adjacent evidence substituted for the executed thing. **Rule: any
claim that a test passes or fails, or that a numeric property holds, carries either the
quoted assertion body or a pasted measurement.** Registration proves coverage; only the
assertion proves behaviour. Corollary for tolerances: measure at the scale you assert at —
grid-level float noise does not transfer to a derived area (a 3.3e-16 relative grid
asymmetry is not a 1e-12 absolute bound on an m² quantity).
