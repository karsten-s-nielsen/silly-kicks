# silly-kicks

Maintained fork of socceraction — SPADL event conversion + VAEP action valuation for soccer analytics.

## Architecture

- **Hexagonal**: All core functions are pure (pandas in, pandas out). Zero I/O, zero global state mutation.
- **Converters** (`spadl/`): Each provider (StatsBomb, Opta, Wyscout, Sportec, Metrica, Gradient Sports, SkillCorner, plus the Kloppy gateway) has its own module. All return `tuple[pd.DataFrame, ConversionReport]` with guaranteed columns/dtypes via `_finalize_output()`. **Gradient Sports goal-capture (4.13.0, ADR-018):** own goals = `RE`+`shotOutcomeType=="G"` → `bad_touch`+`owngoal` (conceding team/rebounder kept; post-LTR own-half geometry tripwire warns+reverts a mis-located one); cross-goals = `CR`+`G` → keep the cross + synthesize a `shot`/`shot_freekick`+`success` by the crosser (foul-synth 0.5-offset pattern); synthesized rows (cross-goal shot + foul) carry `is_synthetic=True` (new GS schema column) since they share the parent's `original_event_id`; voided `possessionEvents.nonEvent==True` events are excluded (optional column — absent → observable no-op warn, tallied in `excluded_counts`). `"O"` shot-outcome is off-target → `fail` (4.12.2, not own-goal). Empirically grounded in the full WC2022 catalog; owner-gated e2e in `tests/spadl/test_gradientsports_scoreline_e2e.py`. **GS null-actor team attribution (4.25.0, ADR-027):** the null-actor duel/foul events (594 `OTB`+`CH` + 28 `FOUL`+`FO` on the canonical WC2022 feed — both `gameEvents.teamId` AND `playerId` NULL; a CH is a two-sided 50/50 duel) carry NaN `team_id`/`player_id` (GS schema ids are now nullable `Int64`, NOT the `SPADL_COLUMNS` `int64`), NEVER a sentinel `0` (non-NaN → bypassed `pd.isna` routing → crashed the lakehouse opponent guard `_resolve_opponent_team_id`). ADR-001 forbids back-filling from duel/foul qualifiers; an ADR-001-legal canonical-player self-heal (`_resolve_team_ids`) fills team ONLY from a real same-match `player_id` (ambiguity raises). `convert_to_atomic` now preserves source id dtype (was force-casting to atomic `int64` — latent crash for GS NaN AND kloppy-family object strings). VAEP/tracking-retrain trigger. **Provider data-quality fixes (4.20.1):** (1) **SkillCorner `time_seconds` is period-relative** — `_parse_time_start` parsed the continuous broadcast clock; `_to_period_relative` now subtracts period-start offsets `{1:0,2:2700,3:5400,4:6300,5:7200}` (2nd-half events were ~2700–5800s vs period-relative frames → linkage collapse; ADR-017). (2) **SkillCorner goalkick result** no longer hard-wired `success` → routed through `same_team_next`. (3) **sportec pass/set-piece result from native DFL `play_evaluation`** — it previously marked ALL passes/set-pieces/goalkicks success, ignoring the parsed `play_evaluation`; the punt-synth goalkick inherits its parent Play's eval. **4.21.3 generalized this to a kloppy-aligned success-ALLOWLIST** (`silly_kicks/spadl/sportec.py` `_extract_play_eval`/`_play_evaluation_is_fail`/`_warn_unexpected_play_eval`, single-sourced across the main + synth sites): `fail` iff the Evaluation is non-empty AND ∉ `{successfullyCompleted, successful}`, so unseen reason-coded failures (`unsuccessfulBecauseOfFoul`) fail by construction; empty/absent/NULL → success (no mass-fail on a missing column); unexpected tokens warn. Byte-identical on the 7 IDSSE matches (only non-success token is `unsuccessful`; owner-gated bronze e2e `tests/spadl/test_sportec_playeval_e2e.py`). Hyrum: a DFL stream with failure tokens beyond `unsuccessful` shifts its fail distribution. (4) **metrica left unchanged** (measured-correct: PASS = completed pass, loss = separate `BALL LOST` event). (5) **Frame-orientation `home_team_id` dtype bug (ADR-019)** — `gradientsports.py`/`sportec.py` tracking adapters set `team_attacking_direction` via a raw `team_id == home_team_id` that silently matched ZERO players for an int `home_team_id` vs object-string `team_id` → mislabeled → `play_left_to_right` double-flip → mis-oriented frames (the `structural_sgm` away-blow-up ROOT CAUSE + latent corruption of every frame-linked tracking feature on dtype-mismatch); both now use `ids_match` + **fail loud** on zero-match (kloppy gateway unaffected — derives home_team_id internally as string). SkillCorner + sportec + orientation changes are **VAEP/tracking-retrain triggers**. DFL goalkicks ~71% complete (not 100%). **Restart-coordinate enrichment (4.22.0, ADR-025):** post-conversion `spadl.add_restart_coordinates(actions, *, frames=None, links=None)` imputes NaN restart coords for Law-fixed-spot types (goalkick/penalty/corner/throw-in) as NEW provenance-tagged columns (`enriched_start_x/_y`/`enriched_end_x/_y` + `start_coord_source`/`end_coord_source` ∈ `{native, tracking_ball, tracking_gk, restart_prior, next_event, unresolved, tripwire_reverted}` + `start_coord_confidence`/`end_coord_confidence`), NEVER mutating canonical `start_x/end_x` (Phase 1, additive — **no retrain**; canonical promotion is deferred Phase 2). Single engine `tracking.resolve_restart_geometry` (`impute_types` gate); `tracking.resolve_gk_geometry` is now a byte-identical shim over it (`impute_types=(goalkick,)`, golden-snapshot-gated → xT-GK/completion unchanged). Geometry tripwire (ADR-018-style) lives at the `add_restart_coordinates` EDGE (engine is pure); reverts an imputed-out-of-region origin → `tripwire_reverted` (warns), native out-of-region warns only. `tracking.RestartCoordinateReport` aggregate QA. NaN coords are a GS set-piece phenomenon (StatsBomb/Wyscout/SkillCorner 0%; live-probe-grounded). C4-free (spadl helper, not a tracking aggregator — count stays 27).

## Key conventions

- No pandera — schemas are plain Python dicts (`SPADL_COLUMNS`, `ATOMIC_SPADL_COLUMNS`).
- Config DataFrames (`actiontypes_df()`, etc.) are cached with `@functools.cache`.
- Vectorized dispatch: converters use `np.select` over pre-flattened columns, not `apply(axis=1)`.
- All `warnings.warn()` calls include `stacklevel=2`.
- ML naming conventions (uppercase `X`, `Y`, `Pscores`) are allowed in `vaep/` and `xthreat/*.py` per ruff per-file-ignores.
- **Converter identifier conventions are sacred.** SPADL DataFrame converters never override the caller's `team_id` / `player_id` columns from provider-specific qualifiers. Qualifier-derived facts surface as dedicated output columns (see `tackle_winner_*` / `tackle_loser_*` on sportec). Decision: ADR-001.
- **Public enrichment helpers (post-conversion `add_*` family) tolerate NaN in caller-supplied identifier columns.** NaN identifiers route to the documented per-row default (typically NaN-output / False / 0); helpers never crash on NaN input. Decoration with `@nan_safe_enrichment` from `silly_kicks._nan_safety` is the formal opt-in; the CI gate at `tests/test_enrichment_nan_safety.py` auto-discovers decorated helpers. Decision: ADR-003.
- **Academic attribution discipline.** Every new feature implementing a published methodology gets an entry in the `NOTICE` file's "Mathematical / Methodological References" section. Cross-link from per-feature docstrings via `See NOTICE for full bibliographic citations.` Mirrors the lakehouse pattern. Decision: ADR-005.
- **Aggregator column liveness is CI-gated (non-NaN AND non-constant).** Every registered `tracking` `add_*` (the full `__all__` surface, jersey helper included) must produce non-null values for every column it ADDS, and every float METRIC column with ≥2 observed values must carry >1 distinct value, on the multi-domain fixture in `tests/tracking/test_aggregator_column_liveness.py` (5 action windows: pass / shot / GK goalkick / attacking-third / wide-area; actor carries the ball through a final-step kick; per-window velocity/layout/GK/kick variation; event clocks jittered off the frame grid). A meta-assertion pins the gate surface to `tracking.__all__`, so a NEW `add_*` must wire a liveness entry or CI fails. Constants BY DESIGN go in the `STRUCTURAL_CONSTANTS` registry with a justification + dedicated invariant test (current entry: `pitch_control_at_ball__spearman` near-ball PPCF degeneracy; the space-creation structural zeros were instead RETIRED from the contract, 4.24.0) — never silent exclusions. Born from the TF-41 hard-coded-NaN `_opponent` defect (ADR-026; non-constant added 4.24.0 after `space_destroyed_m2 ≡ 0` showed non-NaN alone is insufficient).
- **Linkage-provenance columns are idempotent.** All tracking `add_*` aggregators that merge provenance columns (`frame_id`, `time_offset_seconds`, `link_quality_score`, `n_candidate_frames`) must skip the merge when those columns already exist on the input DataFrame. This allows callers to chain multiple `add_*` calls without producing `_x`/`_y` suffixed duplicates. Pattern: `if not any(c in out.columns for c in provenance_cols):`. CI gate: `tests/tracking/test_provenance_skip_guard.py`.
- **Pre-linking optimization via `links` kwarg.** All tracking `add_*` aggregators accept an optional `links: pd.DataFrame | None = None` kwarg. When provided, the function skips its internal `link_actions_to_frames` call and uses the caller-supplied pointers. Pipeline callers (e.g. lakehouse) pre-link once and pass `links` to all enrichment steps, reducing N × 2-5s to 1 × 2-5s per match. The `links` DataFrame must be the pointers output of `link_actions_to_frames` (columns: `action_id`, `frame_id`, `time_offset_seconds`, `n_candidate_frames`, `link_quality_score`). Internal helpers (`_resolve_action_frame_context`, kernel functions) also accept `links` for full thread-through. `infer_ball_carrier` additionally accepts `pre` (a precomputed `_pre_index_frames(frames)`) and `ball_carrier_at_action` accepts both `pre` and `links`; the pre-index dominates carrier cost (~99%) yet is param-invariant, so the TF-24 Stage-1 calibration objective caches `pre`+`links` per match (invariant-prepare) and re-runs only the carrier kernel per Optuna trial (~100× faster sweep; bit-identical).
- **Shared pitch-control surface via `pitch_control_cache` kwarg.** All pitch-control-consuming aggregators (`add_obso`, `add_cover_shadows`, `add_gk_influence`, `add_player_influence`, `add_space_creation`, `add_pitch_control`) accept an optional `pitch_control_cache: PitchControlCache | None = None` kwarg (mirrors `links`). `PitchControlCache` (in `tracking/pitch_control/`) memoizes **canonical** per-frame surfaces keyed on `(game_id, period_id, frame_id, team, method, params, ball_position, decompose)`, so families that need pitch control on overlapping frames compute each surface once instead of once per family. Each aggregator uses a fresh local cache by default (within-pass reuse); pipeline callers pre-build one cache and pass it to all steps for cross-family reuse (like `links`). Only canonical-frame surfaces are cached — **counterfactual** (player-removed) surfaces in `cover_shadows`/`space_creation` are never routed through the cache. Zero global state. Decision: ADR-008 (TF-7).
- **Dtype-safe id comparisons at tracking-feature seams (ADR-019, 4.15.0).** Tracking consumers NEVER compare SPADL-action ids vs frame ids (or `home_team_id`) with raw `==`/`!=`, and NEVER merge action↔frame on id keys without alignment — those silently mis-resolve across dtypes (`Int64(366) == "366"` → False) or raise on a mixed merge key. Route through `silly_kicks.tracking._id_compat`: `ids_equal`/`ids_differ` (column-vs-column, NA-safe both-present), `ids_match` (Series/array vs scalar), `same_id` (scalar↔scalar groupby loops), `align_join_keys` (pre-merge, numeric-vs-object only). One `_canonical` truth (integral-float collapse; genuine strings pass through), same-kind/both-object fast path (zero overhead matched pipelines). Opt-in loud guard: public `validate_id_dtypes` + `IdDtypeDiagnosis` (mirrors ADR-017's `validate_time_base`). CI gates: red-first **asymmetric** dtype-invariance gate over every registered `add_*` (numeric actions × string frames + reverse, `home_team_id` independent axis) + meta-assertion (gate surface == registered surface) + boundary-focused AST lint (`tests/tracking/test_id_compat_lint.py`; 4.21.1 amendment extends it to the converter-adapter `convert_to_frames` orientation seam — `gradientsports`/`sportec` use `ids_match`, `kloppy` routed through `same_id`, so **only `_id_compat.py` is exempt**; `ALLOW_MODULES == {_id_compat.py}` pinned) + structural de-dup perf guard. Fixed three latent bugs (object-`is_ball` `~`-no-op ball-as-opponent; `str(5.0)` iterrows-upcast player-influence/cover-shadow mislabel; object-path opponent join-miss) → **VAEP retrain trigger**. ADR-001 preserved (fix lives at consumer seams, not converters). **4.25.0 (ADR-027): the AST lint is a NAME-heuristic** — it missed a raw `t != action_team` in `_line_breaking.py` ward (a NaN-team crash + an Int64-vs-string silent opponent miscompute on GS) because the operands are not named `*_id`; the behavioral NaN-safety gate (`tests/test_enrichment_nan_safety.py`, NaN-team fixture) caught it. Fixed via `same_id` + a `pd.isna` NaN-route. The behavioral gate, not the lint, is the backstop.
- **Per-action geometry is emitted in the SPADL action-LTR frame (ADR-028, 4.26.0).** Actions are per-acting-team LTR (acting team attacks x=105); `convert_to_frames` is home-attacks-right (home attacks x=105 every period). They are a 180° point reflection apart for **away-team actions**, and the geometry layer historically sampled frame positions WITHOUT re-projecting → ~50% of tracking action rows wrong: visibly-bimodal absolute positions (`pre_shot_gk_x`, `defensive_line_x`, `team_shape_centroid_*`) AND silently-wrong mixed-frame scalars (`nearest_defender_distance`, `receiver_zone_density`, `defenders_in_triangle_to_goal`, all `pressure_on_actor__*`, `pre_shot_gk_distance_to_shot`/`_angle_*` — action anchor combined with frame positions). One frame serves BOTH teams' actions, so the caller cannot pre-orient; re-projection is per-action + library-owned. Fixed by ONE helper `tracking/_action_orientation.py` (`acting_team_attacks_rtl` keyed on the frame's `team_attacking_direction`, `align_join_keys` for the id join; `reproject_to_action_ltr`) at THREE seams: the shared `_resolve_action_frame_context` (fixes all 8 context kernels at once + makes their hardcoded goal-at-(105,34) correct), `_kernels._defensive_line_at_actions`, and `add_team_shape`/`_team_shape_at_actions`. `add_ghost_gk` emits action-LTR (`x→105−gr_x` uniform; `y→68−gr_y` away only) — model stays goal-relative; `compute_team_shape` made **orientation-aware** (deepest line nearest the defended goal; ltr/home byte-identical, only rtl/away changes). Self-reconciling features (`structural_pass`/`gk_influence`/`player_influence`/`cover_shadows`/`shape_graph`/`obso`/`space_creation`/`das`/`pitch_control`/`pausa`/`xt_gk`) DON'T use the context and are untouched (no double-flip). Durable guard: `tests/tracking/test_action_ltr_mirror_invariance.py` (same physical situation → identical action-LTR output under a frame mirror). **VAEP/tracking-retrain trigger** (away-team values change; home-team byte-identical). C4-free (no new aggregator/backend/model). Atomic mirror inherits.
- **Frame-LTR orientation is single-sourced for consumer-built frames (ADR-029, 4.27.0).** ADR-028's per-action re-projection only works on frames already in the canonical **home-attacks-right** convention; it no-ops on absolute frames (`team_attacking_direction` all-null) — filtering to `.notna()` rows yields an empty direction lookup → no flip → ~50% mirror-wrong geometry. Providers converted via `convert_to_frames(output_convention="ltr")` (sportec/GS) or the kloppy gateway (metrica/skillcorner) are already oriented, but a consumer holding **bronze DataFrames** (not a kloppy `TrackingDataset`) builds frames itself and must orient them. Public `tracking.orient_frames_to_ltr(frames, *, home_team_id, home_team_start_left, home_team_start_left_extratime=None)` is the **unlabeled-input** sibling of `play_left_to_right` (which serves already-labeled frames): pure composition of `compute_attacking_direction` (private) + `play_left_to_right` with fail-loud guards (missing-schema; already-labeled → raise + route to `play_left_to_right`; zero home-match (ADR-019); ET-without-flag). Two entry points by input state — labeled → `play_left_to_right`, unlabeled → `orient_frames_to_ltr`. **Consumer contract:** any consumer building frames from a non-kloppy source MUST orient before the geometry layer; the helper is only as correct as the caller-derived `home_team_start_left` (validate per game — e.g. defending GK lands near the attacked goal post-orient). Additive — no provider behaviour change, no silly-kicks retrain; the lakehouse re-materializes metrica/skillcorner after adopting it. The sportec/GS adapters are NOT refactored through the helper (primitives already shared; Chesterton's Fence). Positive ET orientation is regression-guarded on both the helper and the native adapters (`tests/tracking/test_adapter_extra_time_orientation.py`), prompted by a live GS-ET flip that was a consumer-side `home_team_start_left_extratime` placeholder bug, not a silly-kicks bug.
- **The kloppy TRACKING gateway pins the canonical SPADL coordinate system (ADR-031, 4.29.0).** `tracking/kloppy.py` previously emitted frames **y-mirrored** vs SPADL actions (`action_y == 68 − frame_y`) for SkillCorner / Metrica / IDSSE-dev: the EVENT gateway (`spadl/kloppy.py`) pinned `_SoccerActionCoordinateSystem` (now extracted to the shared `spadl/_kloppy_coordinates.py` + `socceraction_coordinate_system` helper, imported by both gateways), the tracking gateway never did, so frames kept each provider's kloppy-native vertical. Single-axis y mirror (NOT orientation — orthogonal to ADR-028/029; error `|68−2y|` → 0 at centre, ~full width at touchlines, which hid it). Fix: `convert_to_frames` pins the CS via a **CS-only `transform()` signature** — dropping `to_pitch_dimensions`, which otherwise silently OVERRIDES the CS vertical and leaves y inverted (Gate 0); the CS carries its own standardized 0–105/0–68 dims, so x is byte-identical. **NOT** a blanket `y=68−y` flip (which would double-invert an already-canonical provider; no-op-on-canonical guarded). DGX-verified: SkillCorner + Metrica both inverted → fixed (**calibration retrain trigger** — but the lakehouse builds SC/Metrica via its OWN bronze builders, so PR-S94 fixes the calibration/pining path + external gateway consumers, NOT lakehouse prod); the **native** sportec/IDSSE path is y-CORRECT (Gate D — no fix, no retrain). First of a sequence (PR-S94 / T1); the IDSSE/Sportec DFL **parse-port** single-sourcing (T3, PR-S95) + the lakehouse's own SC/Metrica builder y-check follow. C4-free (no new aggregator; count stays 28).

## Testing

```bash
python -m pytest tests/ -m "not e2e" -v --tb=short
```

e2e tests require dataset fixtures not committed to the repo. Tests with
fixtures committed to the repo should not be marked e2e — they run in
the regular suite.

CI runs a bulk suite step serial (`--benchmark-skip`) on every matrix leg and a benchmark
*measurements* step single-threaded (`--benchmark-only`) on the primary leg only (see the
slow-test-gating note below for the per-leg split). There are no wall-clock
`assert ms < budget` perf tests — performance regressions are guarded by
**deterministic structural guards** (call-count spies on each function's dominant
primitive; see `tests/_perf_structural.py` + the `*_perf_budget.py` files), which
never flake on shared runners. (An xdist parallelization was tried and reverted: it
regressed py3.12 on the 4-core/7GB CI runners — memory/JIT pressure.)

**`@pytest.mark.slow` = expensive AND platform/interpreter-INVARIANT** (does-it-run train-script
smokes, same-run internal-consistency/parity, calibration cache-equivalence). These run **once on the
CI primary leg (`ubuntu-3.12`, matrix `primary: true`)**; every other leg runs `-m "not e2e and not
slow"`. Do **NOT** mark version-sensitive tests `slow` (golden-hash / snapshot / absolute-numeric — e.g.
`test_golden_*`) — they must stay on all legs (OS + interpreter axes), as must cheap behavioral-contract
guards (dup-`action_id`, id-dtype-invariance, orientation/roster). The matrix partition is guarded by
`tests/test_ci_slow_gating_wired.py`. Decision: ADR-023.
