# Trained-artifact serialization, chirality & publishing

> On-demand class-2 context (ADR-102-style store). The current terse RULES live in `AGENTS.md`; this file holds the WHY / history / measurement. See the spec `docs/superpowers/specs/2026-09-24-agents-md-restructure-design.md`.

- **Trained artifacts are parameters-only, pickle-free, and fail-closed on load (ADR-011, ADR-016, ADR-040, ADR-044, ADR-050).** Every bundled model (`GhostGkModel`, `XShotOccurrenceModel`, `XCrossAttemptModel`, `GkCompletionModel`, `GkRetentionModel`) serializes as npz or booster-JSON plus JSON metadata plus `SHA256SUMS` -- never pickle -- and inference never imports sklearn. Distributed ghost artifacts carry **no training data** (`stores_training_data:false`), so `predict_density` and `ghost_gk_density_spread` exist only on a locally `fit()` model. `load()` enforces two independent guards. **Chirality** (`_chirality.verify_chirality`) re-runs the model's own outputs on `canonical_probe_frame` and raises both on a MISMATCH and on a MISSING fingerprint -- every pre-enforcement artifact is the mis-served class -- with `legacy_override=True` as a warning escape hatch. The **feature contract** (`_feature_contract`) records the feature vector an extractor produces on a fixed probe plus the geometry constants it consumes: a missing contract WARNS (pre-contract artifacts are undeclared, not known-bad), a probe change warns and skips only the fingerprint comparison, and a fingerprint or declared-constant mismatch RAISES with that model's own `IntegrityError`. **Declared constants compare FIRST and ALWAYS**, including when the probe changed, because a sub-probe-resolution change moves no feature and only the declared constant catches it. Tolerance is chosen, not inherited (`atol=1e-6`, `rtol=0`); `equal_nan=True` is load-bearing, since `np.allclose(v, v)` is False for any NaN-bearing vector; and a declared constant MUST be load-bearing on the probe, or the guard fires when nothing changed and `legacy_override` becomes reflex. `load_xgb_booster_base_score_safe` strips the bracketed `"[X]"` `base_score` that xgboost 3.x writes and 2.x silently drops to the `0.5` default.

- **Every model publish goes through ONE card-required seam `scripts/_hub_publish.publish_model_with_card` (ADR-088).** All `publish_*.py` scripts (`ghost_gk`/`ghost_outfield`/`xshot_occurrence`/`xcross_attempt`) delegate to it — a **new publisher MUST use it, never `upload_model_only` directly**. It (a) **requires `--model-card`** and refuses a card-less publish BEFORE any network, (b) `create_repo(exist_ok=True)`, (c) stages the allowlisted model files **plus the card as `README.md`** into a temp dir, then model-only-uploads (the ADR-072 leak allowlist, which now includes `model.npz` for ghost-outfield alongside `model.json`/`rfcde_weights.npz`). Born from the recurring incomplete-publish class: the card was a forgettable manual "copy to README.md" step (dropped in TF-60 PR3, nearly again in PR5) and ghost-outfield's `model.npz` was un-allowlisted so the weights would upload as NOTHING. A card-less / weightless / missing-repo publish is now unrepresentable; the upload path is unit-tested with a fake `HfApi` (`tests/scripts/test_hub_publish_guard.py`). Scripts-only — not in the wheel (`packages = ["silly_kicks"]`).

- **The ghost-GK leaf traversal is numba-accelerated, BIT-IDENTICALLY, with a numpy fallback (ADR-076).** The boosted-tree leaf walk is a shared hot loop: `_vectorized_leaf_values` backs `predict_mean` (production serving), `_vectorized_leaf_indices` backs the KDE query leaf-match (`predict_density`) AND `fit()`'s training leaf-match. Hexagonal: `_vectorized_leaf_*` are the numpy PORT (reference + fallback), two serial `@njit` kernels in `tracking/_ghost_gk_numba.py` (`_leaf_values_numba` / `_leaf_indices_numba`) are the ADAPTER, and a `_FlatTrees` value object (per-tree **LOCAL** left/right + offsets + six field arrays) is passed EXPLICITLY. numba is auto-used when the `[numba]` extra is installed, numpy otherwise; `SILLY_KICKS_GHOST_FORCE_NUMPY=1` forces the numpy path (both-adapters coverage on every CI leg). Measured 11.8× on `predict_mean`, `np.array_equal` (max |Δ| 0.000e+00) — so every golden/chirality/feature-contract test passes unchanged: **no retrain, no re-materialize, no artifact change, C4-free.** Four contracts that MUST NOT re-break: (1) `_flat_trees`/`_flat_trees_y` are **derived state — never serialized**, rebuilt from `_tree_nodes` at `fit`/`load`. (2) `_FlatTrees.left`/`right` stay per-tree **LOCAL** (the kernel walks `cur = left[base+cur]`; remapping to global would double-add `base`), and `_leaf_indices_numba` returns the **LOCAL `cur`** matching numpy's `current` (a global `base+cur` would break the `np.array_equal` gate). (3) The convergence-guard fidelity is **ASYMMETRIC**: `_vectorized_leaf_values`/`_leaf_values_numba` RAISE on a >depth-cap tree (they read `value`=garbage), `_vectorized_leaf_indices`/`_leaf_indices_numba` do NOT (they never read `value`; return the non-converged LOCAL index) — a guard on the indices kernel would itself break bit-identity. (4) The numba leaf import is **LAZY** (bound as module attributes on first use, never at module load) so a bare `import _ghost_gk` stays numba-free — pinned by `test_ghost_gk_does_not_eagerly_import_numba`, mirroring the KDE `cpu-numba` path. `predict_density`'s default `kde_backend` is **`"auto"`** = `cpu-numba` if numba else `vectorized` — the fastest **EXACT** backend (≤1e-9 of vectorized; the KDE golden already runs cpu-numba); **`fft`/`fft-cic` stay an explicit opt-in** (approximate on the raw grid — the default stays exact). A raw-grid exactness consumer pins `kde_backend="vectorized"`. Decision: ADR-076.

- **Velocity-keyed model auto-select serves POSITION-ONLY variants on freeze-frames (ADR-067).** `XShotOccurrenceModel`/`XCrossAttemptModel`/`GhostGkModel` ship `position_only` variants (velocity features DROPPED, not NaN-filled — the feature contract raises on non-finite) auto-selected at the serve seam by the DECLARED velocity marker, mirroring `variant_key_for_provider`: `variant_key_for_velocity(frames)` (pure Layer A, in `_velocity_availability.py`) + a per-model `_resolve_*_model_for_frames` `(model, key)` resolver (Layer B). **The missing-`position_only` fallback goes to NaN, NEVER to `default`** (the default velocity model is invalid on velocity-less frames — the load-bearing asymmetry with the completion template). A **mixed-availability** frame set RAISES (`velocity_availability_is_mixed`; the all-rows `velocity_unavailable_by_design` is False on a partial set, which would otherwise fabricate `speed=NaN` on the marked rows). The ADR-054 undeclared-missing raise STAYS in `compute_*`, not the resolver. **`feature_set` is `Literal["faithful","extended","position_only"]`** (`"extended"` reservation KEPT — Chesterton's Fence); ghost, which had no `feature_set`, gains one (incl. save/load serialization) + a single-frame-capable extractor path (it skips the `prev_state` cross-frame derivatives). Load-guard blocks are threaded by `feature_set` (`_chirality_block` reads `model.feature_set`; `_feature_contract_block` takes a `feature_set` param). **Provenance is a CLOSED set `{default, position_only, custom}`** on the `add_*` path (`xshot_occurrence_variant`/`xcross_attempt_variant`/`ghost_gk_variant`; the `das_source` stamped-column shape, NOT the OPEN `xt_gk_completion_variant`); `compute_*` output stays byte-identical (add_* RE-RESOLVES the key) so velocity-bearing direct callers + the numeric `*_xfns` path are unchanged. `add_ghost_gk`'s measured `ghost_gk_x=52.5` fabrication fence is preserved by disabling its precompute short-circuit on DECLARED frames (never trust a pre-computed ghost that bypassed the seam), NOT by the old NaN short-circuit; its `ghost_gk_source` gains a `velocity_unavailable` branch for the declared-unbundled degrade. Trainers gain `--feature-set position_only` (threaded to prepare + the model + the `for_each` shard-generation TOKEN — feature_set changes the X columns, the 4.77.1 stale-shard trap). **Retrain/Hyrum trigger: SB360 xShot/xCross/ghost NaN → value once variants bundled; velocity-bearing byte-identical; gkdv's ghost arm begins working on SB360.** Decision: ADR-067.

- **Detection-aware provider visibility is a usability contract enforced at TWO layers around ONE shared rule in the neutral `tracking/_provider_visibility.py` (ADR-069).** A detection-aware provider (`_DETECTION_AWARE_PROVIDERS={"skillcorner"}`) whose per-player `visibility` flag was discarded (the kloppy gateway hard-codes `visibility=None`; the native `tracking.skillcorner` builder preserves it) must fail LOUD — never train ghost-GK on the interpolator (~80% of SkillCorner keeper positions are extrapolated). The taxonomy + `validate_provider` + `assert_detection_aware_visibility` (RAISES iff detection-aware ∧ `visibility.isna().all()`; empty raises too — NO `len()` guard, matching the original) live in `_provider_visibility`, **moved OUT of `_ghost_gk` under the 4.53.0 `_id_compat` clean-break precedent** (a rule multiple consumers must obey does not belong inside one consumer's private module; the taxonomy is provider-DATA, not ghost-model). `_ghost_gk` references them via a **MODULE ALIAS (`_pv.*`), never `from ._provider_visibility import ...`** — a bare import re-exports `validate_provider`/`_FULLY_OBSERVED_PROVIDERS` as `_ghost_gk` attributes (a transitive re-export) while `_DETECTION_AWARE_PROVIDERS` breaks: an asymmetric half-clean break; a negative test pins that `_ghost_gk` exposes NONE of the four moved names. `keeper_detection_mask` STAYS in `_ghost_gk` and delegates (raise trigger + mask preserved; message unified/provider-generic — no test pinned the old `keeper_detection_mask:` prefix; the surviving `match` strings are `discarded|null`, `skillcorner`, `unknown`). **Layer 1 (build-time):** `materialize_tc3_frames._guard_provider_frames` (called by `_work` before it returns frames) refuses to WRITE a detection-aware shard whose `visibility` is dropped (M2) or all-null, so the poison never becomes a shard. **Layer 2 (consume-time):** `train_ghost_gk.validate_corpus_visibility` reads parquet `null_count` METADATA (zero data pages) for EVERY detection-aware shard — catching a MIXED corpus (one tail-kloppy shard), not just a systematic one — BEFORE extraction; provider resolved from `source_provider` (the flat `for_each` generation has no `{provider}/` segment; a stats-less shard falls back to reading the one column; a 0-row shard is not a discard signal). The per-frame `keeper_detection_mask` + the `for_each` 3-consecutive-abort remain as backstops. Additive — **no model change, no retrain** (native carries a real `visibility`, so both layers no-op on every bundled corpus; they fire only on a detection-discarding builder). Decision: ADR-069.
