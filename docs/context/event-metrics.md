# Event-only metric families

> On-demand class-2 context (ADR-102-style store). The current terse RULES live in `AGENTS.md`; this file holds the WHY / history / measurement. See the spec `docs/superpowers/specs/2026-09-24-agents-md-restructure-design.md`.

- **Territory — territorial dominance (`territory/`):** TF-54 (ADR-086), the "Van Dijk" metric (Sumpter/Twelve module 10.2). Event-only per-`(player, match)` valuation of the ground a defender patrols. `compute_territorial_dominance(actions, *, xt, method="completed_failed", window=None, params)` → `(samples, TerritoryReport)`. A defender's *territory* = the **trimmed convex hull** (`trim_fraction=0.70`) of their own-half defensive-action locations (tackle/interception/clearance); opponent passes whose **destination** lands inside it are valued by an **INJECTED** fitted `ExpectedThreat` at that destination — **`xthreat.values_at_points` (the xT VALUE), NEVER `rate`** (which is an end−start difference that NaNs failed passes, killing the prevented leg): **conceded** (completed) vs **prevented** (failed), + forward-only variants, per-pass rates, hull area/centroid (12 metric columns). **`TERRITORY_METHODS = {completed_failed, counterfactual}`** — the default `completed_failed` values opponent passes at their observed end (byte-identical); **`method="counterfactual"` (TF-54b Path B, ADR-099) re-adds the event-only cone** — a GSAA-style `(P_complete − outcome)·xT(target)` over passes AIMED INTO the hull, modeling a failed pass's intended target over its death-direction cone (`q`, from the injected xT's transition distribution, family-agnostic) × an injected `PassCompletionModel` (`c`, ADR-022 duck-typed) × the injected `xt` value; ships behind the NON-default door with 5 cf-only columns (4 metric + `territory_target_source` provenance) and a conserving `n_target_modeled`/`n_target_unresolved` census (ADR-042). The SEPARATE tracking-based `silly_kicks.territorial_defense` sibling (ADR-090, SB360 removal counterfactual) is a DISTINCT mechanism (it took the "counterfactual" *name* while the door was briefly a dead `NotImplementedError`; ADR-099 re-fills the event-only door, they coexist). **Frame reconciliation is library-owned:** the hull is in the defender's action-LTR frame and opponent passes are point-reflected `(fl−end_x, fw−end_y)` into it for membership (ADR-028) — the metric is a 180° reflection relating the two teams' frames, so the e2e must NOT `play_left_to_right`. A degenerate hull (< 3 non-collinear actions) → a `territory_hull_source="degenerate"` NaN-metric row, **counted** (`TerritoryReport` conserves `n_scored + n_degenerate_hull + n_no_actions == n_players_in`; ADR-042). Uses `type_id` (real SPADL) not `type_name` (add_names-only). Grouped on the CANONICAL player id, raw id emitted (ADR-019). Event-only: imports `spadl`/`id_compat`/`xthreat` ONLY, never `tracking` (AST allowlist `tests/territory/test_import_allowlist.py`); nothing imports `territory`. A `compute_*`, NOT an `add_*` (C4 count stays 33). `TerritoryParams` frozen (`for_provider` empty per ADR-009); 12 `completed_failed` columns + 4 `counterfactual`-only metric columns in `feature_glossary` (glossary 451→455; 7th `compute_*` leg) + `NOTICE`; a `territory` C4 container. **Known under-count (`completed_failed`):** a failed pass's SPADL `end` is the death location, not the intended target — which is exactly what `method="counterfactual"` (ADR-099) models over the death-direction cone. **Ranking:** per-defender numbers are player-attributable only where the defender-vs-team confound is identifiable; a defender RANKING ships iff a crossed defender+team-cell **ICC census** (`scripts/build_territory_ranking_census.py`, locked constants) clears — an ADR-009 apply + a reported artifact, NEVER a library API (same posture as ADR-090). **The census CLEARED on the full public open-data corpus (4.120.0: 5989 defenders / 1103 multi-team ≥20; defender-share ICC lo=0.121 > 0, power=1.0 → LICENSED), so a reported defender ranking ships this cycle** as `docs/research/territory_ranking_census/ranking.parquet` (with `census.json` verdict + honest-limit) — the broad multi-club corpus supplies the cross-team observations the single-tournament SB360 sibling (ADR-090) lacks. Additive — no VAEP/tracking retrain, no re-materialize. Decision: ADR-086 (event-only counterfactual cone: ADR-099).

- **Expected passing + xT destination profiles (`expected_passing/`, `xthreat.destination_profiles`):** landed with TF-54b (ADR-090) as **reusable seams** carried from the unmerged `ab9001c`; the event-only counterfactual *cone* those seams back landed later as `territory` `method="counterfactual"` (TF-54b Path B, ADR-099). `expected_passing.PassCompletionModel` is an event-only logistic pass-completion model (pure-numpy serve; sklearn only inside `fit`; pickle-free JSON+SHA256 + feature-contract + chirality + fail-closed load, ADR-011/016/040/044/050); imports `spadl`/`id_compat`/numpy ONLY, never `tracking` (AST allowlist). **`PassCompletionModel.bundled()` serves the public-corpus default weights** (`silly_kicks/expected_passing/weights/`, trained by `scripts/train_pass_completion.py` on public StatsBomb open-data, `assert_public_corpus`-gated, clean `training_commit`) — bundled in the 4.112.0 cycle (WC2022, OOF AUC 0.811); **re-fit on the FULL public open-data corpus 4.120.0 (TF-54b, `--all-competitions`: 80 competition-seasons / 3961 matches, GroupKFold-by-match OOF AUC 0.794 / ECE 0.006)** — the `bundled()` test runs against the re-fit weights. `xthreat.destination_profiles` (backing `xthreat/_counterfactual_seam.py`) owns the flat-index / y-inversion (ADR-041) and consumes the transition matrix as a **family-agnostic distribution** (`singh_transition_matrix` is sub-stochastic, not row-stochastic), so both `singh_counts` and `kde_smoothed` are valid. An `expected_passing` C4 container (new-to-`main`). Additive — no retrain. Decision: ADR-090.

- **xSuccess + VAEP_adjusted (`xsuccess/`, `vaep/adjusted.py` + `VAEP.rate_adjusted`):** TF-61 (ADR-095), from Paul/Klemp/Memmert 2025 ("Beyond Outcome Bias"). **(1) `xsuccess.XSuccessModel`** — event-only, **END-BLIND** action-completion `P(success | pre-action context)` over ALL on-ball types (`result_id==success` label; `non_action` dropped). **END-BLIND is a correctness invariant, NOT a caveat:** features are start-anchored geometry + type + bodypart + time — **never** the realized action end, because for a *failed* action the SPADL end IS the outcome (interception/death point), so an end-using completion model is a **postdiction** (target leakage) that re-injects the bias VAEP_adjusted removes; `PassCompletionModel` is NOT a counter-precedent (it serves a *supplied* target, not a realized outcome). Guarded by an **end-location invariance** test (perturb `end`/`result` → features byte-identical, the `ReceiverModel` bar). Calibrated XGBoost served via the `[xgboost]` extra (xShot precedent) + pure-numpy isotonic — no runtime sklearn; pickle-free booster-JSON + metadata + SHA256, fail-closed `load` (SHA → feature-contract → chirality, ADR-011/016/040/050). **Per-type-logistic fallback family** (`fit(family="per_type_logistic")` / `train_xsuccess --family`) = the ADR-009 calibration fallback (one standardized logistic per `action_type`, calibrated-by-construction, pure-numpy serve, one-sided/thin types serve the base rate). `_load_booster_base_score_safe` is **copied (not imported)** from `tracking/_xshot_occurrence.py` to keep xsuccess event-only. Imports `spadl`/`id_compat`/numpy/pandas ONLY (xgboost/sklearn function-local), **never `tracking`** (AST allowlist `tests/xsuccess/test_import_allowlist.py`); nothing imports `xsuccess` except `vaep`. Ruthless stack (dev/train-time): `XSuccessObjective` (ruthless `CachedObjective`, `assert_cache_equivalence`) for Optuna HPO + `scripts/evolve_xsuccess_features.py` (OpenEvolve feature-representation discovery within a leakage-safe END-FREE allowlist; committed deterministic output + provenance + held-out check; seed-fallback). **(2) `VAEP.rate_adjusted`** (+ `vaep.adjusted.adjusted_value`) — re-scores an already-fitted **STANDARD** VAEP on a **surgical result-feature counterfactual** (flip ONLY the current action's a0 `result_onehot`/`actiontype_result_onehot`; hold locations, goalscore, predecessors fixed — the ceteris-paribus form, NOT the paper's whole-dataset flip which inflates goalscore + rewrites predecessor history), weights by `xSuccess`/`(1−xSuccess)`, runs the *existing* `formula.value` delta (eqs 8–12). **No retrain.** Requires result-bearing features → **raises on HybridVAEP** (the flip is a no-op, non-vacuity guard); NaN `xSuccess` → NaN adjusted value. Additive — no default retrain, **no `*_xfns`** (a model + a rating method, not `add_*`; reads `result` only as a training label), **no `feature_glossary` growth**; +1 C4 container (`xsuccess`); action-coupled aggregator count unchanged (33). Bundled weights + construct-validity report land in the release's 2nd clean-tree-provenance commit (TF-57/TF-62 2-phase). Decision: ADR-095.

- **Duels — Glicko-2 duel ratings (`duels/`):** TF-55 (ADR-086). Event-only per-`(player, match)` pairwise skill rating over ground-duel outcomes. `compute_duel_ratings(actions, *, initial_ratings=None, window=None, window_stat="as_of_end", params)` → `(samples, DuelRatingReport)`, one row per `(game_id, player_id)`: `duel_rating`/`duel_rating_deviation`/`duel_volatility` + `duels_contested`/`_won`/`_lost` + a `duel_winner_source` provenance (`native`/`derived`). **Glicko-2** (Glickman: `_SCALE=173.7178`, Illinois volatility update, inactivity RD growth) with the **match as the rating period** — matches process in ascending-`game_id` order (a chronology proxy) with ratings **carried forward**; the pure, leakage-free `update_glicko(ratings, period_games, *, params)` primitive is validated against Glickman's published worked example (1464.06/151.52/0.05999). **A rating system is long-lived: `initial_ratings` RESUMES a later batch and `DuelRatingReport.final_ratings` (canonical-keyed) is the resume seed — `compute(m1+m2)` final state == two batches threaded via `initial_ratings` (byte-equal, resume-equivalence gated on real data).** `window` (a Collection of `game_id`s) slices the trajectory (one row/player, `game_id` NA; ratings are cumulative NOT summed): `window_stat="as_of_end"` (default, latest rating in the window) or `"change"` (delta from just before the window, seed for a debutant); counts summed. **Duel extraction:** `native` (sportec `tackle_winner/loser`, ADR-001 dedicated columns) OR, absent those, `derived` from an **adjacent cross-team `tackle`/`take_on` pair** within a 5 s window (winner = whoever's action SUCCEEDED); the strategy is chosen at **frame-set granularity** (`_has_native`), never per-duel-guess. **Ground duels only** (SPADL has no aerial type); an **indeterminate** duel (both-success/both-fail) is **EXCLUDED and counted** (`DuelExtractReport`; ADR-042), never a fabricated winner; both participants must be non-NA. Grouped on the CANONICAL player id (`canonical_id`), raw id emitted (ADR-019). Event-only: imports `spadl`/`id_compat` ONLY, never `tracking` (AST allowlist `tests/duels/test_import_allowlist.py`); nothing imports `duels`. A `compute_*`, NOT an `add_*` (C4 count stays 33). `DuelRatingParams` frozen (`for_provider` empty per ADR-009); 6 columns in `feature_glossary` (8th `compute_*` leg) + `NOTICE`; a `duels` C4 container. **Known limit:** the derived path only pairs adjacent `tackle`/`take_on` (~11 duels/match on StatsBomb WC2022). Additive — no VAEP/tracking retrain, no re-materialize. Decision: ADR-086.

- **Match outcome — win probability / xPoints (`match_outcome/`):** TF-53 (ADR-097). Event-only per-`(game_id, team_id)` outcome model from an INJECTED per-shot xG (port pattern — silly-kicks ships no xG). `compute_match_outcome(actions, *, xg_column, params) -> (samples, MatchOutcomeReport)`: each team's **exact Poisson-binomial** goal PMF (`goal_count_pmf`, DP convolution over per-shot Bernoullis — **NEVER `Poisson(ΣxG)`**, which discards chance quality) → the two-team scoreline simplex (`match_outcome_probabilities`) → `p_win`/`p_draw`/`p_loss` + `xpoints = 3·p_win + p_draw` + `expected_goals`. **Two ORTHOGONAL string-dispatched corrections on the frozen `MatchOutcomeParams`, and the DEFAULT is BOTH ON (ADR-097):** `same_possession="collapse"` (Rung 3b — same-possession shots combine as `1 − ∏(1 − xg)` via `spadl.add_possessions`; ON on CORRECTNESS: same-possession shots are not independent Bernoulli trials, so the independent model double-counts) + `team_dependence="dixon_coles"` (Rung 3a — Dixon & Coles 1997 low-score τ reweighting with a fitted ρ; ON on MEASURED evidence — the full-corpus paired per-match Brier beats independent on 77.3%/68.7% of matches, Wilcoxon p≈1e-124/1e-71). `"independent"` on either axis recovers the naive exact PB. **The `dixon_coles` default couples the default compute path to the bundled ρ** (`DependenceModel.bundled()`, `functools.cache`'d): pickle-free JSON + SHA256 + `|ρ|<1` range + `training_commit`, **fail-closed load — a missing/tampered/out-of-range artifact RAISES, never silently degrades**; `"independent"` is the artifact-free opt-out. **Own goals** counted by RESULT (`result_id==owngoal`, ADR-018) for the `MatchOutcomeReport` scoreline census, EXCLUDED from the xG model (no xG). Conservation census (ADR-042: `n_matches_scored + n_matches_excluded_not_two_teams == n_matches_in`); honest-NaN (no-shots team → `P(0)=1`; NaN-xg shot excluded+counted; non-two-team game excluded+counted). Canonical-id grouped (ADR-019). Hexagonal — imports `spadl`/`id_compat`/`_frame_index.group_rows` ONLY, never `tracking` (AST allowlist `tests/match_outcome/test_import_allowlist.py` both directions); nothing imports `match_outcome`. A `compute_*`, NOT an `add_*` (action-coupled aggregator count stays 33); in NO default xfn list, no `*_xfns` (a match-grain metric reading no gamestate features). `MatchOutcomeParams` frozen (`for_provider` EMPTY per ADR-009; a per-provider ρ tune is a separate gated PR). Bundled ρ (scipy-MLE `minimize_scalar`, StatsBomb open-data 3,961 matches, ρ=0.0216) + the reported-not-gated calibration study land in the release's 2nd clean-tree-provenance commit (TF-57/TF-61 2-phase; `docs/research/tf53_match_outcome_calibration/`). **Pappalardo/Wyscout cross-provider calibration is out of scope** — public Wyscout has no xG and the metric is xG-driven end-to-end. 5 columns in `feature_glossary` (glossary 446→451) + `NOTICE`; +1 C4 container (`match_outcome`). Additive — no VAEP/tracking retrain, no re-materialize. Decision: ADR-097.

- **Win probability — in-game win/draw/loss + xImpact (`win_probability/`):** TF-63 (ADR-101), the in-game, time-varying extension of TF-53 (Paul, Klemp & Memmert 2025). Event-only per-`(game_id, action_id)`: an **interval-hazard logistic** on `(score_diff, minutes_remaining, base_strength, home, man_advantage)` feeds a **forward Markov chain on `score_diff`** (Dixon & Robinson 1998; in-game WP per Robberechts, Van Haaren & Davis 2019) — it **REPLACES, does not reuse, the TF-53 `match_outcome` convolution/simplex** (team-independence is exactly the approximation the chain removes), so `win_probability` imports **no `match_outcome`, no `tracking`, no `vaep`** (AST allowlist both directions); the only cross-edge is `vaep → win_probability`, a lazy function-local import. Public surface: `compute_win_probability(actions, *, model, games=None, strength_column=None, params) -> (samples, WinProbabilityReport)` (per-action `p_win`/`p_draw`/`p_loss`/`win_prob_leverage`), `goal_leverage` (per-action `ΔP(win | goal) = P(win|score+1) − P(win|score)`, exact chain re-run), `WinProbabilityModel`, `WinProbabilityParams`. **`VAEP.rate_ximpact`** (+ `vaep/ximpact.py`) = `rate_adjusted` × the same-state goal leverage on the acting-team perspective; **raises on HybridVAEP** (inherited from `rate_adjusted`), NaN-propagating; in NO default xfn list, **no `*_xfns`** (state-based, reads no post-action outcome). **Leverage non-negativity + `score_diff`-monotonicity are GATE-ENFORCED, not structural** (a state-dependent mean-reverting kernel is not guaranteed stochastically monotone): `certify_coherence` REJECTS a bad fitted hazard at bundle time — fix the model, never clamp; the exact goal difference and dead-state → 0 ARE structural. **Chirality is N/A** (no geometric/coordinate features) — the fail-closed `load` guard is SHA256 + the feature-contract probe ONLY (ADR-011/040/050). `base_strength` is leakage-free by date (mean xG-supremacy over each team's STRICTLY-earlier matches). Own goals counted by RESULT (`result_id==owngoal`, ADR-018). Conservation census (ADR-042: non-two-team game excluded+counted; unresolved state honest-NaN). Canonical-id grouped (ADR-019). A `compute_*`, NOT an `add_*` (action-coupled aggregator count stays 33); `win_prob_leverage` in `feature_glossary` (455→456), `ximpact`/`p_win`/`p_draw`/`p_loss` glossary-generalized; `win_probability` is `metric_contracts`-exempt (per-action feature-grain, not a per-(entity, match) mart family). `WinProbabilityParams` frozen (`for_provider` EMPTY per ADR-009). **Face-validity note (honest limit, `docs/research/tf63_ximpact/`):** leverage is ΔP(**win**), so a late **go-ahead** goal scores high and a garbage-time goal ≈ 0, but a trailing late **equalizer** scores LOW (loss→draw is a points-swing, not a win-swing); an expected-points variant is a future ADR-009. Bundled `default` weights (3,961 public open-data matches / 80 competition-seasons; OOF ECE 0.017, slope 0.991) + the reported-not-gated construct-validity report land in the release's 2nd clean-`training_commit` commit (TF-53/TF-57/TF-61 2-phase); +1 C4 container (`win_probability`). Additive — no VAEP/tracking retrain, no re-materialize. Decision: ADR-101.
