# Velocity availability, FOV observability & GK clamp

> On-demand class-2 context (ADR-102-style store). The current terse RULES live in `AGENTS.md`; this file holds the WHY / history / measurement. See the spec `docs/superpowers/specs/2026-09-24-agents-md-restructure-design.md`.

- **SB360 visibility companions are OPT-IN and additive (ADR-062, 4.84.0).** `add_action_context(actions, frames, *, visible_area=None)` emits six companion columns (`<feature>_observed_fraction`/`_observed_source` for the three region-based counts: nearest-defender, receiver-zone, defenders-in-triangle) ONLY when `visible_area` is supplied — the primary count columns are byte-identical with and without it, and the per-Series functions + `tracking_default_xfns` are untouched, so NO VAEP feature changes and NO retrain. `classify_region_observation(polygon, region) -> (fraction, source)` + the FEATURE-level `REGION_OBSERVATION_SOURCE_VALUES` (`observed`/`no_polygon`/`degenerate_polygon`/`degenerate_region`) REUSE the ADR-055 polygon tokens and ADD `degenerate_region` (a zero-area/NaN-radius region-of-interest) — **not** a widening of the pinned `VISIBLE_AREA_SOURCE_VALUES`; `unlinked` is overlaid by the caller from the action↔frame link. The nearest-defender region is an inscribed disk of radius = the measured distance, so a NaN distance → `degenerate_region`, never a fabricated fraction. The companion path reads a caller-supplied polygon ndarray → a 2nd purity variant is registered (ADR-033). The companions are DELIBERATELY outside the ADR-053 SB360 audit (a two-leg comparison is vacuous on a full-coverage fixture) and outside `feature_glossary` (opt-in ≠ default-config output) — both documented at `tests/sb360/_registry.py::audited_surface`. Decision: ADR-062.

- **`speed_source` has three tokens, not two.** `TRACKING_CATEGORICAL_DOMAINS["speed_source"]` is `{native, derived, unavailable}`. `"unavailable"` is a frame builder DECLARING that its source has no per-player temporal history, so `speed`/`vx`/`vy` can never exist -- deliberately distinct from a NULL `speed_source` ("not derived YET"), because the two demand opposite responses. Third-party builders may set it; it is a public contract, not a snapshot backdoor. An UNMARKED or PARTIALLY-marked frame set missing `vx`/`vy` still RAISES: fail-loud wins on a mixed frame set.

- **A provenance COLUMN where the VALUE changes; a DIAGNOSTIC where only the INTERPRETATION changes (ADR-054).** `add_ghost_gk` earns `ghost_gk_source` because a number becomes NaN -- a per-row fact. The five other aggregators whose output moves with velocity (`add_elastic_sync`, `add_obso`, `add_pausa`, `add_pitch_control`, `add_space_creation`) produce an HONEST value either way -- pitch control at zero velocity is a well-defined positional model, not a fabrication -- so what changes is how it should be READ, which is a property of the whole frame set. Hence public `validate_velocity_regime`/`VelocityRegimeDiagnosis`, the third member of the `validate_time_base` (ADR-017) / `validate_id_dtypes` (ADR-019) family, split across `schema.py` and `utils.py` the way that family already is. It carries FIVE regimes, because "forgot `derive_velocities()`" is NOT a variant of `mixed`: nothing is structurally missing there, and labelling it `mixed` would raise with a false explanation in the case a user is most likely to hit. **The velocity guard itself lives at the SHARED SERVING SEAM `_serve_positions_core`**, never at one aggregator: there are THREE public ghost entry points and two bypass `add_ghost_gk` (`ghost_gk_xfns` -> `compute_ghost_gk`, and `gkdv` -> `serve_ghost_gk_positions`). The seams degrade DIFFERENTLY and the asymmetry is forced -- `serve_ghost_gk_positions` returns NO rows rather than NaN ones, because `gkdv/_engine.py` RAISES on a non-finite ghost on a scored frame.

- **Velocity-less providers get the zero-velocity model via ONE fail-fast edge seam (ADR-063).** The four velocity-requiring pitch-control aggregators (`add_gk_influence`/`add_cover_shadows`/`add_player_influence`/`add_space_creation`) + `pitch_control_at_target` route missing velocity through `tracking._velocity_availability.zero_velocity_if_unavailable(frames, *, method="spearman")`: vx/vy present → unchanged (same object); ABSENT + DECLARED (`velocity_unavailable_by_design` — SB360 freeze-frames) → a zero-velocity copy (classic Spearman positional model); ABSENT + NOT declared + velocity-requiring method → **RAISES** (a forgotten `derive_velocities()` is a caller bug, failed loud not swallowed into an all-NaN column — the ADR-043 discipline). `compute_pitch_control` is UNCHANGED (policy at the edge, engine pure). The seam sits at the compute_* sites AND the `_*_at_actions` kernel EDGES (before the per-frame `except (ValueError, KeyError)` catch, so the raise is not swallowed); it REPLACES two ad-hoc unconditional `vx/vy=0` blocks (`pitch_control_at_target`, `compute_space_created`) and one silent `_compute_cover_shadow_dict` `return None`. **Three tiers, MEASURED not asserted (D2):** model-relative columns (share/xT/blocking/OBSO — dimensionless, no physical referent) are LIFTED (Tier-1); physical-quantity estimates (`gk_reachable_area_m2`, `gk_closing_time_*`, `reachable_area_*`, `actor_reachable_area_m2` — m²/s, systematically biased at zero velocity) are SUPPRESSED to NaN (Tier-2); constitutively-velocity columns stay honest-NaN (Tier-3). **Tier-2 suppression is ACTIVE, not the absence of a lift** — `compute_tti` auto-fills vx/vy=0, so the Tier-2 columns compute FOR FREE once the share path stops raising; keeping them NaN is an explicit branch (in `compute_gk_influence`/`compute_player_influence`, plus the `_player_influence_at_actions` ASSEMBLY because `actor_reachable_area_m2` initialises 0.0 and stays 0.0 for a GK actor). **NO per-row token** (PREFERRED D1): a constant `velocity_unavailable` column is the shape `schema.py:310-312` rejects — the signal is the frame-level `validate_velocity_regime`; `das_source` is legit only because it VARIES. **NO retrain** (velocity-bearing output byte-identical — the helper returns the same object; the helper also returns an EMPTY frame set unchanged, so VAEP `feature_column_names` introspection never raises). Breaking (intended): `add_pitch_control` is public (lakehouse d32). Audit re-adjudicated: Tier-1 → `differs_by_design`, velocity-invariant Tier-1 → `works`, Tier-2 → `honest_nan`. The four `*_xfns` opt-in transformers mirror the SAME contract (edge helper at each transformer top so the forgotten-velocity raise precedes their per-frame `ValueError` catch; `player_influence_xfns` replicates the Tier-2 assembly suppression; `space_creation_xfns` delegates to `add_space_creation`). **`add_obso`/`add_pausa` (+ `obso_xfns`/`pausa_xfns`) also fail-fast** via the SINGLE shared `_precompute_obso_lookup` seam — they were never in the 40-NaN set (they already zero-filled on declared frames, so declared behaviour is byte-identical and the SB360 obso verdict is unchanged), but their loose zero-fill silently accepted a forgotten `derive_velocities()`; `add_pressure_on_actor(method="bekkers_pi")` is now **Tier-3 honest-NaN** on velocity-unavailable frames (ADR-063 amendment): its active-pressing `speed_threshold` filter is a velocity-GATED discrete term, so its zero-velocity value is artifact-dependent (`speed=NaN`→filter no-ops→a different model under the same name; `speed=0`→degenerate 0), NOT a smooth limit — so it SUPPRESSES, does not lift. **The reusable tier-assignment discriminator: a zero-velocity form that is a smooth limit of the same model → Tier-1 lift; one gated by a velocity-DISCRETE term (threshold/filter) → Tier-3 honest-NaN.** Contrast the existing ball-less degrade (base model = still-meaningful → fallback, not NaN). The seam REPLACES the prior unconditional vx/vy raise in `pressure_on_actor`'s bekkers branch (edge, engine pure); `add_pressure_on_actor` delegates so it inherits it; positional `andrienko_oval`/`link_zones` untouched. Closes the pressure-honesty loop for `GkRetention`'s marts `release_pressure` (= `pressure_on_actor__bekkers_pi`) at the source.

- **The velocity-availability contract (ADR-054) is CI-ENFORCED, not just documented, and anchored STRUCTURALLY (ADR-054 amendment).** `add_xshot_occurrence` fabricated on velocity-less SB360 (its `speed` feature → XGBoost missing-value routing; live on the `pre_shot_gk_full_default_xfns` GK-union bundle) — now guarded at the shared `compute_xshot_occurrence` seam exactly like `compute_xcross_attempt` (declared→honest NaN; undeclared-missing-velocity→raise). The systemic fix is `tests/tracking/test_velocity_feature_contract.py`: a static gate whose population is **frame-consuming model-scoring entries** (a `frames` param + fitted-model scoring), NOT the `*_FEATURE_NAMES*` naming convention — each velocity-feature entry must CALL the guard in its body (a module import is not enough), `_GUARD_EXEMPT` carries verified wrappers/eval-probes/velocity-free-scorers, and `test_population_is_exact` (keyed on `(module,name)`) catches a new frame-served model whatever it names its features. KNOWN LIMIT: the in-body-call check keeps the two-prong block duplicated across serve modules; if DRY'd into a shared helper, teach `_fn_calls_guard` to follow one call level. `add_space_creation` opponent-perspective softens a one-team SB360 FOV crop to per-row NaN (new additive `space_opponent_source` provenance: `resolved`/`unresolved_one_team`) instead of aborting the batch; full-tracking + 0/3+-team frames still raise. **The softening gate keyed on `velocity_unavailable_by_design` as a PRAGMATIC FOV PROXY** (velocity-less ≠ FOV-cropped in general; they coincide only in today's providers) — **RETIRED onto the real `validate_fov` signal by ADR-077** (the softening now keys on a per-action `fov_cropped`; a one-team frame WITHOUT `visible_area` now RAISES).

- **FOV-observability is single-sourced through ONE registry engine, and there is ONE observability model — the observed AREA fraction of a convex region (ADR-077).** StatsBomb-360 freeze-frames carry only the in-FOV players (a per-action `visible_area` polygon), so every region-/aggregate-based tracking metric silently under-reports. Public `validate_fov`/`FovDiagnosis` (`schema.py`+`utils.py`) is the 4th frame-set diagnostic after `validate_time_base`/`validate_velocity_regime`/`validate_id_dtypes` (regimes `full_coverage`/`fov_cropped`/`absent`/`mixed`, the last reachable only at `0<n_full<n`; consumes the polygon table only; empty never raises). The neutral `tracking/_fov_registry.py` (imports only `_visibility`/`_kernels`/`id_compat`/`_polygon`/`spadl.config` — never `pitch_control`/`_das`) binds each raw metric column to a convex-region builder (`ObservabilityEntry(column, region, covers=())`; `_NO_REGION` is an IDENTITY sentinel tested with `is`, never `==`) and `append_observability_companions` emits `<column>_observed_fraction`/`_observed_source` via `classify_region_observation` in ONE code path. **A per-contributor "roster fraction" is VACUOUS on a freeze-frame** (a cropped player is absent from the frame entirely → fraction ≡ ≈1.0, silent in exactly the biased case) — the model is always observed-AREA of a convex region (tight ROI, or a **FIXED action-LTR zone keyed on the column's ROLE**, NEVER a `goal_map`: the polygon+metrics are all action-LTR, so a `goal_map` end mis-orients away-possession actions — the S1 silent failure). ADR-062's three `add_action_context` ROIs are retired into it BYTE-IDENTICALLY (parity-gated). Seven aggregators NEWLY gain an opt-in `visible_area=None` kwarg this cycle (`add_pressure_on_actor`/`add_packing`/`add_defensive_line`/`add_team_shape`/`add_player_influence`/`add_xt_gk`/`add_defensive_credit`), joining `add_action_context`'s ADR-062 companions (**eight companioned total**); `add_xt_gk` companions the method-dispatched pressure ROI on `xt_gk_pressure`/`xt_gk_pev` ONLY (composite `xt_gk` EXEMPT, M1); `add_defensive_credit` emits ONE magnitude-weighted per-action rollup and **widens the public `compute_defensive_credits` long-form by +3 additive trailing columns** `origin_x`/`origin_y`/`region_radius` (a Hyrum surface for fixed-position long-form consumers). A two-axis completeness gate (`test_fov_completeness_gate.py`) forces every FOV-sensitive column (`region_support` ∪ hand-curated `_AGGREGATE_FOV_SENSITIVE`, tracking `add_*` surface, boundary entries excluded structurally) to be companioned or `_OBSERVABILITY_EXEMPT`-with-reason (exempt: composite `xt_gk`; `ghost_gk_x`/`ghost_gk_y` — a learned whole-frame model, bespoke observability deferred). **Everything is additive+opt-in: primary columns byte-identical with/without `visible_area` → NO VAEP retrain, C4-free** (`validate_fov` is a diagnostic, the registry is internal). **The companions are glossary-EXEMPT (absent from default-config `emitted_columns()`, like ADR-062's — glossaring them would fail `test_no_stale_entries`; the count does NOT grow, the spec's "count grows" is inaccurate) and OUTSIDE the default SB360 audit** (a two-leg full-coverage fixture makes a visibility companion vacuous; recorded at `tests/sb360/_registry.py::audited_surface`, verified on the licensed corpus instead). **Caller-facing (Task 7, NOT additive):** `space_creation`'s opponent-perspective one-team softening now keys on `fov_cropped` (retiring the `velocity_unavailable_by_design` proxy) and RAISES on a one-team frame without `visible_area` where it previously softened. Decision: ADR-077.

- **Gradient Sports clamps the goalkeeper's tracked position at 27.5 m from goal — a SOURCE-DATA limitation, guarded by `validate_gk_position_clamp` (ADR-083).** GS's broadcast tracking pins the keeper at a hard 27.5 m from its OWN goal (universal + exact across matches/keepers on the RAW provider data — verified; keeper-specific, outfielders roam the full pitch), which silly-kicks faithfully passes through (native roster keeper identity, no coordinate clamp — NOT a silly-kicks/lakehouse defect). So **any GS goalkeeper-depth analysis is INVALID past 27.5 m** (the TF-19/TF-60 counterfactual GK arms, `xt_gk`, GK influence, the factual keeper position itself). Public `validate_gk_position_clamp`/`GkClampDiagnosis`/`GoalkeeperClampWarning` is the FIFTH `validate_time_base`/`validate_velocity_regime`/`validate_fov` frame-set diagnostic (`schema.py`+`utils.py`): it detects the clamp SIGNATURE provider-AGNOSTICALLY — a hard ceiling on the keeper's `min(x, 105-x)` (distance from the NEAREST goal, so no orientation/goal_map) with an anomalous PILEUP at it (a natural keeper has ~0 mass at its single-sweep max; measured GS pileup 1.4-14.9% vs sportec/SC 0.00-0.07%, a clean ~20× separation → default `ceiling_tol_m=0.1`/`pileup_threshold=0.01`, conservative because a false positive on a natural provider is worse than missing a rarely-sweeping GS keeper). **`tracking.gradientsports.convert_to_frames` calls it `warn=True`** so every GS frame consumer is told (a silent pass-through was the trap; the `min_keeper_frames=200` guard no-ops a small slice). Additive, no retrain, C4-free. Surfaced by the TF-60 PR3 sweeper's GS 0.0% `>30 m` coverage; evidence `docs/research/gs_keeper_clamp/findings.md`. Decision: ADR-083.
