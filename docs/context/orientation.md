# Orientation, reflection & the defended-goal map

> On-demand class-2 context (ADR-102-style store). The current terse RULES live in `AGENTS.md`; this file holds the WHY / history / measurement. See the spec `docs/superpowers/specs/2026-09-24-agents-md-restructure-design.md`.

- **Per-action geometry is emitted in the SPADL action-LTR frame (ADR-028, 4.26.0).** Actions are per-acting-team LTR (acting team attacks x=105); `convert_to_frames` is home-attacks-right (home attacks x=105 every period). They are a 180° point reflection apart for **away-team actions**, and the geometry layer historically sampled frame positions WITHOUT re-projecting → ~50% of tracking action rows wrong: visibly-bimodal absolute positions (`pre_shot_gk_x`, `defensive_line_x`, `team_shape_centroid_*`) AND silently-wrong mixed-frame scalars (`nearest_defender_distance`, `receiver_zone_density`, `defenders_in_triangle_to_goal`, all `pressure_on_actor__*`, `pre_shot_gk_distance_to_shot`/`_angle_*` — action anchor combined with frame positions). One frame serves BOTH teams' actions, so the caller cannot pre-orient; re-projection is per-action + library-owned. Fixed by ONE helper `tracking/_action_orientation.py` (`acting_team_attacks_rtl` keyed on the frame's `team_attacking_direction`, `align_join_keys` for the id join; `reproject_to_action_ltr`) at THREE seams: the shared `_resolve_action_frame_context` (fixes all 8 context kernels at once + makes their hardcoded goal-at-(105,34) correct), `_kernels._defensive_line_at_actions`, and `add_team_shape`/`_team_shape_at_actions`. `add_ghost_gk` emits action-LTR (`x→105−gr_x` uniform; `y→68−gr_y` — **UNIFORM since ADR-089**, was `away only` under the x-only model) — the model now serves BOTH-AXES goal-relative coords, and because the keeper's goal-relative flip is the COMPLEMENT of the acting team's action flip the per-action reflection cancels the model's own, so both axes reproject uniformly; the pre-ADR-089 flip-gated `y` double-flipped the flip=False rows once the model's `y` became goal-relative (fixed in `features.py`, guarded by `test_ghost_gk_mirror_invariant`); `compute_team_shape` made **orientation-aware** (deepest line nearest the defended goal; ltr/home byte-identical, only rtl/away changes). Self-reconciling features (`structural_pass`/`shape_graph`/`das`/`pitch_control`/`xt_gk`) DON'T use the context and are untouched (no double-flip). **CORRECTED in 4.52.0 (ADR-041): `obso`, `space_creation`, `pausa`, `player_influence`, `cover_shadows` and `gk_influence` were listed here in error** — they don't use the shared context, but they were NOT self-reconciling either; `obso` simply never handled orientation at all (`home_team_id` was a dead parameter), and `player_influence` multiplied a y-mirrored raw `interpolator()` grid. They are now reprojected AT THEIR OWN QUERY SEAM: the action-LTR target is point-reflected into frame coords and the attack-LTR EPV/threat grid is point-reflected (`[::-1, ::-1]`, BOTH axes) whenever `acting_team_attacks_rtl`. **CORRECTED AGAIN 2026-07-29 — that sentence is TRUE of `obso`/`pausa`/`player_influence` and FALSE of two of the six** (spec `docs/superpowers/specs/2026-07-29-adr028-orientation-defect-class-design.md`): `space_creation` was NEVER reprojected — `_compute_space_creation_for_action`'s `home_team_id` is a DEAD parameter (verified: identical output for `{HOME, AWAY, 999}`) and ADR-041 gave it only an unconditional `axis=(0,1)` opponent mirror, so its two emitted columns were EXCHANGED for every away action (**RC3, FIXED 4.71.0/PR-S139**: `compute_space_created` gains a keyword-only `attacks_rtl` threaded from the FRAMES via `acting_team_attacks_rtl`, and point-reflects the attack-LTR `transition_grid`/`epv_grid` — **the two GRIDS, never the finished `obso_multiplier`**, which also carries a ball-anchored `distance_weight` computed in frame coords that must never be mirrored, the rule the opponent branch already followed; reflecting at the grid seam corrects the opponent multiplier for free since it is built as a flip of the same artifacts. `home_team_id` stays in the signature and stays UNREAD — D3 retires it by disuse, not removal); and `cover_shadows` was only HALF reprojected — the RECEIVER at `_cover_shadows.py:1164`, never the PASSER at `features.py:3698`/`:3861` (**RC1, FIXED 4.70.0/PR-S138**: the passer is now reprojected INTO frame coords at both seams — everything downstream of that tuple is frame-convention and the xT lookup already reprojects itself; in the xfns path the reprojection precedes `_get_cs`, which rounds `passer_xy` into its cache key). A third, `gk_influence`, reprojects the right thing keyed on the WRONG thing: `_gk_influence.py:371-372` applies the both-axes point reflection but gates it on `same_id(attacking_team_id, home_team_id)` — team IDENTITY, not attacking DIRECTION — so it is correct only while frames are home-attacks-right (**D3 — CLOSED in 4.80.0; see the D3 bullet below**). Durable guard: `tests/tracking/test_action_ltr_mirror_invariance.py` (hand-listed, 5 aggregators) PLUS `tests/tracking/test_mirror_registry.py` — a registry-driven pair of gates over all 33 registered `add_*`: **Gate A** (physical mirror; detects convention mixing) and **Gate B** (vary `home_team_id` on FIXED frames; detects identity-keyed direction, which Gate A is structurally BLIND to because swapping `home_team_id` restores the very invariant identity-keying assumes). **VAEP/tracking-retrain trigger** (away-team values change; home-team byte-identical). C4-free (no new aggregator/backend/model). Atomic mirror inherits.

- **Frame-LTR orientation is single-sourced for consumer-built frames (ADR-029, 4.27.0).** ADR-028's per-action re-projection only works on frames already in the canonical **home-attacks-right** convention; it no-ops on absolute frames (`team_attacking_direction` all-null) — filtering to `.notna()` rows yields an empty direction lookup → no flip → ~50% mirror-wrong geometry. Providers converted via `convert_to_frames(output_convention="ltr")` (sportec/GS) or the kloppy gateway (metrica/skillcorner) are already oriented, but a consumer holding **bronze DataFrames** (not a kloppy `TrackingDataset`) builds frames itself and must orient them. Public `tracking.orient_frames_to_ltr(frames, *, home_team_id, home_team_start_left, home_team_start_left_extratime=None)` is the **unlabeled-input** sibling of `play_left_to_right` (which serves already-labeled frames): pure composition of `compute_attacking_direction` (private) + `play_left_to_right` with fail-loud guards (missing-schema; already-labeled → raise + route to `play_left_to_right`; zero home-match (ADR-019); ET-without-flag). Two entry points by input state — labeled → `play_left_to_right`, unlabeled → `orient_frames_to_ltr`. **Consumer contract:** any consumer building frames from a non-kloppy source MUST orient before the geometry layer; the helper is only as correct as the caller-derived `home_team_start_left` (validate per game — e.g. defending GK lands near the attacked goal post-orient). Additive — no provider behaviour change, no silly-kicks retrain; the lakehouse re-materializes metrica/skillcorner after adopting it. The sportec/GS adapters are NOT refactored through the helper (primitives already shared; Chesterton's Fence). Positive ET orientation is regression-guarded on both the helper and the native adapters (`tests/tracking/test_adapter_extra_time_orientation.py`), prompted by a live GS-ET flip that was a consumer-side `home_team_start_left_extratime` placeholder bug, not a silly-kicks bug.

- **The kloppy TRACKING gateway pins the canonical SPADL coordinate system (ADR-031, 4.29.0).** `tracking/kloppy.py` previously emitted frames **y-mirrored** vs SPADL actions (`action_y == 68 − frame_y`) for SkillCorner / Metrica / IDSSE-dev: the EVENT gateway (`spadl/kloppy.py`) pinned `_SoccerActionCoordinateSystem` (now extracted to the shared `spadl/_kloppy_coordinates.py` + `socceraction_coordinate_system` helper, imported by both gateways), the tracking gateway never did, so frames kept each provider's kloppy-native vertical. Single-axis y mirror (NOT orientation — orthogonal to ADR-028/029; error `|68−2y|` → 0 at centre, ~full width at touchlines, which hid it). Fix: `convert_to_frames` pins the CS via a **CS-only `transform()` signature** — dropping `to_pitch_dimensions`, which otherwise silently OVERRIDES the CS vertical and leaves y inverted (Gate 0); the CS carries its own standardized 0–105/0–68 dims, so x is byte-identical. **NOT** a blanket `y=68−y` flip (which would double-invert an already-canonical provider; no-op-on-canonical guarded). DGX-verified: SkillCorner + Metrica both inverted → fixed (**calibration retrain trigger** — but the lakehouse builds SC/Metrica via its OWN bronze builders, so PR-S94 fixes the calibration/pining path + external gateway consumers, NOT lakehouse prod); the **native** sportec/IDSSE path is y-CORRECT (Gate D — no fix, no retrain). First of a sequence (PR-S94 / T1); the IDSSE/Sportec DFL **parse-port** single-sourcing (T3, PR-S95) + the lakehouse's own SC/Metrica builder y-check follow. C4-free (no new aggregator; count stays 28).

- **TF-23b geometric frame-LTR backstop on the native tracking adapters (ADR-035, 4.34.0).** `tracking.{gradientsports,sportec}.convert_to_frames` now self-correct a wrong/absent `home_team_start_left_extratime` from GK geometry: a shared `direction.finalize_orientation` tail (ET guard → per-period flag flip → period-gated label → the idempotent `orient_frames_to_ltr_by_geometry` backstop) replaces the duplicated inline orientation block in both adapters (**supersedes the ADR-029 no-refactor fence for the native adapters ONLY** — kloppy gateway stays intentionally un-routed). The net gains `on_missing_home` (default `"raise"`; adapters pass `"warn"` to keep their warn-don't-raise contract) + `copy` (default `True`; `finalize` passes `False` to drop the redundant 3rd full-frame copy on tracking-scale data) and **no longer orients period-5/PSO frames for ANY caller** (incl. the TF-23 SC/Metrica builders; PSO excluded from geometric analysis). **Byte-identical no-op on the correct-flag path** (DGX G1, strict-dtype: 69/71 corpus matches byte-identical; the only 2 changed are GS WC2022 ET-tracking matches **10506 + 10517** whose constant placeholder flag was geometrically wrong → **VAEP/tracking-retrain trigger for those 2 ET-frame sets only**). Closes ADR-031 **Gate D** (sportec/IDSSE-ET handedness; gated on synthetic sportec ET + the provider-agnostic mechanism — 0 real IDSSE-ET in the pining corpus, G3 re-scoped). C4-free (count stays 28).

- **The defended goal end has ONE implementation: `resolve_defended_goals(frames) -> GoalMap` (ADR-055).** It replaced **ten** hand-rolled `0.0 if same_id(team, home_team_id) else 105.0` forks across 5 modules, and an eleventh fails CI — `tests/tracking/test_goal_map_population.py` is a SEMANTIC AST gate (`IfExp` ∪ `If`/`else`-assigning-one-name ∪ `np.where`; a ternary-only predicate was blind to four `if` statements), landed RED and observed failing on all ten. Three rules, none optional. **(1) Build ONCE per match from the FULL frames and THREAD it in.** The quantity is a mean GK x per `(game, period, team)`; a per-frame map is a different estimator, and the cost is provider-DEPENDENT and measured on the four committed slim fixtures: per-frame disagrees with the per-match map on **7.1%** of team-frames (skillcorner) / 2.2% (metrica) / **0.0%** (sportec, gradientsports), while `attacked_goal` is unresolvable for **35.7%** (skillcorner) / 61.7% (metrica) / 0.0% (dense). The spec's headline **78.8%** comes from its own corpus and does NOT reproduce on these fixtures (max 7.1%); its 34.2% unresolvable rate does (35.7%). The design decision stands on the reproduced numbers alone -- a third of team-frames losing direction is decisive, and on dense tracking building once per match costs nothing. So per-frame functions (`lane_control`, `compute_blocking_score`, `compute_gk_influence`, `_voronoi_threat`, `_compute_cover_shadow_dict`) take `goal_map: GoalMap` **required, no default** — a default re-admits the per-frame path at exactly the call sites that forget it — while `add_*` aggregators take `goal_map=None` and build from their own frames, which is correct by construction AND what makes Gate C possible. **(2) Keys are canonical STRINGS** (`canonical_id(1) == '1'`, `canonical_id(pd.NA) is pd.NA`, never `None`): never hold the mappings as a plain dict, because a raw-tuple lookup MISSES SILENTLY — it shipped exactly that way in `scripts/validate_shot_goalmouth_sb.py`, scanning `(k[0], k[1]) == key` and returning NaN for every row. Use `get` (own end) or `attacked_goal` (opponent's end); `attacked_goal` is a REAL lookup of the opponent's entry, never `105.0 - get(...)`, which is wrong on a degenerate map and would say a team attacks the goal it defends. **(3) An unresolvable end REFUSES.** `GoalEndUnresolvedError` (a `ValueError` subclass) is raised by the per-frame functions and caught BY NAME at the `add_*` edge, which emits a NaN row — policy at the edge, and pre-checking at the aggregator is forbidden because it duplicates the exact lookup the callee is about to do. The old sites all failed OPEN (`nan < 52.5` is False → a confident 105.0). **15 breaking public signature changes across `tracking` and `gkdv`, two renames, and a VAEP/tracking retrain trigger**; `add_cover_shadows` is now KEEPER-DEPENDENT on freeze-frame input.

- **Gate B goes vacuous the moment an aggregator is re-keyed off `home_team_id`, so Gate C replaces its DETECTION (ADR-055).** Gate B varies `home_team_id` on fixed frames; once the parameter is gone it skips on `role="unused"`, and the AST population gate cannot see a direction *bool* — so a re-key would delete the only detector for the class it fixes. **Gate C holds the frames FIXED and swaps the MAP**, requiring the columns named in `gate_c_must_move` to move; it reproduces the D3 magnitudes exactly (`share 0.108532`, `closing_min 4.38062`, `closing_mean 4.02205`, `blocking_score 148.83`). Two limits are recorded AT the gate, not inferred: it proves the map is CONSULTED, not that the right accessor was chosen (`get` and `attacked_goal` both move) — correctness lives in `tests/tracking/test_goal_map_consumers.py`; and it is structurally BLIND to any path the registered aggregator does not call. Measured: patching `_closing_time_per_series` back onto a self-built map leaves Gate C GREEN, because `add_gk_influence` never calls it. Name the columns, never assert a bare `moved > 0`. **4.80.0 found the LIMIT of that substitution: Gate C only covers the sites that take a MAP.** Four of D3's six do; the two bool sites (`add_structural_pass`, `add_player_influence`) take none, so a Gate C entry for them would swap an input they never read and **pass by ignoring it** — vacuous by construction, and the completeness gate's `declared − observed` half rejects it. Their detector is a behavioural **direction-invariance** test (`tests/tracking/test_d3_direction_invariance.py`): mirror the FRAMES, hold `home_team_id` CONSTANT, require action-LTR geometry unchanged. It sees the defect AND survives the fix, which neither Gate A (it swaps the id too, restoring the assumed invariant) nor Gate B (vacuous after the fix) can do. Landed RED — observed at `defensive_line_x` 23.25, `packing_made` 6.0, `packing_goal_threat` 4.0. **`gate_c_must_move` is now checked for COMPLETENESS, not just satisfaction**, because a hand-picked subset lets a partial re-key ship green: `packing_goal_threat` is the ONLY witness for packing's back-line site and was nearly dropped as dead, being constant `0` on the base leg — `0` is CORRECT there, and flipping the end moves it to `[4, 1, 1, 1]`. **A detector's liveness is not "does it vary across rows" but "does it move when the thing it detects changes"**; a base-leg constancy screen classifies it identically to `back_n_count`, which genuinely cannot move, and they need opposite verdicts.

- **Direction NEVER comes from team identity, and "unresolved" is a VALUE, not a default (ADR-051 D3 closed, 4.80.0).** `same_id(team, home_team_id)` is correct only while frames are home-attacks-right and **silently inverts otherwise** — a confident wrong answer, which is why it outlived ADR-055 by three releases. **Mechanism is PER SITE, and ADR-055's `goal_map` ruling does NOT generalise:** functions serving BOTH teams take the map (`_defensive_line`, `_packing`); functions serving ONE take a **bool derived from `acting_team_attacks_rtl`** (`_structural_pass`, `_line_breaking`, `_off_ball_runs`, `_player_influence`). The bool is resolved ONCE at the `add_*` EDGE and threaded down — `acting_team_attacks_rtl` is per-ACTION while the sites are per-FRAME geometry, so calling it in situ would be a worse ISP violation than the map it replaces; and at `_player_influence` a map is a category error, since the site reflects a GRID and would collapse a pitch-x to a boolean on its first line. Threading a map into a one-team site also REVERSES the consolidation ADR-042 performed onto the single orientation authority. **`acting_team_attacks_rtl` returns `dtype="boolean"`, and `<NA>` means unresolved** — it previously returned bare `bool` with an internal `.fillna(False)`, so a resolved left-to-right team and an unknown one were THE SAME VALUE and 21 call sites inherited the guess. `.fillna(False)` is still right at many of them; it just has to be WRITTEN, with a reason. Where a guess would fabricate: `_player_influence` blanks its three xT columns and KEEPS `reachable_area*` (measured exactly flip-invariant, max |delta| 0.0 vs 1.17e3 for `off_ball_xt`); `add_space_creation` refuses the whole row, because its two columns are EXCHANGED rather than degraded and half an exchanged pair is not a partial answer. **Consequence: UNORIENTED frames now yield NaN where they used to yield a confident wrong number** (ADR-029's negative control flipped from asserting the defect to asserting the refusal). The contract paid for itself immediately, exposing two live defects: `frames["is_ball"].astype(bool)` — the ADR-019 string-qualifier trap, so `~` selected NO player rows and the resolver fell through for every provider with an object/string `is_ball`, invisible because the fall-through returned all-`False`; and `_unresolvable_direction_mask`, a SECOND hand-rolled resolvability test that repeated that trap AND tested membership with a RAW tuple against a `(game_id, period_id, team_id)` index (ADR-055 rule 2) — **deleted, not repaired**, since the `<NA>` value removes any reason for a consumer to re-derive it. **Two rules the migration produced.** A scope predicate bounds the DEFECT, never the API MIGRATION: the D12 pin (`in scope iff it CALLS same_id/ids_match with home_team_id`) is recall-complete over the defect and structurally BLIND to eleven public per-Series helpers in `features.py` that merely DECLARED and forwarded the parameter — five shipped forwarding into a kernel that had stopped accepting it. **Enumerate a removed parameter by AST signature-diff against the base commit**, which is also what separates them from the ten dead-parameter functions that pre-date the change. And an `add_*` refusal path must build every column the code AFTER the `try` reads, not just the ones it emits: `add_packing`'s `GoalEndUnresolvedError` fallback omitted the internal `line_x`, turning the ADR-055 NaN row into `KeyError`. **A dead parameter is removed WITH the use, or it is never removed** — 4.80.0 also deleted 25 `home_team_id` parameters that nothing read (8 dead at the base commit; the cascade killed 17 more, and the cycle total across all three arcs is 62 signatures), residue from ADR-028/041 re-keys that took out the *use* and left the *signature*, and they had to be driven to a FIXPOINT because the dead ones formed forwarding CHAINS (the obso family existed only to hand the argument to `_precompute_obso_lookup`, which ignored it; removing the sink killed five public signatures above it). Two mechanical traps, both hit: a reads-counter calls a parameter LIVE when its only use seeds an unused closure default (`_htid=home_team_id`), and a call-site sweep keyed on the callee's NAME misses ALIASED forwarding (`_std = tracking.add_xt_gk`), which is how the atomic mirrors were left broken after their target was cleaned. **Verify a fence before removing it, and expect the answer to differ per site:** `add_xt_gk`'s documented "GK-feature-family signature parity" was measurably stale (ADR-055 had re-keyed two of that family, so parity meant matching the one member that still READS it), while `_off_ball_runs_kernel` and `_compute_space_creation_for_action` KEEP their unread copies — the first because its Gate B green IS the standing measurement that the parameter is unread.

- **The goal-relative transform is a 180-degree POINT REFLECTION, not an x mirror (ADR-051 §8b).** `_geometry.to_goal_relative_x`/`_y` map `(x, y) -> (105-x, 68-y)` when the defended goal is at high x, so the two goal ends differ by a ROTATION. Adding a signed-y quantity without routing it through `to_goal_relative_y` reintroduces the defect it fixes: before 4.74.0 there was no y counterpart, so `goal_x=105` was determinant **-1** against an identity at the other end, every RADIAL stayed byte-identical and every BEARING negated (xS 12/27 features, xCross 3/16) — one physical scene scored differently depending which END the acting team attacked. Gated per-feature by `tests/tracking/test_pr5_chirality_gates.py`; the durable evidence is end-invariance on REAL frames (1,360 scenes, feature and prediction delta exactly 0), because the synthetic gate alone would pass if BOTH ends were wrong the same way. **The ghost-GK extractor was the x-ONLY exception until ADR-089** — its own `_ghost_gk._to_gr_x`/`_to_gr_y`/`_to_gr_vx`/`_to_gr_vy` (a separate transform from `_geometry`) now apply the same both-axes point reflection to every signed-y feature + the target `gk_y`, so all bundled ghost-GK variants are re-fit and the ghost serves + gkdv engine consume frame-ready `ghost_x`/`ghost_y` (no consumer re-derives orientation). **`GEOMETRY_VERSION` must be bumped whenever the transform's numeric output changes** — but note its load path only WARNS on mismatch (the fail-closed prong is on pitch dims), so the real protection is chirality + feature_contract, and a change relaxing those two must not assume `geometry_version` holds the line.

- **Reflection goes through the one public seam `silly_kicks/reflection.py` (ADR-045).** A 180-degree point reflection point-reflects POINTS, **negates VECTORS** (`vx`/`vy`/`dx`/`dy`), leaves MAGNITUDES (`speed`) alone and swaps DIRECTION LABELS. Every column declares a `ReflectionKind` in `TRACKING` / `SPADL` / `ATOMIC_SPADL_REFLECTION_KINDS`; `reflect()` serves schema-bearing tables and `reflect_columns()` derived or pre-canonical frames. The historical defect class is columns that an explicit per-site list simply omitted -- `vx`/`vy`/`x_smoothed`/`y_smoothed` are not in `TRACKING_FRAMES_COLUMNS` (preprocess adds them), so they rode through untransformed. `on_unknown` defaults to `"warn"`, NOT `"raise"`: `to_spadl_ltr` runs inside nine converters on frames carrying the caller's unbounded `preserve_native` columns, so a raise has no reachable remedy; fail-closed lives in the CI registry-completeness meta-assertion instead. Consumers who control their column universe escalate via `filterwarnings("error", category=UndeclaredGeometricColumnWarning)`. **Guards on reflection defects must be per-row, never aggregate** -- measured mean biases of -1.1% and -0.002 pass an aggregate check vacuously.
