# Shot-stopping, GK-decision & keeper identity

> On-demand class-2 context (ADR-102-style store). The current terse RULES live in `AGENTS.md`; this file holds the WHY / history / measurement. See the spec `docs/superpowers/specs/2026-09-24-agents-md-restructure-design.md`.

- **Shot-stopping — GK Goals Prevented / GSAA (`shot_stopping/`):** TF-59 PR2 (ADR-085). Event-only per-`(goalkeeper, match)` shot-stopping — the missing GK pillar (all other GK work is distribution/positioning). `compute_shot_stopping(actions, *, psxg_column, defending_gk_column="defending_gk_player_id", defending_team_column="defending_gk_team_id", params=)` → `(samples, ShotStoppingReport)`, one row per `(game_id, keeper)`: `shots_faced`/`goals_conceded`/`psxg_faced`/`goals_prevented` (**≡ GSAA = ΣPSxG − GA**) + `_excl_penalties` companions. **PSxG is INJECTED** (port pattern; silly-kicks ships no xG/PSxG — the `xg_column` idiom); **PSxG-presence IS the on-target gate**. Own goals (`bad_touch`+`owngoal`, ADR-018, excluded by the shot-class `type_id` gate — NO separate mask), blocked (`shot_blocked` True; ADR-046, `pd.NA`=not-blocked), and the shootout (`period_id == shootout_period_id`, default 5) are excluded; penalties reported both ways. **Honest attribution census** — an NA-keeper shot is excluded from per-keeper rows but COUNTED in the conserving `ShotStoppingReport` (ADR-042), never dropped-silent nor misattributed. **Output ids RAW** (consistent with `defending_gk_player_id`; join via `id_compat`, ADR-019); keepers are GROUPED on the CANONICAL id (`canonical_id_series`), raw id emitted via `.first()` — a mixed-dtype keeper id is not fragmented into two split-GSAA rows (byte-identical for a single-dtype provider). Consumes PR1's `defending_gk_player_id` + `defending_gk_team_id`; a `compute_*`, **NOT** an `add_*` (C4 aggregator count stays 33). Event-only: imports `spadl`/`id_compat`/`keeper_identity` ONLY, never `tracking` (AST allowlist `tests/shot_stopping/test_import_allowlist.py`); `ShotStoppingParams` frozen (`for_provider` empty per ADR-009); 8 columns in `feature_glossary` (6th `compute_*` leg) + `NOTICE`. Additive — no VAEP/tracking retrain, no re-materialize. Decision: ADR-085.

- **GK build-up Decision-quality — chosen-vs-available (`gk_decision/`):** TF-62 (ADR-092), the xT-GK "Decision Value" extension. Reframes xT-GK from possession **value** (quarantined — v1 degenerate ADR-024, v2 not construct-validated ADR-036, ~80% team-confounded per the Eyestone collaboration) to **decision quality**: `decision_value = value(chosen) − E[value(available options)]`, which **normalizes out the team-created option set BY CONSTRUCTION** (the keeper is credited only for *which* reachable option they pick). `compute_gk_decision_value(option_set, *, params) → (samples, GkDecisionReport)` + `summarize_gk_decision(samples) → per-(keeper, game_id)`. **Metric:** per GK build-up decision (the `gk_distribution_mask` domain — goal-kick or acting-GK open-play pass) with **≥ `min_options` (default 3)** options, option value `EV(o) = xpass_completion(o) × (1 + max(0, opponents_bypassed(o)))` — the Eyestone-validated completion × progression form, **deliberately NOT `xthreat`** (keeper-degenerate ~0.0005) and **NOT `passing_option_score`** (a safety score, ~0-correlated with value); emitted `decision_value` (chosen − mean; random ⇒ ~0), `sel_efficiency` (chosen / max), `decision_pct` (fraction of alternatives beaten, **ties split half** ⇒ random = 0.5 exactly — the strongest discriminator), `chosen_ev`, `best_ev`. **Hexagonal `OptionSet` port yielding a UNIFORM option-rows schema** (`is_chosen`/`completion`/`opponents_bypassed`/`option_set_source` per candidate) → a **tier-agnostic scoring engine**; **xPass lives INSIDE the reconstruction adapter, never the engine.** The native tier ships `SkillCornerGIOptionSet` (curated `passing_option` rows with native `opponents_bypassed`; **no** packing kernel, **no** goal-map). **The value function is a pluggable frozen-dataclass strategy** (house "pluggable family" idiom, like `xthreat`'s transition family): default `completion_progression`; a non-default selector **RAISES `NotImplementedError`** (xT-/retention-based variants are RESERVED-typed-not-built). **New `providers/skillcorner` GI parse port** `parse_passing_options(gi_events, *, game_id)` — shaping only (ADR-084 `appearances.py` pattern; raw GI loading stays scripts-side); imports `id_compat` + pandas only, never `silly_kicks.tracking`. **Hexagonal:** the NATIVE tier imports only `silly_kicks.id_compat` + pandas/numpy (parsed option rows are injected — it does NOT import `providers.skillcorner`); the RECONSTRUCTION tier imports `silly_kicks.tracking` PUBLIC seams (`compute_packing_metrics`/`action_ltr_goal_map`/linking) + `keeper_identity` + `reflection`, NEVER a `silly_kicks.tracking._*` private (the tracking-consuming-sibling allowlist shape, like gkdv/territorial_defense); **nothing imports `gk_decision`** (AST allowlist both directions, `tests/gk_decision/test_import_allowlist.py`). A `compute_*`, NOT an `add_*` (the 33 action-coupled aggregator count is unchanged); in NO default xfn list; **ships NO `*_xfns`** — the metric never reads `result_id` or any post-contact outcome (value = pre-outcome xPass + geometry), so there is no leakage concern. **Conservation + honest-NaN:** `GkDecisionReport` conserves (`n_decisions_scored + Σ drop_reasons == n_decisions_in`, ADR-042/043) with drops `too_few_options`/`no_unique_chosen`/`chosen_unvalued` — never a fabricated 0. Keepers grouped on the CANONICAL id, raw id emitted (ADR-019/ADR-085). `GkDecisionParams` frozen (`reachability_min_xpass = 0.85` default — the responsive "reachable = high-completion" reconstruction filter, since 0.5 inverts on SB360 (a useless default); `for_provider`-tunable; `min_options = 3`). 5 columns in `feature_glossary` (glossary 394 → **399**) + `NOTICE` (ADR-005/048); a `gk_decision` C4 container. **HONEST LIMIT (load-bearing, in the docstrings/glossary/NOTICE/battery): validated as an INSTRUMENT, NOT player-attributable — per-keeper numbers are NOT a ranking** (the net-of-team signal is real within multi-keeper teams but the transfer-robust keeper-intrinsic component is underpowered/unconfirmed; ranking is a future ADR-009 gated on a crossed keeper+team ICC over a multi-club transfer corpus, same posture as ADR-090) **and value-function dependent** (`completion × progression` penalises deliberately-direct keepers even net of team). Owner-run construct-validity battery `scripts/validate_gk_decision.py` (ADR-052 shards, ADR-037 clean-tree, ADR-056 input contract) **RAN on the full owner-tier corpus** (report `docs/research/gk_decision_construct_validity/`): native **VALIDATED** (906 matches — responsive t≈+27 / discriminating keeper ICC 0.03–0.04 p=0 / net-of-team club-adjusted ICC 0.07 p=0; transfer inconclusive → ranking not licensed); reconstruction fidelity **moderate** (sel-eff ρ ≈ 0.24 / decision_value ρ ≈ 0.25 at the shipped default, both p<0.001). Reported-not-gated, promotes NO default. **Reconstruction tiers (SHIPPED this cycle, ONE commit — native-first is a BUILD ORDER, not two commits; ADR-092 §12.7):** `ReconstructedOptionSet` scores SB360 + full-tracking in ACTION-LTR (match-LTR frames reflected via the ADR-045 seam; chosen = the actual pass end, NEVER snapped; the nearest teammate within `receiver_exclusion_m` of the end is excluded from the ALTERNATIVES only) with the injected `PassCompletionModel` xPass per candidate + the reused `tracking.compute_packing_metrics` progression + the reachability filter. The **promoted public `tracking.action_ltr_goal_map`** constructor (ADR-055 "ONE implementation of the defended goal end" + the ADR-091 per-action-LTR convention) is used here AND by `territorial_defense` (its private copy MIGRATED onto it, duplicate deleted). Conservation gains `no_frame`/`fov_cropped` (ADR-042/077), auto-pulled by `compute_gk_decision_value` from the adapter's `drop_counts()` AFTER `option_rows()` runs (an inline `extra_drops=drop_counts()` would capture pre-run zeros). The battery's **SB360 reachability sweep is a threshold GRID that RECOMMENDS the per-provider threshold**: SB360 inverts at reachability 0.5 (the bundled WC2022 xPass runs generous on SB360, ~95% of reconstructed options ≥0.5, so a 0.5 filter can't bite) and is **responsive at 0.85**, so **the default is 0.85** (0.5 was a useless default); a deeper per-provider xPass recalibration for SB360 remains a future ADR-009 refinement (NOT required for responsiveness — the 0.85 default handles it). Additive — no VAEP/tracking retrain, no re-materialize. Decision: ADR-092.

- **GK-domain keeper identity: use the RESOLVED `player_key`, never raw `player_id` (4.45.0/PR-S112).** SPADL `player_id` is **null for goal-kicks by design** (the taker isn't in the raw event — the reason `acting_gk_from_frames`/the lakehouse goal-kick-taker override exist), and it was 100% null across the whole GK-distribution domain in the gold marts. The resolved Kimball surrogate `fct_action_context.player_key` (99.9% populated on `is_gk_distribution` rows) is the keeper identity. Analysis loaders source resolved fields from GOLD marts, NOT raw `bronze.spadl_actions`. CI guards: `tests/xtgk/test_player_key_contract.py` (pure SQL-source guard + an `@e2e` `player_key ≥99%` data-contract that catches both a wrong-column read and a resolver regression).

- **Keeper identity has ONE resolver, and its native path DELEGATES (ADR-078).** SB360 freeze-frames are anonymous (`snapshot_to_tracking_frames` numbers the rows; no player identity), so every GK-domain aggregator that keys on *which* keeper had nothing to key on and scored NaN. `tracking.resolve_keeper_identities(actions, frames, *, identity, roster=None)` is the ONE resolver: `identity="native"` DELEGATES to the existing TF-13 `defending_gk_from_frames`/`acting_gk_from_frames` (ADR-055 single-source — it MUST NOT re-derive frame-based identity); the `identity="roster"` **event-›roster-›derivation-›NA** precedence ladder is the SB360 new work (a goal-kick actor `player_id` overrides a stale roster starter → a durable `conflict` flag, never a lost warning). It returns a PURE `{(canonical game, period, canonical team) → KeeperIdentity(gk_id, source, conflict, team_id)}` map (game/team keys canonical per ADR-055 rule 2, `period_id` used AS-IS; the value's `team_id` is the keeper's OWN team in its RAW representation — ADR-085; every id compare via `id_compat`, ADR-019) + a conserving `KeeperIdentityReport`; `keeper_id_source` vocab `{event, roster, native, derived, unresolved}` (the `_das.py` `DAS_SOURCE_*` idiom). Under `identity="roster"` a roster that names NONE of the frame's non-ball teams (the synthetic `{0,1}` fallback, a wrong-match roster, or an unbridgeable dtype) RAISES — a roster-APPLICABILITY guard, NOT a `{0,1}` detector, and NOT a mirror of `shape_snapshots` (which silently emits `{0,1}`). The resolver mutates NOTHING; the caller owns placement via two pure helpers: `add_defending_gk_player_id` (action-grain opponent stamp) and **`apply_keeper_identities_to_frames` — the R1 identity→frame bridge** (stamps the resolved real id onto the anonymous keeper rows so `add_pre_shot_gk_position`'s `frame.player_id == defending_gk_player_id` match succeeds; WITHOUT it every SB360 GK-position feature is silently NaN). The bridge is applied on the ROSTER path ONLY — native frames already carry real ids, and stamping the per-`(game, period, team)` consensus would clobber a mid-period sub. ADR-037 confines gkdv to `tracking._das`, so a gkdv-domain consumer reaches this resolver DRIVER-side (scripts may import `tracking` freely), NEVER via a gkdv library import. **Retrain/Hyrum trigger: SB360 GK-domain features go honest-NaN → VALUES; non-GK/non-SB360 byte-identical.** **Promoted to `silly_kicks.keeper_identity` + substitution resolution un-foreclosed (ADR-084, amends ADR-078).** The resolver moved OUT of `tracking/` to the public top-level module `silly_kicks.keeper_identity` — a breaking import move, NO shim (fail-loud at import; ADR-019/ADR-043 clean-break precedent); the `native` path lazy-delegates to `tracking._gk_resolve`, so `import silly_kicks.keeper_identity` stays tracking-free. It gains a `frames=None` **event-only** enumeration path and un-forecloses subs/red-cards via an injected **`KeeperAppearances` port** (`validate_keeper_appearances`/`KEEPER_APPEARANCE_COLUMNS`, one row per `(keeper, period)`, keyed per `(game, period_id, team)`, PERIOD-RELATIVE (ADR-017), `object` ids — DFL/SkillCorner ids are strings) + a shared per-period builder `build_keeper_appearances_from_segments(segments, periods, *, game_id)` (`KeeperSegment`; source vocab `{native_intervals, sub_events, starting_xi, emergency_keeper}`) + interval-granular `add_defending_gk_player_id(actions, keeper_map, *, appearances=None)` (attribution flips at the sub minute; `defending_gk_source` provenance `{appearance, map_fallback, appearance_map_conflict, unresolved}`; BYTE-IDENTICAL and no extra column when `appearances` omitted — until **ADR-085**, which ALSO stamps the authoritative `defending_gk_team_id` on BOTH paths (gold-standard: read from the `keeper_map` VALUE — `KeeperIdentity` gains a raw `team_id` field the resolver populates on both the roster and native paths, so the `keeper_map` is self-sufficient and the defending team resolves even for an opponent that never appears in the actions), so the omit path now carries `defending_gk_player_id` + `defending_gk_team_id` but no `defending_gk_source`, existing values unchanged) + four `providers/<p>/appearances.py` extractors (StatsBomb/Sportec/GradientSports/SkillCorner), each depending on the port + `id_compat` + pandas/stdlib ONLY (AST module-level import-allowlist gate `tests/providers/test_appearances_import_allowlist.py`; never `silly_kicks.tracking`). Additive — no retrain. Decision: ADR-078 (amended by ADR-084, ADR-085).
