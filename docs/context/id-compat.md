# Dtype-safe id comparisons (id_compat)

> On-demand class-2 context (ADR-102-style store). The current terse RULES live in `AGENTS.md`; this file holds the WHY / history / measurement. See the spec `docs/superpowers/specs/2026-09-24-agents-md-restructure-design.md`.

- **Dtype-safe id comparisons are a REPO-WIDE contract (ADR-019, 4.15.0; scope widened 4.53.0/ADR-043).** No consumer anywhere in the package compares ids (action↔frame, action↔action, or against a scalar `home_team_id`/`player_id`) with raw `==`/`!=`, and none merges on id keys without alignment — those silently mis-resolve across dtypes (`Int64(366) == "366"` → False) or raise on a mixed merge key. Originally written as a *tracking-feature-seam* rule; it never was one, and 4.53.0 stopped pretending — the seam is the **public `silly_kicks.id_compat`**, imported by **50 modules across 6 packages** (39 when ADR-043 promoted it; the growth is adoption, re-measured 2026-08-14) (`spadl/`, `vaep/`, `atomic/`, `causal/`, `gkdv/`, `tracking/`; measured by AST over `silly_kicks/`, excluding the module itself). ADR-043 promoted it out of `tracking/_id_compat.py`: five packages were reaching into a private *tracking* submodule, two via function-local imports in `spadl/utils.py` written to dodge a circular import, and a seam ADR-019 makes MANDATORY is public API by definition. **Breaking import-path change, no shim** — the pin fails loud at import, and a shim would have made the promotion cosmetic. Surface: `ids_equal`/`ids_differ` (column-vs-column, NA-safe both-present), `ids_match` (Series/array vs scalar), `same_id` (scalar↔scalar groupby loops), `align_join_keys` (pre-merge, numeric-vs-object only), `restore_id_dtype` (put a kernel-built id column back on its SOURCE dtype where that dtype can represent the result — numpy ints can't hold NA, so a result with unmatched rows stays float). One `_canonical` truth (integral-float collapse; genuine strings pass through). **The both-object fast path is CONTENT-probed, not free** (`_raw_comparable`): an object column of boxed floats raw-compares False against the same id as a string, so dtype alone cannot license a raw `==`. Probe cost ≈15% of the comparison per side, ≈30% for the guard. Opt-in loud guard: public `validate_id_dtypes` + `IdDtypeDiagnosis` (mirrors ADR-017's `validate_time_base`). CI gates: red-first **asymmetric** dtype-invariance gate over every registered `add_*` (`tests/tracking/test_id_dtype_invariance.py`; numeric actions × string frames + reverse, `home_team_id` independent axis) + meta-assertion (gate surface == registered surface) + the **`PUBLIC_ID_SCALAR_ENTRIES` registry** (`tests/invariants/conftest_id_scalar.py`, exercised by `tests/invariants/test_public_id_scalar_registry.py`) + structural de-dup perf guard. **The AST lint is DELETED as of 4.53.0/ADR-043 — deleted, NOT widened, and do not reinstate it.** Widening was rejected on principle, not cost: it was a NAME heuristic (it missed ADR-027's `t != action_team`, and `_ghost_gk`'s `str(t) == home_team_id_norm` because the scalar was renamed), but the unfixable part is that **a safe same-source compare and an unsafe cross-source one are the IDENTICAL AST** — only the scalar's *provenance* separates them, and no syntactic rule sees provenance, so any widening either flags correct code (breeding the exemptions that grew `ALLOW_MODULES` in the first place) or keeps missing real defects. **Complete by ENUMERATION where the lint was incomplete by HEURISTIC** (same idiom as ADR-003's NaN-safety registry and ADR-033's `PURITY_ENTRIES`): the registry derives its surface from `inspect.signature` over the `__all__` exports of `spadl`/`atomic`/`vaep`/`causal`/`tracking`, keyed by defining qualname — **102 functions: 77 exercised directly, 22 delegated** to the `add_*` gate (machine-checked against that gate's registered surface, not asserted in prose), **3 justified non-invariant** — each invoked on a matched scalar, a mismatched-but-value-equal one (`5` vs `"5"`), and a **float** one (`5.0`; not redundant — a naive `str(x)==str(s)` renders identically for ints, so only the float axis exposes it). Two meta-assertions pin it to the public surface in BOTH directions, so a newly-exported id-scalar function fails CI until registered, delegated or justified — the anti-rot property the lint's glob lacked. It caught two live `str()`-comparison defects on its first run that the lint structurally could not have seen. Fixed three latent bugs (object-`is_ball` `~`-no-op ball-as-opponent; `str(5.0)` iterrows-upcast player-influence/cover-shadow mislabel; object-path opponent join-miss) → **VAEP retrain trigger**. **A FOURTH instance of the `str()`-on-a-float-id trap landed in 4.79.0, and it marks the registry's LIMIT: the enumeration is complete over a SURFACE — id-SCALAR arguments of public functions — and `_elastic_sync.py` keyed an internal DICT on `merged["player_id"].astype(str)` while querying it with `str(action_row["player_id"])`.** Every frame set carries a ball row whose `player_id` is NA, which upcasts an integer id column to float, so the lookup stored `"10.0"` and the query asked `"10"`; **every** lookup missed, `dist` fell to the caller's `inf` default, and `elastic_confidence` collapsed to a constant `accel_weight / (accel_weight + proximity_weight)` = 0.6. A miss is indistinguishable from "infinitely far from the ball", so nothing failed loudly — and the SB360 audit recorded the broken state as `identical` → **`works`**, because BOTH legs degraded identically. **Two rules follow.** Reach for `canonical_id_series`/`canonical_id` on any id used as a DICT KEY or join token, not just in a comparison — `astype(str)` on an id column is the defect, and the NA ball row makes the float upcast unavoidable rather than exotic. And a completeness-by-enumeration gate bounds the surface it enumerates, never the defect class: cite it as covering *its* surface, never as covering the trap. ADR-001 preserved (fix lives at consumer seams, not converters). **4.25.0 (ADR-027), retained as the historical case that killed the lint:** it missed a raw `t != action_team` in `_line_breaking.py` ward (a NaN-team crash + an Int64-vs-string silent opponent miscompute on GS) because the operands are not named `*_id`; the behavioral NaN-safety gate (`tests/test_enrichment_nan_safety.py`, NaN-team fixture) caught it. Fixed via `same_id` + a `pd.isna` NaN-route. **Behavioral gates, never a lint, are the backstop** — ADR-043 acted on exactly this by replacing the lint with the enumeration registry above. One site ships DELIBERATELY ungated (the velocity-state defending split, ADR-043 decision 6): its `gk_team` scalar comes from the same frame it is compared against, so no input can distinguish `ids_match` from `==` and no lint could flag it without flagging safe code — recorded so a future reader meets the reasoning instead of "fixing" an untested line.
