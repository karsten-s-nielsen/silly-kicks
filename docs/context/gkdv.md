# GK Deterrent Value (GKDV) & TF-19 probes

> On-demand class-2 context (ADR-102-style store). The current terse RULES live in `AGENTS.md`; this file holds the WHY / history / measurement. See the spec `docs/superpowers/specs/2026-09-24-agents-md-restructure-design.md`.

- **GKDV — GK Deterrent Value** (`gkdv/`): PR-3 of the TF-19 cycle (ADR-043; spec `docs/superpowers/specs/2026-07-12-tf19-gkdv-regate-and-v1-design.md`). Counterfactual valuation of keeper POSITIONING: how much does the actual keeper's position change the attacking team's space and threat versus a league-average "ghost" keeper in the same frame state? **Depends on `silly_kicks.tracking` PUBLIC seams ONLY, never the reverse** — `tracking/` must never import `gkdv/` (pinned by `tests/gkdv/test_import_allowlist.py`; the same rule ADR-037 set for `tracking/_model_eval.py`). **Engine** (`_engine.py`): `build_ghost_frames(frames, *, home_team_id, model=, carrier=, params=)` → `(counterfactual_frames, provenance, report)`, PURE (never mutates `frames`); domain = alive ball ∧ in-possession team attacking ∧ ball within `domain_ball_to_goal_m` of the attacked goal ∧ defending-GK row present; the ball carrier is pinned ONCE and shared by the domain filter and the serving seam. **A NaN/missing ghost is dropped-and-COUNTED, never scored as Δ=0** — a zero delta from a missing keeper reads as "no deterrence" and biases keeper aggregates toward the null (`GkdvReport` conserves exactly: `n_frames_scored + Σ drop_reasons == n_frames_in`); a non-finite served ghost RAISES rather than making the keeper vanish. `counterfactual_frames` is the FULL input with only the defending keeper substituted, so consumers MUST restrict to the scored set via `provenance_to_targets` / `provenance["drop_reason"].isna()` before differencing. **Arms** (`_arms.py`), both in ATTACKER-VALUE units as `actual − ghost` so **negative = deterrent** uniformly: `delta_das` (accessible space; direction is pinned ONCE on the FACTUAL frames and the SAME pinned column feeds BOTH legs — accessible-space otherwise infers direction per period from a team-x mean the ghost displacement perturbs, so the two legs could infer OPPOSITE directions and the difference would not be a counterfactual at all; routed through `get_individual_das` summed per team via the narrow `_das_port.py`, since `get_das` hardcodes `infer_attacking_direction=True`) and `delta_threat_suppression` (`compute_threat_pc(actual) − compute_threat_pc(ghost)`). **Asymmetric keeper modelling, by construction:** the threat arm carries `lambda_gk` (a keeper GAIN applied after the influence field, so keeper position enters via TTI) while ΔDAS is **keeper-BLIND** (accessible-space's column map has no `is_goalkeeper`), i.e. ΔDAS measures relocating a GENERIC player. **`method="spearman"` is a HARD API constraint** enforced in `GkdvParams.__post_init__` — a GK-blind pitch-control configuration is *unrepresentable*, not merely discouraged, and the check lives in ONE place (the arms deliberately do not re-check). **Neither arm accepts a `pitch_control_cache`, and that is CORRECTNESS not performance:** `PitchControlCache` keys on frame IDENTITY (`game_id, period_id, frame_id, team, method, params, ball_position, decompose`) and excludes player positions, so a ghost frame — which carries its twin's identity — would be served the factual leg's surface and every delta would collapse to exactly zero with no warning. Ships **no `add_*` aggregator** (C4 action-coupled count unchanged) and is in **no** default xfn list. §6.4 Layers 0–3 and the xS-arm probe (PR-3b) are NOT in this PR. Attribution: Le et al. 2017 (ghosting); DEFCON-GNN arXiv:2512.10355 (comparator only, not implemented). **Batched arms (`delta_das_batch` / `delta_threat_suppression_batch`, ADR-075):** the single-frame `delta_das` / `delta_threat_suppression` are now THIN WRAPPERS over these — one accessible-space call per leg over a unit's scored frames instead of one per frame (the amortization that makes gkdv viable at production scale: measured ~630× the threat arm's per-frame cost, so DAS-batching is the whole win and there is deliberately **NO vectorized spearman kernel** — measured YAGNI; the threat arm's ~1 ms/frame rests on the already-shipped 4.92.0 pitch-control hoists). `delta_das_batch` pins direction **ONCE over the unit** (more robust than the historical per-frame pin — free because gkdv has no persisted output) and reduces per `(game_id, period_id, frame_id)` with `sum(min_count=1)`, so a non-simulatable frame is honest-NaN, never a fictional 0.0; a whole-batch `DasUnscoreableError` (velocity-less / dead-ball unit) → all-NaN over the keys; a Series `attacking_team_id_by_frame` missing a scored-frame key **RAISES** (never silently NaNs). Both legs must be row-aligned on `(game_id, period_id, frame_id, player_id)` (positional pin/loop; `_assert_legs_aligned`). **The mixed-batch NaN** (a non-simulatable frame NaN'd *inside* a batch, not raised) is a version-pinned accessible-space contract ALREADY relied on by `add_das` (`features.py` single-pass), guarded by `tests/tracking/test_das.py::test_get_individual_das_mixed_batch_nans_bad_frame_not_crash`; a batch-level pre-filter is deliberately DECLINED (the exposure is system-wide, not gkdv-specific — any future fix belongs in `get_individual_das`). The threat arm is **possession-independent** (`compute_threat_pc` takes `attacking_team_id` explicitly, reads no `team_in_possession`), so it always scores where DAS degrades to NaN — the two arms are **independently scoreable** (no symmetric guard). **No retrain, no re-materialize** (gkdv has never produced output), C4-free. **TF-19 A+2 physics-arm instrument-validity + responsiveness probes (ADR-082, reported-not-gated):** `gkdv/_probe.py` ships the dose imposer `impose_defending_keeper_dose` + the POOLED-corpus verdicts `layer0_instrument_verdict` (instrument validity: `arm_unscoreable` short-circuits FIRST on domain `< MIN_DOMAIN_FRAMES` or an all-NaN leg, then void iff the saturating median clears NEITHER `SATURATING_MULTIPLE=5×` the realistic median NOR the placebo p95) / `layer1_responsiveness_verdict` (`gk_med >= PHYSICS_ARM_PROBE_RATIO * max(nd_med, placebo_p95)`, no absolute floor) + `paired_vector_controls` (parent `_model_eval` idiom: ONE defending-team outfielder per control — the NEAREST alone (`nd`) + R SINGLE-outfielder placebos — displaced by the keeper's SAME per-frame vector; `nd_med` and `placebo_p95` are DISTINCT single-player quantities so the `max` is meaningful, NOT a combined R+1-player move). **Layer-0 zero-baseline guard: the `>= 5x realistic` leg requires `real_med > 0`** (ΔDAS is zero-dominated, so `5*0` would vacuously validate a dead instrument; the placebo leg is the backstop) and the reduce RECORDS the pooled medians for auditability. **The verdicts are POOLED-corpus statistics computed in a REDUCE over ALL shards, NEVER per shard** (a per-shard impl reads a thin per-match domain as `arm_unscoreable`; guarded non-vacuously). **`arm_unscoreable` is a FIRST-CLASS verdict, DISTINCT from `instrument_void`** — a thin domain / velocity-less arm is not "broken". **`PHYSICS_ARM_PROBE_RATIO=2.0` is a NEW registration** (NOT `TF19_PROBE_RATIO`/`XS_PROBE_RATIO`, both model-specific). The arm OUTPUT-column → `EXPECTED_DIRECTION`-key bridge is `_ARM_DIRECTION_KEY` / `expected_direction_for_arm` (threat arm column `delta_threat_suppression` → key `delta_threat`; an unmapped arm RAISES). The owner-run driver `scripts/build_tf19_instrument_responsiveness.py` (`for_each` map + pooled reduce + §6.1 `gate_eligible` census + §6.2 per-keeper sign table `named_keeper_signs.parquet` checked against a PRE-REGISTERED `NAMED_KEEPER_PRIOR` (Alisson/Neuer→deterrent, LOCKED before the run + stamped in the artifact; owner-injected `--keeper-names-json` runs the confirmatory `meets_prior` check) + Layer-4 anchoring on the gate-eligible subset) resolves keeper identity DRIVER-side via `silly_kicks.keeper_identity.resolve_keeper_identities` (ADR-078/ADR-055 single-source, promoted per ADR-084 — **the planned gkdv-local resolver was DROPPED**; ADR-037 keeps gkdv → `tracking._das` only). The threat arm is reported `arm_unscoreable` (no loadable `ExpectedThreat`, same constraint as `build_gkdv_arm_values`); ΔDAS is NaN on velocity-less SB360 (ADR-063). No gate flip (`TF19_PROBE_ABS_FLOOR`/`regate_verdict`/`EXPECTED_DIRECTION` untouched), no retrain, no re-materialize, C4-free.
