- **The package version is single-sourced in `silly_kicks/_version.py` (ADR-079).** `pyproject.toml` `[project]` is `dynamic = ["version"]` with `[tool.hatch.version] path = "silly_kicks/_version.py"`, and `silly_kicks/__init__.py` re-exports it — so the wheel/sdist metadata and the runtime `silly_kicks.__version__` derive from ONE literal and cannot drift. Bump that **one** file for a release; `uv.lock` follows from `uv lock` (never hand-edit it), and the metadata follows from hatchling. A typo in the `[tool.hatch.version] path` fails CI at `pip install -e`, so it can't lie dormant until release. Guarded by `tests/test_version_single_source.py` (catches *reintroduction* of a second source, which deletion alone cannot).

- No pandera — schemas are plain Python dicts (`SPADL_COLUMNS`, `ATOMIC_SPADL_COLUMNS`).

- **Metric-family output contracts are single-sourced in `silly_kicks.metric_contracts` (SK-EXPORT, ADR-098).** Every column-emitting metric family (`team_metrics`/`match_outcome`/`shot_stopping`/`gk_decision`/`territory`/`duels`/`restdefense`) exports its `*_METRIC_COLUMNS` + grain `*_KEYS` publicly in `__all__`, and `METRIC_CONTRACTS` (a plain `dict` valued by a `TypedDict` — `keys`/`metric_columns`/`columns`/`column_types`) is the uniform consumer surface for a schema-drift parity guard (one loop, no per-package name/type knowledge). `match_outcome`'s dict metric constant is coerced AT the registry (never changed in the package); `column_types` is populated only for the 5 families whose `*_COLUMNS` is a typed `dict`. **A new metric family must register or `tests/test_metric_contracts.py` fails** (completeness-by-enumeration over packages exporting a `*_METRIC_COLUMNS`; `xsuccess` is the one exempt — a VAEP rating method with no mart column set; `_UNDERIVABLE` empty). `gk_decision`'s grain is `("game_id","keeper")` (the `summarize_gk_decision` grain), NOT `player_id`. Additive — no retrain/re-materialize.

- Config DataFrames (`actiontypes_df()`, etc.) are cached with `@functools.cache`.

- Vectorized dispatch: converters use `np.select` over pre-flattened columns, not `apply(axis=1)`.

- **No rescan-in-loop; use `silly_kicks._frame_index.group_rows` (ADR-068).** A full-table filter inside a per-item loop (`df[df["frame_id"]==fid]`, `df[(df["a"]==x)&(df["b"]==y)]`, or a positional forward scan) is O(n·m) where O(n) is available — the class the 2026-08-24 audit found in 9 sites across `causal`/`tracking`/`spadl`/`scripts` (invisible at test scale, biting only at real-match 0.95–3.2 M rows). Build the grouping ONCE with `group_rows(df, by)` (dtype-safe `groupby().indices` lookup, empty-frame-on-miss, raises on ADR-019 canonicalisation collision) and `.get(key)` per item. The turnover scan (numba-@njit on equality-preserving int codes + pure-Python fallback) and the cover-shadow baseline (setup/core hoist) are the loop-shaped variants of the same fix. All output-preserving (parity test + structural call-count guard per site); **not** a retrain trigger.

- **Item/row-looping primitives carry a sub-quadratic-growth guard (ADR-073).** `call_counter` is scale-INVARIANT (a `calls==1` assertion passes whether the one call is internally O(n) or O(n²)) and benchmarks only MEASURE — so a single-call-internally-O(n²) (the 4.92.0 turnover bug) reaches a lakehouse report, not CI. `tests/_perf_structural.assert_subquadratic_growth(measure_work, *, sizes=(256,1024,4096), max_exponent=1.5)` asserts the empirical operation-count growth EXPONENT stays ≤ 1.5 (deterministic integer counts, small fixtures, every leg — never wall-clock; a quadratic-ish detector, sub-n^1.5 is out of scope). Each adopter supplies a SCOPED counter that isolates the super-linear-suspect op: `rows_scanned_counter` is the rescan proxy (boolean-mask `__getitem__` + `.groupby` + axis-0 `.take`, with a re-entrancy depth guard so `df[mask]`'s internal take is not double-counted); a compiled kernel counts its pure-Python fallback via a counting-array; a constant-work primitive (databricks IN-batch) uses an equality guard. A NEW `group_rows` caller MUST register a guard in `tests/_scale_guarded.SCALE_GUARDED` (meta-assertion enforces the superset of AST-derived callers + degenerate-companion). **A growth fixture MUST scale the GROUP (loop-iteration) dimension, not a within-group one** — a rescan is O(groups×table), so a constant loop count (single game / fixed team set) leaves the regressed rescan LINEAR and the guard passes on the bug (a guard that cannot guard; `assert_subquadratic_growth` passing is necessary, not sufficient — each adopter needs the regression-goes-quadratic proof). Known limit: a new rescan that neither routes through `group_rows` NOR rebuilds a `groupby` in-loop is not force-caught (no reliable AST signal); the AST rescan-lint was considered and DECLINED (ADR-019 lint lesson).

- All `warnings.warn()` calls include `stacklevel=2`.

- ML naming conventions (uppercase `X`, `Y`, `Pscores`) are allowed in `vaep/` and `xthreat/*.py` per ruff per-file-ignores.

- **`detect_input_convention` must require DISCRIMINATING evidence, and DEFER when it has none (ADR-059).** Rule 1 infers `POSSESSION_PERSPECTIVE` from *"every reliable (match, team, period) group attacks high-x"* — but `reliable` is filtered to `n >= min_shots_per_group_medium` (5), so when that filter removes the low-side groups an all-high survivor set is an **artifact of the filter, not a measurement**. Measured wrong on **2 of 36** real Gradient Sports matches, at `confidence="medium"`, against a converter that correctly declares `PER_PERIOD_ABSOLUTE`. Rule 1 now fires only on a configuration an absolute convention could not produce — **two distinct teams reliable in the SAME period**, or **one team reliable across TWO periods** — and otherwise returns `convention=None` with a diagnostic naming why. **Deferral is the safe direction and that asymmetry is the whole argument:** `validate_input_convention` reads `None` as "keep the caller's declared convention", so a false ambiguous leaves output correct and loses only a cross-check, while a false positive contradicts a correct declaration and **raises** under `on_mismatch="raise"`. The second clause **IS** the guard TF-22 added inline to the ABSOLUTE branch in 3.0.1 — both branches now call `_a_team_spans_periods`, ONE spelling; the first clause is deliberately NOT given to that branch, because separating `ABSOLUTE` from `PER_PERIOD` requires observing a team ACROSS periods and a single shared "is this discriminating?" helper would silently loosen TF-22. Rule 1 is what validates statsbomb + skillcorner, so the coverage risk is a SILENT downgrade to ambiguous: `test_statsbomb_raw_detected_as_possession_perspective` guards it on 3 real matches; SkillCorner is guarded by `test_skillcorner_raw_detected_as_possession_perspective` on real public match `1886347` (`PUBLIC_CORPUS` registers TWENTY redistributable SkillCorner matches as of 2026-09-09, a 10→20 second public drop — **visibility is keyed PER MATCH, never on the provider name**, which is the inference `scripts/_corpus.py` exists to prevent and which was made anyway while reading that very file). Its fixture deliberately retains a below-threshold group, so it exercises the sparse-drop shape that caused the misfire and still classifies. **The durable rule: "no counter-evidence" is not evidence — when a FILTER precedes a universal claim, ask what the filter removed.**

- **Block-detection columns are cross-provider + nullable (ADR-046, 4.56.0).** Every converter emits `shot_blocked` + `cross_blocked` (in `SPADL_COLUMNS`, pandas `"boolean"`) via the shared `spadl/utils._blocked_flag` helper with 3-valued semantics: `True`/`False` on shot/cross rows the provider encodes a block, `pd.NA` on non-shot/non-cross rows AND on providers that cannot encode it (Opta unverified; SkillCorner absent — real-data verified both tiers; StatsBomb `cross_blocked` real (opposing-team `Block` via `related_events` + `not block.offensive`, corpus-probed ~510 matches); Sportec/Metrica/kloppy `cross_blocked` infeasible). `cross_blocked` = open-play `cross` only (set-piece crosses `pd.NA` in v1). Additive → **no retrain**; declared `"invariant"` in the ADR-045 reflection registry; atomic-SPADL unaffected (projects to `ATOMIC_SPADL_COLUMNS`). TF-51 prerequisite. GS `crossOutcomeType=="B"` pining-probed on real WC2022; StatsBomb un-deferred via an open-data `related_events`->`Block` probe (~510 matches, R1/R2/R3 pass; `docs/research/sb360_cross_blocked/`).

- **Public enrichment helpers (post-conversion `add_*` family) tolerate NaN in caller-supplied identifier columns.** NaN identifiers route to the documented per-row default (typically NaN-output / False / 0); helpers never crash on NaN input. Decoration with `@nan_safe_enrichment` from `silly_kicks._nan_safety` is the formal opt-in; the CI gate at `tests/test_enrichment_nan_safety.py` auto-discovers decorated helpers. Decision: ADR-003.

- **Public `add_*` enrichers are PURE — input-mutation is CI-gated (ADR-033, 4.32.0).** Every registered `add_*` (the full public surface across `spadl`/`atomic.spadl`/`tracking`/`atomic.tracking` — `__all__` UNION `.features.__all__`, since the 15 `atomic.tracking.features` mirrors export via the submodule, not the package) must NOT mutate any caller-supplied DataFrame/Series/ndarray and MUST return a NEW object. Gate: `tests/test_add_star_purity.py` — one canonical `PURITY_ENTRIES` registry (key `"<package>:<add_name>"`), build-fresh-owned-inputs-once + snapshot-every-array-arg + value-equality + `out is not input`; two meta-assertions pin the surface to the public export (a new `add_*` must register or CI fails). A best-effort AST heuristic NUDGES toward per-branch coverage. **Contributor contract:** any `add_*` that *conditionally* adds columns (a present/absent branch) MUST register ≥2 purity variants (both branches) — the heuristic is a nudge for the one known shape, NOT a guarantee, so the contract is the real backstop. Born from the `add_gk_distribution_metrics` gk_role-present in-place-mutation defect (the gk_role-absent path always copied, so the old column-list guard never caught it). Same PR renamed `pitch_control_at_action`→`pitch_control_at_target` (function aligns with its emitted `pitch_control_at_target__<method>` column base, unchanged since 4.31.0) — note the lakehouse keeps its own DEFCON `pitch_control_at_action` mart column (different semantics; not silly-kicks').

- **Every band needs a test from BOTH sides, and every counterfactual needs a non-vacuity assertion that it actually moved something.** A gate that only asserts "value is inside the band" passes identically when the value is inside the band *and* when the computation silently produced nothing; a counterfactual test that only asserts `delta == expected` passes when both legs are secretly the same object. Assert the failing side too (a mutation that SHOULD move the number out of the band), and assert the counterfactual measurably differs from its factual twin. **Four silent-null defects in this codebase share exactly one shape** — the kloppy tracking y-inversion (ADR-031), the fabricated `flat_zones` grid origin (ADR-036/PR-S113), the identity-keyed `PitchControlCache` served to a moved-GK counterfactual (ADR-043), and a mirrored external-provider event frame — each produced a plausible number from a computation that had not happened. None was caught by a one-sided assertion; each was caught by a test that checked the other side. Precedents: `test_deep_zone_gate_nan_invariance.py`'s non-vacuity meta-assertion (its first draft compared an all-zero surface to an all-zero surface), the `test_ghost_gk_mirror_invariant` off-centre probe (ADR-040 strengthened it because the central probe moved ~0.1 m and was vacuous), and `tests/gkdv/test_arms.py::test_unpinned_implementation_would_measurably_differ`.

- **Private modules can have downstream consumers.** Before renaming, splitting or relocating any `silly_kicks/**/_*.py`, check `docs/PRIVATE_CONSUMERS.md`. Path pins fail **silently** — a renamed module degrades a consumer's guard with no `ImportError`.

- **Academic attribution discipline.** Every new feature implementing a published methodology gets an entry in the `NOTICE` file's "Mathematical / Methodological References" section. Cross-link from per-feature docstrings via `See NOTICE for full bibliographic citations.` Mirrors the lakehouse pattern. Decision: ADR-005.

- **Aggregator column liveness is CI-gated (non-NaN AND non-constant).** Every registered `tracking` `add_*` (the full `__all__` surface, jersey helper included) must produce non-null values for every column it ADDS, and every float METRIC column with ≥2 observed values must carry >1 distinct value, on the multi-domain fixture in `tests/tracking/test_aggregator_column_liveness.py` (5 action windows: pass / shot / GK goalkick / attacking-third / wide-area; actor carries the ball through a final-step kick; per-window velocity/layout/GK/kick variation; event clocks jittered off the frame grid). A meta-assertion pins the gate surface to `tracking.__all__`, so a NEW `add_*` must wire a liveness entry or CI fails. Constants BY DESIGN go in the `STRUCTURAL_CONSTANTS` registry with a justification + dedicated invariant test — never silent exclusions. The registry is currently EMPTY: the space-creation structural zeros were RETIRED from the contract (4.24.0), and the dead `pitch_control_at_ball__spearman` near-ball-PPCF degeneracy was RETIRED + replaced by the LIVE `pitch_control_at_target__spearman` (sampled at the action destination + ADR-028-reprojected; 4.31.0, ADR-032). Born from the TF-41 hard-coded-NaN `_opponent` defect (ADR-026; non-constant added 4.24.0 after `space_destroyed_m2 ≡ 0` showed non-NaN alone is insufficient).

- **Geometry constants are canonical and CI-enumerated (ADR-050).** Use `spadlconfig.penalty_area_half_width` / `penalty_area_depth` and the two frame-explicit predicates `_geometry.in_penalty_area_absolute(x, y, *, attacked_goal_x)` / `in_penalty_area_goal_relative(gr_x, y)` -- two entry points because the call sites differ on FRAME, not just strictness, and `goal_x` already means the *defended* goal in `_geometry` (same name, two readings, an 88.5 m error). The goal-relative form takes no goal argument so the ambiguity cannot re-enter. **`_ghost_gk`'s 40.3 divergence is CLOSED** -- it read its own 40.3 while its weights were fit on it, the contract turned that into a load-time raise rather than a deletable comment, and the ghost re-fit cycle discharged it; predicate, declaration and constant now all read `spadlconfig`. The domain rule has ONE expression: the scalar `in_penalty_area_goal_relative` delegates to `in_penalty_area_goal_relative_array`, and `in_penalty_area_absolute` delegates to the scalar, so all three entry points evaluate one body (`bool()` at the scalar seam is load-bearing -- `np.False_ is False` is False and two tests assert with `is`). **KNOWN LIMIT, measured: the contract catches a changed CONSTANT and is BLIND to a changed predicate SHAPE.** A `gr_x >= 0` clamp leaves `_feature_contract_block()` byte-identical -- it declares no new constant and the probe frame carries no behind-the-line player -- so `load()` stays green while real-data values move. Adding a bound, flipping strict to non-strict, or changing a fold is a manual-discipline change; do not reason "the contract will catch it if it matters". Rule: **a module-level constant exists iff something in that module reads it** -- aliases would satisfy the enumerator vacuously. `tests/tracking/test_geometry_constant_enumeration.py` AST-walks the extractor modules and requires every geometry constant either declared in a model's contract or `_EXEMPT` with a reason.

- **"Nothing there" is not "nothing VISIBLE there" (ADR-055).** `tracking/_visibility.py` ships `point_observed` (`bool | None` — `False` is a CLAIM, and a missing polygon supports no claim), `region_observed_fraction` (an `(M, 2)` POLYGON, never a bbox: a bbox can only OVER-report coverage for a triangle, i.e. fabricate observation) and `add_visible_area_coverage` emitting `visible_area_fraction` + `visible_area_source` over the closed `{observed, no_polygon, degenerate_polygon, unlinked}`; the fraction is NaN for every non-`observed` token — **never 1.0, never 0.0**. Sutherland–Hodgman needs a convex CLIP, so the provider polygon is always the SUBJECT and the REGION is the clip — that puts the convexity requirement on the argument the caller constructs and lets a concave region be REFUSED rather than silently mis-clipped. Primitives live in the neutral `silly_kicks/_polygon.py` (the `id_compat` / `reflection` position) because `providers/` has no runtime dependency on `tracking/` and adding one would invert the port layering. `visible_fraction` → **`observed_pitch_fraction`**, now CLIPPED and NaN-on-degenerate (the polygon VERTICES stay unclipped — ADR-054 D5 is about the vertices). **The PRODUCER must honour the same split (4.77.1):** `shape_snapshots` emits a `visible_area` row whenever something WAS published, even when it converts to nothing usable — dropping it collapses `degenerate_polygon` into `no_polygon`, which the seam exists to keep apart, and it shipped that way (a published 2-vertex polygon read as "nothing published"). `polygon_to_spadl` therefore returns an empty `(0, 2)` on a malformed odd-length list rather than raising mid-corpus; the empty array is below `MIN_VERTICES` and reads as degenerate. The 4.77.0 note declining this on "fail-loud vs degrade" grounds was **wrong** — it enumerated crash and silence while the seam already shipped the honest third answer. **A scope decision defended by a false dichotomy is still a scope decision;** the tell is a justification appealing to a principle the module's own vocabulary contradicts. Wiring coverage INTO the count features is deliberately NOT done *by changing existing values* — it is done as an OPT-IN companion instead (ADR-062, below), which keeps the existing columns byte-identical and leaves the partial-observation policy to the consumer (ADR-009).

- **A liveness gate's FIXTURE needs its own precondition test (ADR-032 idiom, re-learned 4.74.0).** A gate is only as good as the rows it scores, and two silent fixture defects made the xS liveness gate score noise for three cycles: rows ~3x outside the model's trained domain (so it measured extrapolation) and a generator that zeroed `vx`/`vy`, pinning ball speed to ONE value — the same degeneracy PR-S118 found in the xCross fixture and left in the xS one. Two statistically equivalent models scored AUC 1.0 and 0.0 on it. When a gate asserts a behavioural property, pin the fixture's validity separately (in-domain, no constant feature, enough rows), and assert only what the guarded thing actually does — the retired version asserted `near > far`, which BOTH models contradict (`corr(r,p)` +0.89 and +0.94).

- **A feature that reads its own action's `result_id`, or any post-contact outcome, ships with NO `*_xfns` factory -- or stays out of every default xfn list.** Enforced by an auto-discovering absence guard anchored on the transformer NAME, so renaming a factory cannot silently disarm it. TF-48 shot goalmouth (ADR-030) and TF-51 defensive credit (ADR-047, ADR-049) ship no factory at all; `packing_xfns` (ADR-039) and `off_ball_run_value_xfns` (ADR-042) exist but are in no default list. Opting a leaky factory into a default list is a HybridVAEP-class correctness break, not a tuning choice.

- **Public warning categories are deliberately separate, never one umbrella.** `SyntheticEPVWarning`, `IgnoredSurfaceInputsWarning`, `RunValueCoverageWarning`, `MissingFeatureContractWarning`, `UnverifiableFeatureContractWarning`, `OrientationUnresolvedWarning`, `GhostClampWarning`, `UndeclaredGeometricColumnWarning`. None subclasses another (test-enforced): silencing a routine notice must never silence genuine misuse, and escalating the missing-contract case must never turn every benign probe extension into a hard failure. CI escalates `SyntheticEPVWarning`, `IgnoredSurfaceInputsWarning` and `MissingFeatureContractWarning` only -- `OrientationUnresolvedWarning` is NOT escalated, and escalating it remains an open decision rather than a guarantee to rely on.

- **Policy lives at the edge, never in the shared engine.** The ghost pitch clamp sits at the serving seam, not in `predict_mean` (whose exact-boosted parity contract must stay clean); the restart geometry tripwire sits at the `add_restart_coordinates` edge, not in `resolve_restart_geometry`; the per-type base-rate switch sits in `compute_xt_gk`, not in `predict_proba`, which stays a pure scorer. A guard that changes numbers belongs where the decision is made.

- **The library ships RAW primitives; composites, archetypes and rankings stay consumer-side (ADR-009).** TF-45 emits `structural_lbs` / `structural_sgm` / `structural_sdi`; the TIV z-norm composite, the K-means archetypes and the delta-TIV/cumulative rankings are frozen-exogenous consumer concerns.

- **Feature columns are documented in `silly_kicks/feature_glossary.py`, and coverage is CI-gated (ADR-048).** Every derived column carries a `FeatureColumn(name, definition, unit, emitting_module, attribution, higher_is_better)` record; `emitting_module` is the metric's HOME compute module (`_packing`, `_obso`, ...), not the `features.py` monolith where the public producer happens to be defined. `describe_level(z, *, higher_is_better=True)` lives separately in `silly_kicks/reporting.py`, because direction is glossary metadata and the caller supplies it -- so a lower-is-better metric is never mislabelled. A new `add_*` or `*_xfns` must document its columns or the coverage gate fails; the load-bearing completeness dependency is the `add_*` / `*_xfns` NAME SHAPE.

- **The C4 model (`docs/c4/`) is pinned to the code.** Subpackages are derived from the package tree by a completeness gate -- nothing else pinned the diagram to the code, which is how a public subpackage went unmodelled for five releases. A new action-coupled `add_*` aggregator changes the documented count.

- **A coverage denominator must never masquerade as a tactical signal (ADR-042).** Mean disruptive run value divides by `n_valued_disruptive_runs`, NEVER `n_disruptive_runs`, or tracking coverage reads as tactics. A runner absent from the linked frame keeps `run_value` NaN and keeps its ROW (`RunValueCoverageWarning`) -- never a fabricated `0`. Same reasoning behind emitting `peak_speed_source` as DATA: the all-NaN-speed fallback under-states peak speed, so sparse providers legitimately LOSE runs and the consumer has to be able to see that.

- Runtime: pandas, numpy, scipy, scikit-learn (no pandera, no multimethod)
