# Expected Threat (xT)

> On-demand class-2 context (ADR-102-style store). The current terse RULES live in `AGENTS.md`; this file holds the WHY / history / measurement. See the spec `docs/superpowers/specs/2026-09-24-agents-md-restructure-design.md`.

- **xT** (`xthreat/`): Expected Threat. SK-xT-1 (4.17.0, ADR-021) refactored the `xthreat.py` module into a package with a house-style **pluggable transition family** (string-dispatch + frozen-dataclass params, NOT ABCs): `ExpectedThreat(method="singh_counts"|"kde_smoothed", params=, l=, w=)`. The `singh_counts` default is **byte-identical** to the classic socceraction grid (frozen-oracle parity gate at `tests/xthreat_legacy_reference.py`); `singh_transition_matrix` is vectorized (`np.add.at`, byte-identical). KDE-smoothed transition (`kde_smoothed_transition_matrix`, Silverman-1986 bandwidth, adaptive per-source-zone); `KDEParams.bandwidth=1.0` (pure Silverman) is a conservative default — the held-out-NLL optimum is **corpus-size-dependent** (~1 on a 64-match sample, ≥4 on an 8.9M-action mart), tune via the evaluator. `GridSpec` first-class variable resolution (pitch dims stay in `spadlconfig`). Standalone `value_iteration` (raw-diff convergence — monotone-from-below, do NOT "fix" to abs; optional `max_iter`). Held-out **transition-model** NLL evaluator (`holdout_split` `game_id`-keyed, `compute_holdout_nll` pure, `compute_holdout_nll_per_group`) — NOT an xT-quality metric. KNN/conditional deferred (pre-publication); lakehouse `XTGrid` declined (keep raw `.xT`). Additive — no Singh-path change, no retrain trigger (TF-24 calibration `FrozenXt` untouched). Lakehouse-proposed; attribution Singh 2018 / Silverman 1986 / Salimi 2026 (pre-pub). Decision: ADR-021. **SK-xT-2 (4.19.0, ADR-022)** wires xT into VAEP as an opt-in, frame-free feature: `vaep.features.xt_xfns(*, model)` + atomic mirror `atomic.vaep.features.xt_xfns` emit `xt__<model.method>` per gamestate slot (ADR-005 §8 naming), caller-supplies-the-fitted-model (fail-closed; `str`/`None`/unfitted raise; `ExpectedThreat` imported `TYPE_CHECKING`-only — duck-typed at runtime, **no new runtime edge**). In **no** default xfn list (additive — opting it in is a self-triggered VAEP retrain; guard test enforces absence). Atomic reuses `model.rate()` **unchanged** (no `_rate_cells` extraction — SK-xT-1 parity gate untouched) via a synthesized standard-SPADL frame + **type-aware** `result_id` (dribble intrinsic since dribbles are never followed by `receival`; pass/cross success iff next atom is `receival`); maps slots by composite `(game_id, period_id, action_id)`; period-last pass/cross → NaN (inherent atomic edge). Cross-representation symmetry verified by a geometry-keyed oracle (NOT `action_id` — `convert_to_atomic` renumbers it) + a dribble keystone gate on the committed WC2018 fixture. Bundled-grid variant reserved via a typed `str` door (ADR-011). C4-free. **SK-XT-SER (4.121.0, ADR-100): `ExpectedThreat.{to_dict,from_dict,save,load}` — a JSON (pickle-free) cross-process serialize seam.** `to_dict`/`from_dict` are the primitive (serialize `l`/`w`/`eps`/`method`/`params` + the 5 fitted arrays + `heatmaps`; `grid` derived in the ctor; `from_dict` reconstructs BIT-IDENTICALLY, bypassing `fit`); `save`/`load` are thin JSON-file wrappers over them (single serialization source). **Raw-orientation VERBATIM (ADR-041): `xT` is stored y-inverted and round-trips with NO normalize/transpose on either leg**, so `rate`/`destination_profiles` stay bit-identical (functional-equivalence gate). **Fail-closed `from_dict`: unknown/missing `format_version` (≠1) → `ValueError` FIRST, missing key → `KeyError`, method/params mismatch → `TypeError`, all-zero `xT` → `NotFittedError` (via `require_fitted_xt`); `to_dict` on an unfitted model raises.** **NO SHA256 sidecar on `save`/`load`** — the ADR-011/040/050 SHA/chirality machinery is for WHEEL-BUNDLED artifacts (pip-user tamper-detection); `ExpectedThreat` is consumer-fitted + consumer-persisted, so the consumer owns integrity (ADR-100 Option D). Additive — no VAEP/tracking retrain, no re-materialize, C4-free; requested by the lakehouse ExT-v2 fold. **SK-XT-COUNTS (4.123.0, ADR-102): `ExpectedThreat.fit_from_counts(*, shot_counts, goal_counts, move_counts, transition_start_counts, transition_counts, params=None)` — a distributed counts-based fit** so a producer fits an xT grid from one Spark `groupBy` (per-zone count sums, ADDITIVE across competitions) instead of pulling the corpus to a driver. Builds the 4 matrices from raw integer counts then runs the IDENTICAL `value_iteration`; numerically identical to `fit(actions)` on the exact aggregates. **The count→matrix logic is SINGLE-SOURCED: `_scoring_prob`/`_action_prob`/`singh_transition_matrix` refactored into pure `_*_from_counts` cores + thin from-actions wrappers, both `fit` and `fit_from_counts` call the same core → `fit` byte-identical (SK-xT-1 oracle gate).** **THREE move aggregates (the crux): `move_counts` (valid START, feeds `_action_prob`) ≠ `transition_start_counts` (valid START+END, the Singh row denominator) ≠ `transition_counts` (SUCCESSFUL start+end, the numerator)** — `_action_prob` masks NaN-start only, `singh` `dropna(start,end)` first, so a single move-count silently diverges on a valid-start/NaN-end move (named boundary fixture). **NO smoothing/prior** (raw `_safe_divide`). Public zone-binning: `zones_of`/`flat_indexes_of` (the y-INVERTED `(w-1-zone_y)·l+zone_x`, ADR-041) + `MOVE_TYPE_NAMES`/`SHOT_TYPE_NAME` class attrs so a producer replicates sk's binning+filters exactly. Singh-only (KDE `params` raises); shape-guarded. Additive — no VAEP/tracking retrain, no re-materialize, C4-free; requested by the lakehouse ExT-grid producer (P2 recompute).

- **`ExpectedThreat.xT` stores rows y-INVERTED; `rate()` compensates and `interpolator()` does NOT (ADR-041).** `xthreat/_physical.py` is the ONE place that inversion is neutralized: `physical_grid(model, grid_x, grid_y)` resamples onto a **consumer-supplied** grid in ascending-y physical orientation (pass the consumer's own grid; do not invent one), `values_at_points` gives exact NaN-tolerant `rate(use_interpolation=False)` semantics, and `require_fitted_xt` is the single fitted-model guard. Never multiply a raw `interpolator()` output into a physical surface. `compute_threat_pc` REFUSES an unfitted xT -- it used to return `0.0`, so any caller persisting a threat column persisted structural zeros that look like a measurement.
