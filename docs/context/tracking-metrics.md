# Tracking-consuming counterfactual metrics

> On-demand class-2 context (ADR-102-style store). The current terse RULES live in `AGENTS.md`; this file holds the WHY / history / measurement. See the spec `docs/superpowers/specs/2026-09-24-agents-md-restructure-design.md`.

- **Territorial defense — SB360 removal counterfactual (`territorial_defense/`):** TF-54b (ADR-090). The tracking-consuming counterfactual counterpart of `territory`: per-`(defender, match)` valuation of how much a defender's *positioning* suppresses the attacking team's threat on StatsBomb-360 freeze-frames, via a **model-free removal (marginal-contribution) counterfactual**. `compute_territorial_defense(actions, frames, *, xt, params)` → `(samples, TerritorialDefenseReport)`. **Mechanism:** `a_threat_suppressed = compute_threat_pc(counterfactual) − compute_threat_pc(actual)`, where the counterfactual is the factual frame with **one defender row REMOVED** (pitch control re-partitions the vacated space to the remaining players — Fernández–Bornn marginal player value); replacement (ghost) DEFERRED. **Sign convention: attacker-value units, `positive = threat suppressed`** (INVERTED from gkdv's "negative = deterrent"; the probe direction registry encodes `positive`). **Two arms:** **Arm A** (`a_threat_suppressed`) is action-anchored + **identity-EXACT** via the actor bridge, over the acting defender's own defensive actions (tackle/interception/clearance, `type_id ∈ {9,10,18}`); **Arm B** (`b_threat_suppressed`) is hull-based + attribution-**approximate** (nearest-to-target defender removed; single-sources the v1 `territory` trimmed hull via the newly-exported `build_trimmed_hull`/`Hull` with a configurable `own_half_max_x` matching `territory`), reporting `b_attribution_slippage` (the rate the position-chosen contesting defender is **NOT** the hull-owner D — attribution ERROR, **lower = tighter**, honest-NaN when identity is un-measurable on anonymous SB360 frames, NEVER a fabricated 0 per ADR-027). **Actor bridge:** SB360 freeze-frames are anonymous (`snapshot_to_tracking_frames` numbers the rows), so `is_actor` is re-plumbed through the StatsBomb port + `snapshot_to_tracking_frames` as a **snapshot-only** extension column (base `TRACKING_FRAMES_COLUMNS` unchanged) and `silly_kicks.keeper_identity.apply_actor_identities_to_frames` stamps the acting player's real id onto the anonymous actor row (shared home; ADR-078 bridge pattern, ADR-084 module home; independently useful — the eyestone GK build-up-decision metric is a concrete second consumer). Hexagonal — imports `silly_kicks.tracking` PUBLIC seams only; **nothing imports `territorial_defense`** and `tracking` never imports it (AST allowlist `tests/territorial_defense/test_import_allowlist.py`, whole-tree sweep incl. relative imports). A `compute_*`, NOT an `add_*` (C4 count stays 33); in NO default xfn list. **`pitch_control_method="spearman"` is a HARD `__post_init__` constraint** (a GK-blind method is unrepresentable, mirroring `GkdvParams`); the arms accept **no `pitch_control_cache` — that is CORRECTNESS not performance** (ADR-043 landmine: `PitchControlCache` keys on frame IDENTITY excluding player positions, so a removed-defender counterfactual carrying its twin's identity would be served the factual surface and every delta would collapse to exactly 0 with no warning). **Conservation + honest-NaN (ADR-042/ADR-027/ADR-055/ADR-063/ADR-077):** a removal on a defender-depleted frame (`< min_defenders_after_removal`, default 1) is dropped-and-counted `removal_undersupported` (a 0-defender surface degrades to attacker-controls-all — an upward-biased outlier, NOT a fabricated 0); an unresolvable goal end → `unresolved_geometry` honest-NaN (`GoalEndUnresolvedError` caught at the arm edge, ADR-055). **Goal resolution is per-frame from the action-LTR CONVENTION, dual-mode via `frame_convention` (ADR-091):** SB360 freeze-frames are per-acting-team-LTR (ADR-028), so a per-MATCH `resolve_defended_goals` (mean GK x) is bimodal and scores ~0 — the DEFAULT `frame_convention="per_action_ltr"` builds a per-frame `action_ltr_goal_map` (the acting team attacks x=105; GK-INDEPENDENT/FOV-proof, so keeperless frames still score), while `frame_convention="match_ltr"` reuses the per-match `resolve_defended_goals` for continuous-tracking-derived (home-attacks-right) frames. The compute OWNS the convention via a `goal_map_for` factory; `classify_arm_a_domain`/arms are convention-agnostic. **A convention-faithful `make_per_action_ltr_fixture` + a two-sided regression are load-bearing: the match-oriented e2e/audit fixtures masked a metric that scored 0 on real SB360.** An under-observed local region → `fov_cropped_local` (SPEC-02 local-completeness gate); the removal-depletion guard applies to BOTH arms, and `TerritorialDefenseReport` conserves BOTH — Arm A over its domain (`n_frames_scored + Σ drops == n_frames_in`) and Arm B over its qualifying `(defender, in-hull-pass)` pairs (`arm_b_n_scored + Σ arm_b_drop_reasons == arm_b_n_in`). Threat suppression is a Tier-1 dimensionless LIFT at zero velocity (ADR-063). ids canonical via `id_compat` (ADR-019). `TerritorialDefenseParams` frozen (`for_provider` empty per ADR-009). **DEMOTED to experimental (4.112.0 commit 2, ADR-090 construct-validity below):** the public metric surface is REMOVED — out of `territorial_defense.__all__` (now empty), out of `feature_glossary` (glossary count reverts −3 → 394), and out of the SB360 boundary audit (`BOUNDARY_ENTRY_POINTS`, `NOT_EXERCISED_BUDGET` 50→46); the metric + arms + engine are retained as PRIVATE modules (`._compute`/`._arms`/`._engine`, imported by the `scripts`/tests consumers from the private path) for the replacement-ghost redesign, mirroring the TF-60 Layer-3 arms (ADR-089). The `territorial_defense` C4 container stays (the code exists; no analyst-facing edge) and `NOTICE` keeps the attribution for the retained code. **HONEST LIMIT (load-bearing): the metric is NOT construct-validated (battery verdict below), and per-defender numbers are NOT player-attributable** — the marginal-removal delta is **team-conditioned by construction** (vacated space re-partitions to teammates); in a single-tournament / national-team corpus (WC2022 + 30 licensed SB360) the defender-vs-team confound is **unidentifiable** (one player = one national team → zero cross-team defender observations), so **per-defender numbers are NOT a defender ranking** and the elite-defender ("Van Dijk") prior is elite-defender/elite-team **collinear** (FACE-VALIDITY, not attribution). Ranking is a future ADR-009 gated on a crossed defender+team **ICC** over a **multi-club transfer** corpus. The owner-run construct-validity battery (`scripts/validate_territorial_defense.py`; ADR-052 shards, ADR-037 clean-tree, ADR-056 input contract, locked pre-registered prior) **RAN on 321 SB360 matches (`docs/research/territorial_defense_construct_validity/`) and returned a NEGATIVE verdict — Layer-0 `instrument_void` + Layer-1 `not_responsive` (pooled dose median 0.0 vs single-player placebo p95 0.137; named-defender face-validity 2/3 at noise-level magnitudes)** — so per the standing rule (*a metric that fails validation must not ship as that metric*) the public metric surface is REMOVED (demotion above); **reported-not-gated** (promotes NO default). Additive — no VAEP/tracking retrain, no re-materialize. Decision: ADR-090 (per-action goal resolution + `frame_convention` amended by ADR-091).

- **Positioning — prescriptive defensive-positioning optimiser + measured positioning gap (`positioning/`):** TF-56 (ADR-104), from databallpy `optimization` (Oonk & Shah, MIT). The **PRESCRIPTIVE sibling of GKDV's descriptive counterfactual**: a pure simulated-annealing solver `optimise_positions(frame, *, movable, objective, constraints, optimizer=None, seed=None) -> OptimizeResult` searches for the best REACHABLE defensive shape under a composable objective + per-player TTI reachability, plus a measured `compute_positioning_gap(frames, *, xt, movable=None, objective=None, params) -> (samples, PositioningReport)` at **frame/team grain**: `positioning_gap = threat(actual) − threat(reachable optimum) ≥ 0` per defensive frame. **Objective-agnostic solver behind `Objective`/`Constraint`/`Optimizer` protocols (no God-object); the shipped glossaried column freezes to ONE canonical `ThreatObjective`** (`compute_threat_pc`, spearman, GK-aware `lambda_gk`, `goal_map`-oriented) — `WeightedSum`/`CappedContribution`/`PressureObjective`/`DasObjective` are EXPLORATORY (a weighting IS a tactical choice; consumer-side per the raw-primitives convention, ADR-110). **`gap ≥ 0` by PATH IDENTITY, not two independent calls:** `OptimizeResult.actual_score` is the SA incumbent-0 evaluation (the SAME code path as `best_score`), and the metric takes `threat_actual = opt.actual_score`. **DETERMINISTIC:** the RNG is seeded from `(game_id, period_id, frame_id)` via `hashlib` (process-independent, never Python's salted `hash`), so the column is a pure, CI-golden-able function of inputs. **`ThreatObjective` computes the surface DIRECTLY, NEVER `PitchControlCache`** (ADR-043 identity-key landmine — a moved-defender frame would be served the factual surface and every gap would collapse to 0; non-vacuity-gated). **`ReachabilityConstraint`** = `compute_tti(REAL pos+vel, candidate) ≤ max_reach_seconds`, evaluated against the player's REAL state (never a mid-search intermediate); frozen `ReachabilityParams(max_reach_seconds=0.7, reaction_time=0.1, max_acceleration=7.0=SpearmanParams)`; an infeasible candidate is rejected at the SA proposal, never scored. **Movable default = the defending team's OUTFIELDERS; the GK is EXCLUDED from `movable`** (keeper positioning is GKDV's domain) but stays a FIXED agent contributing via `lambda_gk`. **`pressure_on_target(frame, player_id, *, method, params) -> float` (NEW public `tracking` primitive) REUSES `pressure_on_actor` via a synthesized one-row action — `add_pressure_on_actor` is UNTOUCHED** (no delegation refactor, no new golden; the existing `tests/tracking/test_pressure_*.py` remain the guard). **Domain (per-condition census, spec §6):** alive ball ∧ opponent-in-possession ∧ ball within `domain_ball_to_goal_m` (35.0 = gkdv's `_DOMAIN_BALL_TO_GOAL_M`) of the DEFENDED goal ∧ two-team frame ∧ velocity present ∧ ≥1 movable; 1 fps downsample; each drop attributed to its own `positioning_gap_source` token (`excluded_not_two_teams` is DISTINCT, not folded into `excluded_out_of_domain`); `PositioningReport` conserves (ADR-042); honest-NaN, never a fabricated 0. **Velocity Tier-3 (ADR-063):** a declared-velocity-less frame → `velocity_unavailable` excluded-and-counted; undeclared-missing `vx`/`vy` → RAISE (fail-loud). **SB360 is OUT of v1** — the blocker is FOV partial-observation of the shape + from-rest reachability (NOT "no DAS"; the threat objective is Tier-1 at zero velocity). Oriented via `resolve_defended_goals` (ADR-055), never team identity. **Hexagonal:** imports `silly_kicks.tracking` PUBLIC seams + `id_compat`/`reflection`/`spadl.config` ONLY, never a `tracking._*` private, never `silly_kicks.xthreat` (`xt` INJECTED, the port pattern); **nothing imports `positioning`** (AST allowlist both directions). A `compute_*`, NOT an `add_*` → the action-coupled aggregator count STAYS 33; in no default xfn list; **no `*_xfns`** (frame-grain, reads no gamestate/outcome); +1 C4 container. Frozen params (ADR-009, `for_provider` empty). Canonical-id grouped (ADR-019). `metric_contracts` registers `POSITIONING_METRIC_COLUMNS` + grain `("game_id", "team_id")` (ADR-098). Glossary +3 (`positioning_gap`/`threat_actual`/`threat_optimum`, `higher_is_better=False`). NOTICE: Oonk & Shah / Le et al. 2017 / Spearman / Bekkers / Pleuler TTI. **PERF (MEASURED, not estimated): ~1.8 s/scored-frame @ 2000 SA iters** (`ThreatObjective` recomputes a full pitch-control surface per iteration — the cache is refused by design), so the bounded velocity-bearing corpus is feasible and the coarse-grid-search lever is NOT v1 (registered, reserved). Structural guards: `compute_threat_pc` runs exactly `1 + n_feasible_proposals` per solve (no quadratic re-score); one feasibility check per iteration (linear in the budget — the `compute_threat_pc` count is NOT the linearity proxy, being confounded by the cooling feasibility ramp). **HONEST LIMIT (load-bearing):** `positioning_gap` scores the REACHABLE improvement, so a dose that displaces a defender AWAY from its reachable-improvement zone SHRINKS the recoverable gap — the naive "worse position → larger gap" is empirically FALSE (the dosed position carries its own shifted reachable set) AND the gap is orthogonal to concurrent shape-badness (corr(threat_actual, gap) = −0.20), so the dose instrument is RETIRED (spec §8 amendment, owner-ratified 2026-09-22). Instrument validity = optimizer-STABILITY (seed/iteration-invariant optimum; requires the spike-fixed `init_sigma_m=2.0` — the retired 5.0 left the optimum seed-noisy, per-frame gap std 0.324 vs 0.000) + discrimination; the commit-2 ship gate is PREDICTIVE — a higher gap at t predicts more conceded threat over t+Δ (meaningful precisely because the gap is orthogonal to concurrent threat). **Status: NOT construct-validated** — the glossaried column ships ONLY if the owner-run commit-2 battery (`docs/research/tf56_positioning/`, `scripts/build_tf56_positioning_validity.py`) returns GO (predictive-positive-and-significant ∧ discriminating ∧ optimizer-stable/non-degenerate); a NEGATIVE battery DEMOTES it in the same release (out of `__all__`/glossary, code retained private — the territorial_defense / TF-60-arms precedent). Per-defender attribution/ranking DEFERRED (a future ADR-009 gated on a crossed defender+team ICC over a multi-club transfer corpus). Additive — no VAEP/tracking retrain, no re-materialize. Decision: ADR-104.

- **Team coordination — coordination dynamics (`coordination/`):** TF-58 (ADR-111). **Tracking-only, not action-coupled** (a `compute_*`, never an `add_*`; the aggregator count is untouched; no `*_xfns`). `build_coordination_signals(frames, *, windows, actions=None, ...)` prepares filtered, resampled, oriented team and player signals ONCE; seven family computes read them (`compute_relative_phase`, `compute_cross_correlation`, `compute_vector_coding`, `compute_spectral`, `compute_coherence`, `compute_cluster_phase`, `compute_relative_stretch`), and `compute_team_coordination` orchestrates them into `CoordinationResult` (seven tables registered in `metric_contracts`, ADR-098) + one conserved `CoordinationReport`. Levels: team–team, cross-variable (defending ↔ attacking, possession windows only), intra-team, dyads (period windows by default) and whole-team cluster; windows from `period_windows` (+ sliding) or possession spells (`possession_windows_from_actions` / `_from_frames`). **Why each method (the question it answers):** relative phase (Hilbert on the centred, reflect-padded segment; Lamb & Stöckl) — are the two rhythms in phase or anti-phase (Bourbousson 2010 histogram, Folgado 2014 % near-in-phase); lagged cross-correlation (±15 s, Fisher-z pooled over segment slices; a positive lag means A leads) — who leads whom; vector coding (Moura 2016 Table 1) — which team drives each joint step; spectral median frequency (Moura 2013) — the tempo of a team signal and of possession exchanges; Welch coherence (spectra pooled BEFORE forming the coherence, the segment count K reported because coherence is biased upward at small K, Carter 1987) — frequency-resolved coupling; cluster phase + SampEn / Cross-SampEn + Pearson (Richardson 2012; Duarte 2013) — whole-team synchrony, each player's lag behind the team and the regularity of both; the relative stretch index (Bourbousson 2010) — which team is more stretched and how often the lead flips (its sign-switch times are the H7 input). **Every statistic carries a seeded surrogate null** (spec 7.9: time-shift draws by default, K = 199, keyed so results are order-independent; IAAFT opt-in): coordination statistics are inflated by autocorrelation and short samples, so the percentile / excess against the surrogate mean is what separates coupling from chance.
  **Signal preparation.** A zero-phase Butterworth at the native rate (the Winter dual-pass cutoff correction, so the filter is also the anti-aliasing filter), then ONE linear interpolation of each filtered run at the period-grid times it covers (spec 7.4 step 4). **TF-58 F7:** the first build resampled twice (run-local grid, then the period grid with NaN outside it), so float rounding (`288.9 - 282.0 = 6.899999999999977`) left 1-2 NaN samples at run edges, and `_phasors_over_runs` then dropped the WHOLE run's phase — 80% of SkillCorner player runs (and 13% / 6% on IDSSE / GradientSports) had silently lost their phase. The fix is one float-tolerant edge rule, `tracking.preprocess._butterworth.grid_span` + `GRID_TOLERANCE` (1e-9 samples), shared by `resample_uniform`, `resample_frames` and the coordination period grid. Detection-aware SkillCorner uses observed samples only (the `detected_mask` primitive, ADR-109); gaps up to `max_detection_gap_s` are bridged, longer ones split a run. Phases are computed once per continuous segment and windows only reduce them (D15). **`include_goalkeeper` is per method** (`team_signals` / `dyad` / `cluster`, defaults outfield / outfield / with keeper — Moura, Folgado, Duarte): the team signals put the keeper into every collective variable when set (spec 7.5), dyads add the keeper pairs, and the cluster roster takes the keeper by default. The first build validated all three keys but read only `cluster`; honouring the other two left the default tables byte-identical (3 reference matches).
  **Orientation (C24).** Direction comes only from the `GoalMap` (ADR-055/051), never from team identity. The scale-free outputs are reflection-invariant anyway; positional signals are still expressed in the reference team's attacking direction (attacking team on possession windows, team A otherwise) so the vector-coding mean coupling angle has one meaning. It is applied algebraically per window from team A's goal-relative frame (a 180° point reflection), which keeps phases-once-per-segment compatible with per-window orientation; pinned by a physical mirror test and an id-relabel test.
  **Stoppages (D20).** Resolved once per call in precedence order and recorded per row as `coord_stoppage_source`: `ball_state` (providers in the fail-closed `dead_ball_observed` taxonomy) → `events` (from the action before each set-piece restart to the restart, and from a goal to the next action) → `unavailable` (no split, Moura 2016's behaviour, and every row says so). Only intervals longer than `max_stoppage_s` split, and one source (`_period_stoppages`) splits both every player's run (before the filter: the rows inside are dropped before the run split, spec 7.4 step 2) and the team segments; the first build split only the team segments, so player phases (cluster, dyads) and the player filter ran through long stoppages (fixed 2026-10-03). A split reading only `ball_state` would silently do nothing on 909 of the ~980 corpus matches: the SkillCorner builder marks every frame alive (no reliable dead-ball signal in its feed).
  **Divergences from the primary sources (spec 7.8.8)** — each for a stated reason:

  | Paper | Printed / implied | TF-58 | Why |
  |---|---|---|---|
  | Moura 2016 Eq. 2 | arctan \|Δθ₂/Δθ₁\| | `atan2(Δθ₂, Δθ₁)` | the printed form cannot reach Table 1's bins |
  | Moura 2013 | FFT, mean removal unstated | mean removed, DC excluded | otherwise the median collapses to ~0 |
  | Bourbousson 2010 | linear mean / SD of wrapped angles | circular statistics | bias near ±180° |
  | Duarte 2013 | raw positions | the common zero-phase filtered positions | one preprocessing definition; noise-induced phase slips |
  | Duarte 2013 | substitute spliced onto the replaced player | per-player segments | no artificial discontinuity |
  | Moura 2016 | cross-correlation over whole halves incl. stoppages | segments split at stoppages, Fisher-z pooled | the paper's own named limitation |
  | Moura 2013/2016 | 30 Hz video, 7.5 Hz sampling, 0.4 Hz cutoff | 10 Hz analysis; cutoff by residual analysis per provider | the paper's procedure applied to our providers |

  **Slices (D15, spec 7.4 step 2).** Every observed statistic and every surrogate null reads window ∩ A-segment ∩ B-segment slices (`_both_runs`, an intersection sweep), so nothing spans an on-pitch-count change -- except a substitution handover: a count excursion that returns to its prior count within `max_stoppage_s` does not split (`_absorb_handovers`; owner ruling 2026-10-03, measured: GradientSports handovers return within 22.5 s, the next change lasts 42.5 s); the possession spectrum is sliced the same way (spec 7.8.4). A time-shift null shifts only the B segments holding a row its statistic reads (plan Task 17's contributing segments, `_segments_holding`); one of those too short to shift (`< 2 tau + 1`) makes the null `segment_too_short`, while a segment that merely overlaps the window takes no part (cluster keeps R1's "any run touching the window"). A cluster window needs `MIN_CLUSTER_SAMPLES = 2` usable samples (one sample makes rho_group identically 1 for data and null alike). `possession_windows_from_actions` skips a (game, period) the frames do not cover and names it in a `CoordinationCoverageWarning`; that category is otherwise spec 7.13's one call-level trigger (the dropped share of windows), raised by each public compute and once by the orchestrator, attributed to the caller. Seed keys use the canonical game id.
  **Drivers (spec 8.3).** Every corpus pass first runs the ADR-069 Layer-2 pre-flight for a raw-artifact corpus (`visibility_preflight`: one detection-aware match per provider must carry `visibility`, before any compute; a bounded probe of at most `attempts` loads per provider, so it is ADR-052 Rule C's one TF-58 `_UNSHARDED_LOOP_EXEMPT` entry). D1 / D2 / D3 / the numerics gate run per worker over disjoint `--match-ids-json` slices; every corpus-wide step combines all workers' shares (`_coordination_corpus.combine_workers`) and refuses anything less than `--corpus-json`. Artifacts land in each driver's `--out` (the M-5 handoff: D2/D3 compute with `derivation.json` via `params_from_artifacts`, digests in every token), never the package; commit 2 copies them in.
  **Numerics and cost (ADR-111 Performance).** The surrogate nulls use the spec 7.9 algebraic identities: relative phase's R is one circular cross-correlation per B segment, used only where a FIXED size rule says it is cheaper than the direct null (`RP_IDENTITY_CROSSOVER = 17/4`); cross-correlation is a circular FFT cross-correlation + an exact edge correction + prefix sums. The cluster / team-sync arithmetic is explicit real arithmetic in a fixed order, so numba == numpy bit for bit (D4). `SILLY_KICKS_COORDINATION_REFERENCE_NUMERICS=1` scores through the as-built numerics (the direct nulls + `_cluster_reference`) — the tests' parity oracle and the reference leg of the owner's corpus no-flip gate `scripts/validate_coordination_numerics.py` (no token flip, no percentile crossing 0.025/0.05/0.5/0.95/0.975). Measured per match with numba: SkillCorner ~18 s, IDSSE ~114 s, GradientSports ~131 s (the k = 0 floor is ~14 / 32 / 35 s); the binding bound is the corpus (D3 pass ~27 min on 16 workers). A scipy trap on the way: 1.18's batched FFT is not per-row identical to the 1-D transform, so the direct cross-correlation / coherence nulls stay on per-row 1-D scipy calls. **Status:** commit 1 ships the interim Tier-B parameters (`_provider_params_generated.BASE_SOURCE = "interim"`); the D1 derivation, D2 calibration and D3 validation run on the DGX, and commit 2 regenerates the parameters and records the results. No inferential claim before the D3 replication. Decision: ADR-111.
