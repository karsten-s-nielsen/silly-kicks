# Tracking feature families & frame contracts

> On-demand class-2 context (ADR-102-style store). The current terse RULES live in `AGENTS.md`; this file holds the WHY / history / measurement. See the spec `docs/superpowers/specs/2026-09-24-agents-md-restructure-design.md`.

- **Tracking** (`tracking/`): Per-frame namespace parallel to `spadl/`. 19-column long-form schema (`TRACKING_FRAMES_COLUMNS`); native Sportec + Gradient Sports adapters; native SkillCorner + Metrica bronze->frame builders (ADR-034); kloppy gateway. The linkage primitive (`link_actions_to_frames` + `slice_around_event`) joins SPADL actions to frames -- pointer-DataFrame return plus a `LinkReport` audit (ADR-004). Tracking-aware features compose into VAEP via `compute_features(*, frames=None)` and the `_frame_aware` xfn marker (ADR-005); every family has an `atomic.tracking.features` mirror.
  - **`time_seconds` is period-relative** (it resets each period -- NOT an absolute match clock). ADR-017 enforces it with a per-period `min_link_rate`/`on_low_coverage` guard plus `LinkReport.per_period_link_rate`, and public `validate_time_base`/`TimeBaseDiagnosis` as the pre-link guard for time-filtering consumers (the linker cannot see pre-filtered-out actions).
  - **GK identity:** `is_goalkeeper_source` is `native` or `derived`; `_gk_identification.derive_goalkeepers` is the B+ filtered algorithm with agreement-based source resolution. SkillCorner **trusts its authoritative roster** (`native`, derivation skipped; derive only for a `(game, team)` with no native GK) -- positional derivation is unstable over the short windows a batched builder sees. Metrica has no roster and stays Tier-2 (ADR-007); it seeds NONE, because `gk_jersey_numbers` is a flat team-agnostic list and `derive_goalkeepers` ORs-never-clears.
  - **Metrica input CONTRACT:** bronze `y` must be SPADL bottom-to-top. Kloppy's metrica NATIVE coordinate system is top-to-bottom, so a `TrackingDataset` consumer MUST flip `1-y`.
  - `tracking.preprocess` ships Savitzky-Golay / EMA `smooth_frames`, linear `interpolate_frames`, SG-derivative `derive_velocities`, and the shared `PreprocessConfig` (flag-based `is_default()`, per-provider defaults auto-promoted via `for_provider`).

- **Linkage-provenance columns are idempotent.** All tracking `add_*` aggregators that merge provenance columns (`frame_id`, `time_offset_seconds`, `link_quality_score`, `n_candidate_frames`) must skip the merge when those columns already exist on the input DataFrame. This allows callers to chain multiple `add_*` calls without producing `_x`/`_y` suffixed duplicates. Pattern: `if not any(c in out.columns for c in provenance_cols):`. CI gate: `tests/tracking/test_provenance_skip_guard.py`.

- **Pre-linking optimization via `links` kwarg.** All tracking `add_*` aggregators accept an optional `links: pd.DataFrame | None = None` kwarg. When provided, the function skips its internal `link_actions_to_frames` call and uses the caller-supplied pointers. Pipeline callers (e.g. lakehouse) pre-link once and pass `links` to all enrichment steps, reducing N × 2-5s to 1 × 2-5s per match. The `links` DataFrame must be the pointers output of `link_actions_to_frames` (columns: `action_id`, `frame_id`, `time_offset_seconds`, `n_candidate_frames`, `link_quality_score`). Internal helpers (`_resolve_action_frame_context`, kernel functions) also accept `links` for full thread-through. `infer_ball_carrier` additionally accepts `pre` (a precomputed `_pre_index_frames(frames)`) and `ball_carrier_at_action` accepts both `pre` and `links`; the pre-index dominates carrier cost (~99%) yet is param-invariant, so the TF-24 Stage-1 calibration objective caches `pre`+`links` per match (invariant-prepare) and re-runs only the carrier kernel per Optuna trial (~100× faster sweep; bit-identical).

- **Shared pitch-control surface via `pitch_control_cache` kwarg.** All pitch-control-consuming aggregators (`add_obso`, `add_cover_shadows`, `add_gk_influence`, `add_player_influence`, `add_space_creation`, `add_pitch_control`) accept an optional `pitch_control_cache: PitchControlCache | None = None` kwarg (mirrors `links`). `PitchControlCache` (in `tracking/pitch_control/`) memoizes **canonical** per-frame surfaces keyed on `(game_id, period_id, frame_id, team, method, params, ball_position, decompose)`, so families that need pitch control on overlapping frames compute each surface once instead of once per family. Each aggregator uses a fresh local cache by default (within-pass reuse); pipeline callers pre-build one cache and pass it to all steps for cross-family reuse (like `links`). Only canonical-frame surfaces are cached — **counterfactual** (player-removed) surfaces in `cover_shadows`/`space_creation` are never routed through the cache. Zero global state. Decision: ADR-008 (TF-7).

- **Frame memory: `category` is for STATIC low-card columns ONLY; the cache is bounded; the batched pitch-control API is a future-kernel seam (ADR-103, 4.125.0).** `TRACKING_FRAMES_COLUMNS` sets the SET-ONCE low-cardinality columns `ball_state`/`source_provider`/`is_goalkeeper_source` (+ preprocess's `_preprocessed_with`) to `"category"` and DROPS the all-null `confidence` (20→19 cols); the three MUTATED-post-build columns `team_attacking_direction` (orientation flips it), `speed_source` (velocity derivation sets it) and `visibility` (`_truthy_bool` `fillna("")`) STAY `"object"` — **`category` is not transparent to setitem or `.fillna(new_value)` (raises `TypeError: Cannot setitem on a Categorical with a new category`), so category on a dynamic column is a live crash, not a size win.** Value-neutral (~2× frame memory; per-column ≥5×, not per-frame ≥6× — ids + float coords + the 3 object cols dominate): every `value_counts`/category-keyed `groupby` on a category column casts `.astype("object")` first (else zero-count categories leak into the dict — `LinkReport.per_provider_link_rate` etc.). `PitchControlCache(maxsize=N)` is now a bounded LRU (default `None` = unbounded, byte-identical to before). `compute_pitch_control_batch(frames, requests, *, method, params)` + `PitchControlCache.warm(...)` group-once/dedup and are parity-gated **byte-identical** to the per-frame loop (the seam a future vectorized-spearman kernel plugs into). No VAEP/tracking retrain, no re-materialize, C4-free. Decision: ADR-103.

- **The vectorized spearman kernel + scorer batching are the no-retrain CPU/memory work ADR-103's seam was built for (ADR-105, 4.127.0).** ADR-103 shipped `compute_pitch_control_batch`/`PitchControlCache.warm` as a group-once/dedup seam and named "a future vectorized-spearman kernel" as what plugs in; ADR-105 IS that kernel, plus the scorer-side batching that makes it pay off. **The kernel is CONCAT-AND-SLICE, not pad/mask (the spec's pad/mask was superseded during implementation — the ADR records the ACTUAL mechanism).** TTI is a per-`(player, target)` element-wise quantity, so `compute_spearman_batch(frame_slices, teams, decomposes, ball_positions, *, params)` `np.concatenate`s every frame's REAL players into ONE `compute_tti` call and slices the result back by `bounds = np.cumsum([0, *lengths])`. Byte-identity holds for two reasons: (1) concat carries only real players — there are NO fabricated padding rows to mask, so nothing can perturb a sum; (2) the per-request influence `.sum(axis=0)` is order-dependent, and per-frame row order is preserved by construction (the slice is contiguous), so each frame's sequential sum is identical to the per-frame path (real player counts sit below numpy's 128-element pairwise-summation threshold, so the sum is plainly sequential). The combine is **single-sourced** (the ADR-102 idiom): `compute_spearman` and `compute_spearman_batch` BOTH call the extracted `_spearman_combine` (Stages 1.5–3 + decompose), so the batch is byte-identical to per-frame by construction, not by a parity coincidence — the SK-xT-1-style parity gate + a non-vacuity `test_row_order_alignment_is_load_bearing` (shuffling the alignment must break it) + `test_batch_calls_compute_tti_once_for_n_frames` guard it. `compute_pitch_control_batch` routes spearman through `_batch_from_groups(groups, requests, method, params)` (renamed private — a public `batch_from_groups` tripped the Examples gate), keeps the dedup + the spearman `vx`/`vy`-required raise, and leaves non-spearman methods on the per-frame loop; `PitchControlCache.warm` now groups ONCE via `group_rows` then calls `_batch_from_groups` (fixing the ADR-103 double-`group_rows`). **`compute_threat_pc_batch(items, *, xt, method="spearman", params=None)`** (in `tracking/_cover_shadows.py`, exported from `tracking`) scores the keeper-removed COUNTERFACTUAL legs over EXPLICIT frame slices — each item is `(frame, attacking_team_id, goal_map, field_weight)`, `zero_velocity_if_unavailable` applied per item, then `compute_spearman_batch` + per-item `_voronoi_threat` — and MUST NEVER route through the frame-keyed `PitchControlCache` (the ADR-043 landmine: the cache key excludes player positions, so a keeper-removed frame carrying its twin's identity would be served the factual surface and every delta would collapse to exactly 0 with no warning). **Scorer batching:** `restdefense._compute._score_samples(..., batch_size=64)` chunks scored samples; `_score_chunk` WARMS canonical surfaces on `zero_velocity_if_unavailable(frames, method="spearman")` — warming on the RAW velocity-less SB360 frames raised the spearman `vx`/`vy`-required guard (the 5 SB360-audit `rd_num_superiority` full-suite-only failures), so the zero-velocity copy is load-bearing — then `batch_threat_values(prepared, *, xt, goal_map, params)` scores the two `compute_threat_pc` legs across the chunk via ONE `compute_threat_pc_batch` (byte-identical; a chunk whose batch raises `GoalEndUnresolvedError` falls back to the direct per-sample path). `tracking._run_values.value_off_ball_runs(..., batch_size=64)` chunks the off-ball loop with a per-chunk `cache.warm` pass. **F4 = INTERNAL auto-batching** (`batch_size`, default 64, invariance-gated over `{None, 1, 7, len}`) — deliberately NOT a consumer-driven primitive, because the global action→frame link forecloses sub-unit scoring; `batch_size=64` is documented-tunable with no measured optimum. `defensive_credit`/`gk_decision` are pitch-control-FREE and NOT routed (audited by `test_pc_free_scorers_audit`). `_frame_index.group_rows` gains a defensive `observed=True` (pandas-2's categorical-key default injects phantom empty groups; ADR-057). DAS gains a cost guardrail: `estimate_das_cost(frames)` + `get_das(..., warn_cost=True)` fires `DasCostWarning` past `_DAS_COST_WARN_FRAMES` (5000) at `_DAS_SECONDS_PER_FRAME` (0.02). Value-neutral end-to-end — no VAEP/tracking retrain, no re-materialize, C4-free (aggregator count stays 33). **Deferred to the retrain cycle:** F1b float32 coordinates + id→`category` + off-frame provenance. Decision: ADR-105.

- **Tracking-frame identifier dtypes are NULLABLE, and a constant every variant overrides is a DEFAULT masquerading as a CONTRACT (ADR-058).** `TRACKING_FRAMES_COLUMNS` declares `Int64` for `player_id`/`team_id`, not `int64`. Every frame set carries a ball row, which belongs to no team and holds no player, so both are NA on it **by construction**; numpy `int64` cannot represent NA, so the cast raised `IntCastingNaNError` on every producer and the base was satisfied by **nothing** — all five provider variants overrode it, and the Gradient Sports one had already worked out the right answer locally (its docstring says *"allows NaN on ball rows"*). Not `object` for the base: `id_compat`'s both-object path is CONTENT-probed (~15%/side), so defaulting every producer onto it taxes the seam ADR-019 makes mandatory. The four `object` variants are KEPT (kloppy domain types and SkillCorner's stringified ids are genuinely strings); `GRADIENTSPORTS_TRACKING_FRAMES_COLUMNS` becomes an **alias** rather than a deletion — it is in `tracking.__all__`, and aliasing is already the file's idiom (`SPORTEC`/`SKILLCORNER`/`METRICA` alias `KLOPPY`). Gated red-first in `tests/test_tracking_schema.py` by a base pin (which also asserts the cast preserves NA rather than producing an ADR-027 sentinel) plus one **complete by ENUMERATION** over every `*_TRACKING_FRAMES_COLUMNS` in the module, so a new provider with a non-nullable id dtype fails CI. **The durable lesson: when a cast to a schema constant fails, the constant is a suspect** — 4.77.0 read the same `IntCastingNaNError` as its dtype PIN being unimplementable and dropped it, twice bouncing off the wrong constant. When a schema grows a per-provider variant, ask whether it expresses a genuine provider difference or repairs the base; the second kind belongs at the base the day it is written. **`snapshot_to_tracking_frames` CASTS to this schema, per column** (`_cast_to_declared_schema`): identifier columns follow the CALLER's domain — genuinely-string ids keep `object` (the kloppy family), numeric ids take the base — decided per COLUMN, not per frame, because a caller can legitimately pair a numeric `game_id` with string `team_id`s. Before the cast the ball row's NA upcast integer ids to `float64`, i.e. ids were FLOATS (the `"366.0"` vs `"366"` shape), and the result was resolver-dependent: an `Int64` source stayed `Int64` on pandas 2.3.3 and became `Float64` on 3.0.5. **That cast is what exposed `add_elastic_sync` scoring every action against an empty distance lookup** — see ADR-019 and the CHANGELOG.

- **`DasUnscoreableError` is the ONLY degradable DAS exception (ADR-043).** Everything else PROPAGATES. The former broad `except (ValueError, RuntimeError, ImportError, IndexError, TypeError)` swallowed silly-kicks' own bugs, and an all-NaN column is indistinguishable downstream from legitimately-absent DAS. `add_das` emits a `das_source` column over the closed `DAS_SOURCE_VALUES` vocabulary (each token also exported as a `DAS_SOURCE_*` constant so consumer enums pin to the library's set); `das_at_action` returns a bare Series and carries no provenance; `das_xfns` deliberately does not emit the string column, because VAEP matrices stay numeric.

- **The frame-consuming `add_*` family has ONE canonical call shape, and ONE provider-agnostic producer (ADR-078).** Convention (pinned by `tests/tracking/test_call_convention_registry.py`, derived from `tracking.__all__`): `frames` is NEVER keyword-only (positional-or-keyword, next to `actions`); every OPTIONAL parameter is keyword-only; a single REQUIRED fitted model (`xt: ExpectedThreat`) MAY be the 3rd positional (a wrong 3rd-positional fails immediately on `xt.rate`, so it is not a silent bug class — and forcing keyword-only would churn the 5 positional-`xt` aggregators' **108 call sites** for no correctness payoff, YAGNI). The ONLY signature change was `add_pre_shot_gk_angle` (keyword-only `frames` → positional; main + atomic mirror). `tracking.run_tracking_features(...)` is a provider-agnostic PRODUCER — an ORCHESTRATOR, not a new action-coupled aggregator (C4 count stays 33) — that resolves keeper identity once, bridges both grains (frame bridge on the roster path only), pre-links + shares one `PitchControlCache`, injects `xt`/`xg_column` per family via `FAMILY_MODEL_REQUIREMENTS` (the model-injection routing, SINGLE-SOURCED: `scripts/_sb_battery.py` builds its `ADAPTER_MAP` from it, so the SB360 audit `_entries/*` stay byte-identical), runs each family under a per-family guard (a refusal is RECORDED, never crashed), and returns the enriched actions + a conserving `TrackingFeaturesReport`. A family whose injected model is absent is SKIPPED (honest absence); a velocity-constitutive metric stays NaN whether it self-degrades (`add_das` → `das_source="unscoreable_frame"`, column `das_diff`) or is skipped (ADR-063). `run_tracking_features` + `resolve_keeper_identities` are glossary/SB360-audit-EXEMPT (`run_*`/`resolve_*`, not `add_*`; documented at `tests/sb360/_registry.py::audited_surface`); `run_tracking_features` is `NOT_EXERCISABLE` in the id-scalar registry (a forwarder that never compares `home_team_id`). Component 2 (deterministic snapshot id dtypes) was already ADR-057/058 (4.79.0). Decision: ADR-078.

- **The expected-receiver model uses PRE-PASS state ONLY, and the σ/λ re-tune is per-provider + honest-null (ADR-066).** `ReceiverModel` (`tracking/_receiver.py`, ADR-011 bundle) infers a pass's intended receiver from pre-pass positions (public feature set) + the ball's release-VELOCITY direction + candidate closing speed (owner/GS variant) — NEVER the pass end/loss location (the pass-event angle is origin→end, banned; the only leakage-free release direction is the ball's velocity, absent on velocity-less SB360 freeze frames, so the public model is positions-only). The leakage ban is pinned by an **output-invariance** guard (perturb `end_x`/`end_y` → features byte-identical), NOT a disjunctive "raises or ignores". It DE-LEAKS the RQ failed-pass target as an **opt-in** (`build_rq_pass_scores --receiver-model`; `model=None` is 4.87.0-byte-identical); the failed-pass validity is a trajectory-weak-labelled **UPPER BOUND on the easy tail** (clear-trajectory interceptions, where the proxy is near-ceiling), so a non-decisive gate reads "unvalidatable where the model would matter", not "no value". The σ/λ re-tune is **DISCRIMINATION** (margin-AUC), NOT magnitude "recalibration" (unmeasurable without counterfactual block ground truth), applied **PER-PROVIDER** via `CoverShadowParams.for_provider` (a σ/λ fit on one provider's velocity profile is a global default for NONE — H3), only if a three-conjunct gate clears (receiver-validity + a lane-pressure bias ablation + ADR-060 noise, pre-registered `_cover_shadow_thresholds` referenced not inlined); the honest-null (keep incumbent σ/λ, serve the public receiver) is the likely landing. Reported-not-gated; **amends ADR-009** (gated in-cycle apply). **Training is PER-PROVIDER-LABELED (real-data amendment):** SB360 freeze frames carry NO player identity (ADR-062, rows numbered), so id-based receiver labeling yields **0 positives** — SB360 trains via **TRAJECTORY** labels (the teammate nearest the release→next-touch-START ray within a tight `_LABEL_LANE_WIDTH_M`; ambiguous → **DROP**, never all-zero, never nearest-guess). Identity providers (GS) use clean **id**-labels and a no-id-match pass is **DROPPED**, never per-pass trajectory-guessed — the strategy is decided at FRAME-SET granularity (`labeling_strategy_for_provider`), never per pass. The public model is **SB360-primary**; a `--pool-provider` (GS) earns inclusion ONLY via a held-out gate (`pooling_gate`: GroupKFold on primary games, pool→TRAIN-only, kept iff no primary-top-1 regression) — never naively pooled. A per-frame ball gap raises `NoReleaseDirectionError` (skip/NaN train+serve, counted); a MISSING `vx`/`vy` COLUMN stays a **LOUD `KeyError`** (owner misrouted to a velocity-less provider — the fail-loud discipline ADR-051/ADR-010, NOT ADR-043). The outcome-reading label lives in the DRIVER (`extract_candidate_rows`), pinned by a **driver-layer** leakage guard (perturb the reception anchor → label moves, features byte-identical). Decision: ADR-066.

- **Frame-aware `*_xfns` must resolve frames POSITIONALLY, never by `action_id` lookup (ADR-020).** VAEP shifted gamestate slots repeat the boundary action, so `action_id` is NOT unique in an xfns matrix: `set_index("action_id").at[aid]` returns a Series and raises, and provenance merges fan out. `_kernels.resolve_frame_ids_by_position` is the single seam, byte-equivalent to the old `.at` on unique ids. The production `add_*` aggregator path has unique ids and is unaffected, which is precisely why this survived so long -- so the gate is behavioral and auto-enumerates every `*_xfns` (`tests/tracking/test_frame_aware_xfns_dup_action_id.py`). A `.at` grep missed two of the eight defective families; the behavioral gate found all eight.
